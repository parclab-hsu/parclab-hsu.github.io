## 0. 한눈에 — 언어 철학

| 항목 | C | Python |
|------|---|--------|
| 실행 방식 | **컴파일**(기계어로 번역 후 실행) | **인터프리터**(한 줄씩 해석) |
| 타입 | **정적**(선언 시 자료형 고정) | **동적**(실행 중 결정) |
| 메모리 | **수동**(`malloc`/`free`) | **자동**(가비지 컬렉터) |
| 속도 | 매우 빠름(하드웨어 근접) | 느림(편의성 우선) |
| 주 용도 | 임베디드·OS·펌웨어·실시간 | 데이터·AI·스크립트·웹 |
| 문법 | 중괄호 `{}` · 세미콜론 `;` | **들여쓰기**로 블록 구분 |

> 💡 자율주행 스택에서 **상위 AI/플래너는 Python**, **하위 실시간 제어·펌웨어는 C**로 나뉘는 이유가 이 표에 있다.

## 1. 변수·자료형

```c
// C — 자료형을 반드시 선언, 크기 고정
int   rpm = 2500;      // 4바이트 정수
double speed = 42.5;   // 8바이트 실수
char  gear = 'D';      // 1바이트 문자
```
```python
# Python — 선언 없이 대입, 타입은 자동
rpm = 2500        # int (크기 무제한)
speed = 42.5      # float
gear = 'D'        # str (문자도 문자열)
```
- C의 `int`는 **범위가 정해져** 넘치면 순환한다: `INT_MAX + 1` → `-2147483648`.
- Python의 `int`는 **무제한**: `2**63 + 1` → `9223372036854775809` (넘침 없음).
- C는 **정수 ÷ 정수 = 정수**(`7/2`→3), Python은 `/`가 항상 실수(`7/2`→3.5), 몫은 `//`(`7//2`→3).

> ⚠ Python만 하다 C로 오면 **정수 나눗셈**과 **오버플로**에서 가장 많이 실수한다.

## 2. 출력·입력

```c
// C
printf("속도: %.1f km/h\n", speed);   // 형식 지정자 %.1f 필요
int n; scanf("%d", &n);                // 주소(&) 필요
```
```python
# Python
print(f"속도: {speed:.1f} km/h")       # f-string
n = int(input())                        # 항상 문자열 → int 변환
```
- C는 값의 자료형에 맞는 **형식 지정자**(`%d %f %c %s`)를 직접 골라야 한다.
- `scanf`는 **주소(`&n`)** 를 넘긴다(값을 채워 넣어야 하므로) — C 포인터의 첫 등장.

---

## 3. 조건·반복 — 블록을 나누는 법

```c
// C — 중괄호 + 세미콜론
for (int i = 0; i < 5; i++) {
    if (i % 2 == 0) {
        printf("%d ", i);
    }
}
```
```python
# Python — 들여쓰기(콜론)
for i in range(5):
    if i % 2 == 0:
        print(i, end=" ")
```
- C: `for (초기화; 조건; 증감)`, 블록은 `{}`, 문장 끝 `;`.
- Python: `for x in range()`, 블록은 **들여쓰기**, `;` 없음.
- C의 `switch`(fall-through 주의)는 Python엔 없다(대신 `if/elif` 또는 `match`).

---

## 4. 함수 — 타입과 전달 방식

```c
// C — 반환형·매개변수 타입 명시
int max2(int a, int b) {
    return (a > b) ? a : b;
}
void inc(int *p) { (*p)++; }   // 주소 전달로 원본 수정
```
```python
# Python — 타입 없음(힌트는 선택)
def max2(a, b):
    return a if a > b else b
def inc(lst):        # 리스트(가변)는 원본이 바뀜
    lst[0] += 1
```
- C는 **값 전달**이 기본 → 원본을 바꾸려면 **주소(포인터)**. Python은 **객체 참조**를 넘기되, 불변(int·str)은 안 바뀌고 가변(list·dict)은 바뀐다.
- C 함수는 `return` 값 **하나** → 여러 결과는 포인터 매개변수. Python은 **튜플로 여러 개** 반환(`return a, b`).

---

## 5. 배열(C) vs 리스트(Python)

```c
// C — 크기 고정, 같은 자료형만
int a[3] = {1, 2, 3};
// a[3] = 4;  // ❌ 범위 초과(검사 안 함, 위험)
```
```python
# Python — 동적 크기, 타입 혼합 OK
lst = [1, "two", 3.0]
lst.append(4)   # 자유롭게 확장
```
- C 배열: **컴파일 때 크기 고정**, **같은 자료형**, 범위 초과를 **검사하지 않는다**(버그·보안 취약점의 근원).
- Python 리스트: 크기 자유, 타입 혼합, 범위 벗어나면 **예외**로 알려줌.
- C에서 크기를 실행 중 정하려면 **동적 메모리**(`malloc`) 필요 → `ex16_dynamic.c`.

---

## 6. 문자열 — 가변 배열 vs 불변 객체

```c
// C — '\0'로 끝나는 char 배열 (수정 가능)
char s[] = "RUN";
s[0] = 'r';           // 가능 → "rUN"
strlen(s);            // 3
```
```python
# Python — str 객체 (불변)
s = "RUN"
# s[0] = 'r'          # ❌ TypeError: 불변
s = "r" + s[1:]       # 새 문자열을 만들어야 함
len(s)                # 3
```
- C 문자열은 **문자 배열**이라 각 칸을 바꿀 수 있지만, 끝에 **`'\0'`** 가 없으면 어디서 멈출지 모른다.
- Python `str`은 **불변** → 바꾸면 새 객체 생성. C엔 이런 안전장치가 없어 **버퍼 오버런**에 주의.

## 7. 포인터 — C에만 있는 것

```c
// C — 주소를 직접 다룬다
int a = 10;
int *p = &a;     // p는 a의 주소
*p = 20;         // p를 통해 a를 수정 → a == 20
```
```python
# Python — 포인터 개념이 없음(모든 것이 객체 참조)
a = 10
b = a            # 값 자체가 아니라 객체를 가리킴
# 정수는 불변이라 b를 바꿔도 a는 그대로
```
- C는 **주소를 값처럼** 다뤄 메모리를 직접 제어한다(임베디드·성능의 핵심).
- Python은 포인터를 숨긴다(모두 객체 참조). 그래서 **편하지만 저수준 제어는 불가**.

---

## 8. 구조체(C) vs 클래스/데이터클래스(Python)

```c
// C — struct: 데이터 묶음
typedef struct { double x, y; } Pose;
Pose car = {1.5, -0.8};
printf("%.1f", car.x);
```
```python
# Python — class 또는 dataclass
from dataclasses import dataclass
@dataclass
class Pose:
    x: float
    y: float
car = Pose(1.5, -0.8)
print(car.x)
```
- C `struct`는 **데이터만** 묶는다(메서드 없음). Python `class`는 데이터 + **메서드(동작)** 를 함께.
- C에서 "동작"은 구조체를 받는 **함수**로 분리한다(`move(Pose *p, ...)`).

---

## 9. 메모리 관리 — 수동 vs 자동

```c
// C — 직접 할당하고 직접 해제
int *buf = malloc(n * sizeof(int));
if (!buf) { /* 실패 처리 */ }
// ... 사용 ...
free(buf);            // 안 하면 메모리 누수!
```
```python
# Python — 그냥 쓰면 됨(가비지 컬렉터가 정리)
buf = [0] * n         # 할당
# ... 사용 ...
# 해제 불필요 (참조 없어지면 자동 회수)
```
- C는 **자유롭지만 책임**이 따른다: 누수·이중 해제·댕글링 포인터.
- Python은 편하지만 **언제 회수되는지 통제 불가** → 실시간 제어엔 부적합.

## 10. 언제 무엇을 쓰나 (모빌리티 관점)

| 상황 | 적합한 언어 | 이유 |
|------|-------------|------|
| MCU 펌웨어(Arduino)·ECU | **C** | 메모리·타이밍 직접 제어, 작은 용량 |
| 실시간 제어 루프 | **C/C++** | 예측 가능한 성능, GC 멈춤 없음 |
| ROS2 노드(고수준) | Python 또는 C++ | 빠른 개발 vs 성능 |
| 데이터 분석·AI 학습 | **Python** | 풍부한 라이브러리 |
| LLM 플래너·프로토타입 | **Python** | 생산성 |

> 💡 이 수업의 목표: **C로 하위(펌웨어·통신)** 를 이해하고, 상위 Python/AI와 **어떻게 연결**되는지(C↔ROS2) 체감하는 것.
