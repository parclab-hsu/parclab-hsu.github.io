# 10주차 실습 코칭노트 · ADC·Timer·UART

> 이 문서는 수업 중 학생 활동을 지도하기 위한 코칭 자료다. 교수자는 설명보다 관찰, 질문, 기록을 중심으로 진행한다.

## 오늘의 실습 미션

- 미션 요약: ADC 코드값 계산, PSC/ARR 산정, Teleplot 문자열 출력, 보레이트 확인
- 사용할 자료: `stm32-adc-updated.pdf / stm32-tim.pdf / stm32-serial-communication-updated.pdf`
- 참고 이미지: `figures/attachment-previews/stm32-adc-p01.png`, `figures/adc.svg`
- 제출 형식: 계산표, 회로 캡처, 코드 일부, Teleplot 로그, 사진 중 최소 1개를 포함한다.

## 실습 전 준비

### 전원 확인
전압, 전류제한, 극성, 공통 그라운드를 확인한다. 실패하면 전원을 차단하고 배선을 다시 검토한다.

### 보드 확인
MCU 보드, 드라이버, 센서 커넥터 방향을 확인한다. 애매하면 사진을 기록하고 조교 확인을 받는다.

### 소프트웨어 확인
프로젝트 열기, 빌드, 다운로드, 시리얼 포트를 확인한다. 실패하면 포트와 보레이트부터 다시 확인한다.

### 기록 준비
팀 폴더, 날짜, 버전, 실험 조건을 먼저 작성한다. 결과 없는 실습으로 남지 않게 한다.

## 단계별 코칭 질문

1. 지금 만지는 신호는 전원, 제어, 센서, 통신 중 어디에 속하는가?
2. 이 값을 바꾸면 어떤 물리량이 먼저 변해야 하는가?
3. 측정값이 예상과 다르면 회로, 코드, 장비 설정 중 무엇부터 확인할 것인가?
4. 같은 오류를 다음 팀이 피하려면 어떤 한 줄 메모를 남겨야 하는가?

## 팀 활동 절차

1. 첨부자료 대표 이미지를 열고 오늘 미션 위치를 표시한다.
2. 계산값 또는 설정값을 먼저 예측하고 단위와 기준값을 확인한다.
3. 보드, 회로, 코드 중 하나를 실제로 조작하되 위험한 전원 조건을 피한다.
4. 결과를 캡처하거나 로그로 저장하고 재현 가능한 파일명을 사용한다.
5. 실패 원인을 한 문장으로 기록하고 증상과 원인을 구분한다.

## 평가 루브릭

### A 수준
계산, 측정, 로그가 서로 맞고 최종 ECU 블록과 연결해 설명한다.

### B 수준
실습 결과는 있으나 최악 조건, 오차, 안전 설명이 일부 부족하다.

### C 수준
결과 캡처는 있으나 입력 조건이나 재현 절차가 빠져 있다.

### D 수준
실행 여부만 적고 수치, 그림, 로그 증거가 없다.
