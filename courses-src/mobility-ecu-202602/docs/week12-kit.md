# 12주차 운영 키트 — 인버터 하드웨어 설계

### 교안 정보

| 항목 | 내용 |
|---|---|
| 교과목 | 모빌리티 전자제어유닛 실습 (3학점 · 전공) |
| 대상 | 미래모빌리티학과 3~4학년 |
| 차시 | 12주차 / 15주차 · 180분 |
| 강의실 | Physical AI 실습실 |
| 관련 자료 | 상세 강의자료 12번 · 과제집 19번 · 배포용 워크시트 Y·Z |

### 학습목표

이 시간이 끝났을 때 학생은 다음을 수행할 수 있다.

1. MCU 주변회로, 홀센서, 스로틀, 전류센서, NTC, UART 회로를 HSI와 연결한다.
2. 게이트드라이버와 MOSFET 구동 회로의 기본 요구사항을 이해한다.
3. 회로도 리뷰 체크리스트를 작성한다.

### 핵심 질문

- MCU 핀 하나를 회로와 펌웨어 양쪽에서 어떻게 추적하는가?
- 게이트드라이버는 왜 MCU GPIO로 직접 MOSFET을 구동하는 것보다 안전한가?
- 전류센서와 NTC는 어떤 보호 기능으로 이어지는가?

### 지도 중점

11주차까지가 "소프트웨어로 멈추는 방법"이었다면, 12주차는 **"소프트웨어가 멈춰도 회로가 멈추게 하는 방법"** 이다. 이 주차의 목표는 부품 선정이 아니라 **차단 경로를 하드웨어까지 이중화하는 설계 감각**이다.

> 📌 **11주차에 만든 소프트 차단 경로 위에 하드웨어 층을 쌓는다.** 학생이 11주차 워크시트 X(차단 지연 실측)를 가져오면 소프트 경로의 실제 지연(수백 µs)과 하드웨어 경로(수 µs)를 나란히 비교할 수 있다.

> ⚠️ 이 주차는 **실습보다 리뷰가 중심**이다. 체크리스트가 곧 산출물이며, 12주차 결과가 15주차 fault injection 시험 항목이 된다.

### 1. 180분 진행 대본

#### 블록 1 · 0~50분 — MCU 주변회로와 게이트드라이버

**목표** — "왜 드라이버가 필요한가"를 숫자로 납득시킨다.

1. (5분) **11주차 피드백.** 차단 지연 실측값을 몇 팀 물어본다.

   > 🗣️ "지난주에 소프트웨어로 차단했더니 몇 ms 걸렸습니까? 오늘은 **펌웨어가 죽어도 멈추는 경로**를 만듭니다."

2. (12분) **MCU 주변회로.** 전원, 리셋/부트, 크리스탈, SWD/JTAG, LED, UART.

   레퍼런스 보드 시트 2를 띄우고 **하나씩 짚어 가며** 확인시킨다.

   > 🗣️ "이 회로에서 하나라도 빠지면 보드가 안 켜지거나, 켜져도 디버깅을 못 합니다. **SWD를 안 뽑아 두면 보드를 다시 만들어야 합니다.**"

3. (18분) **게이트드라이버가 필요한 이유 — 계산으로 보여 준다.**

   > ✍️ 판서
   > ```text
   > Igate,peak ≈ Qg / tswitch
   > 예) Qg 30nC를 100ns에 밀어 넣으려면 → 0.3A
   > ```

   > 🗣️ "MCU 핀이 몇 mA 냅니까? 20mA 정도죠. **0.3A가 필요한데 20mA밖에 못 냅니다.** 그래서 드라이버가 있습니다. 게다가 전압도 3.3V가 아니라 12V가 필요하고요."

   부트스트랩과 UVLO를 함께 짚는다.

   ```text
   Igate,avg = Qg × fsw × 스위치 개수
   Cboot     ≥ Qtotal / ΔVboot
   ```

   > ⚠️ `Qtotal`에는 게이트 전하뿐 아니라 **드라이버 소비·누설·여유**가 포함된다. Qg만으로 정하면 부족하다.

4. (15분) **하드웨어 기본 안전 상태 4원칙.** 이 주차의 핵심이다.

   | 조건 | 요구 |
   |---|---|
   | MCU reset·미전원 | 드라이버 입력이 **풀다운으로 off** |
   | 드라이버 UVLO/fault | PWM 허용 조건에 포함 |
   | enable 1개 | 모든 상을 확실히 차단 |
   | 하드웨어 과전류 | **펌웨어가 멈춰도** 동작 |

   > 🗣️ "부팅하는 몇 ms 동안 MCU 핀은 입력 상태입니다. **떠 있죠.** 그때 게이트가 켜지면 어떻게 됩니까? 그래서 풀다운을 답니다. 8주차에 제가 Critical로 물었던 게 이겁니다."

> ✅ **이 블록이 끝났을 때** — 학생이 "MCU가 없어도 게이트는 꺼져 있어야 한다"를 회로로 설명할 수 있는 상태.

#### 블록 2 · 50~105분 — HSI 핀 리뷰와 회로 대조 (활동 1·2)

**목표** — 8주차 HSI 표를 **실제 회로도와 한 줄씩 대조**시킨다.

1. (25분) **활동 1 — HSI 핀 리뷰** (워크시트 Y 상단)

   표를 채우게 한다. 핵심은 **한 신호를 회로·코드·검증 세 곳에서 추적**하는 것이다.

   | 신호 | 핀 | 방향 | 회로 블록 | 코드 | 검증 |
   |---|---|---|---|---|---|
   | IAS_ADC | PA0 | In | 상전류 A | ADC1 IN0 | ADC raw |
   | THROTTLE | PA7 | In | 스로틀 | ADC2 IN7 | 전압 sweep |
   | HALL_A | PD0 | In | 홀센서 | EXTI0 | edge 인터럽트 |
   | PWM_U | PE9/PE8 | Out | TIM1 CH1/CH1N | CCR1 | 오실로스코프 |

   > ⚠️ **TIM1 CHx/CHxN 쌍이 드라이버의 high/low 입력과 맞는지** 반드시 확인시킨다. 뒤바뀌면 상하가 반대로 켜진다.

2. (18분) **활동 2 — 게이트드라이버 회로 리뷰** (워크시트 Y 하단)

   레퍼런스 보드 시트 3에서 항목별로 찾게 한다.

   | 리뷰 항목 | 무엇을 보는가 |
   |---|---|
   | 게이트 저항 위치 | 드라이버 출력과 게이트 **사이**에 있는가 |
   | 부트스트랩 다이오드·커패시터 | 역전압 정격, 용량 근거 |
   | high-side supply | 어디서 오는가 |
   | low-side return | 파워 GND와 어떻게 만나는가 |
   | PWM 입력 신호 레벨 | 3.3V 로직을 드라이버가 받는가 |
   | fault 출력 처리 | 어디로 가는가, 아무 데도 안 가면 NG |

   > 🗣️ "레퍼런스 보드에 게이트 저항이 36개 있습니다. 왜 그렇게 많죠? 12개 MOSFET × 3개(턴온·턴오프·풀다운)입니다. **하나씩 세어 보세요.**"

3. (12분) **전류 센싱과 NTC가 보호로 이어지는 경로.**

   > ✍️ 판서: `Vshunt = I × Rshunt`, 손실 `P = Irms² × Rshunt`

   > ⚠️ **Kelvin 센싱** — 전류가 흐르는 패드와 전압을 재는 배선을 분리한다. 안 하면 배선 저항이 측정값에 섞인다.

   과전류 임계값을 **두 경로로 나누는** 이유를 강조한다.

   | 경로 | 속도 | 특징 |
   |---|---|---|
   | 하드웨어 비교기 → TIM1 BKIN | 수 µs | 펌웨어와 무관 |
   | ADC → 소프트 판정 → Disable_PWM | 수백 µs | 진단·로깅에 유리 |

#### 블록 3 · 105~160분 — fault chain과 bring-up (활동 3·추가 실습)

**목표** — 차단 경로를 **색으로 끝까지 그리게** 한다.

1. (25분) **추가 실습 — fault chain 추적** (워크시트 Z 상단)

   회로도와 코드 양쪽에 **색 펜으로 경로를 표시**하게 한다.

   ```text
   션트 → 차동증폭(×15) → ①비교기 → TIM1 BKIN → BDTR MOE=0  (펌웨어 무관, 수 µs)
                         └→ ②ADC → I_Max 판정 → FltFlg → Disable_PWM()  (수백 µs)
                                                       └→ Fault LED / UART 코드
   ```

   > 🗣️ "두 갈래입니다. 위는 **빠르고 확실**하지만 왜 끊겼는지 모릅니다. 아래는 **느리지만 진단이 됩니다.** 둘 다 필요합니다."

   **stuck-at 검토**가 이 실습의 핵심이다.

   > ⚠️ "비교기 출력이 Low에 고착되면 어떻게 됩니까? **하드웨어 차단이 영원히 동작하지 않습니다.** 그런데 평소에는 아무 증상이 없죠. 그래서 15주차에 **신호 주입으로 경로를 시험**합니다."

   각 단계가 끊기거나 고착됐을 때 최종 출력이 안전한지 표로 검토시킨다.

2. (20분) **활동 3 — 회로 리뷰 체크리스트 10항목** (워크시트 Z 하단)

   판정은 OK/NG로 하고, **NG에는 반드시 조치와 리비전**을 적게 한다.

   예시 두 줄을 판서한다.

   ```text
   4  드라이버 UVLO가 PWM 허용 조건에 포함   NG
      → 조치: FAULT 출력을 PB12로 배선 (rev C)
   5  하드웨어 과전류 비교기 존재            NG
      → 조치: 비교기 + TIM1 BKIN 연결
   ```

   > 🗣️ "NG가 많은 게 나쁜 게 아닙니다. **NG를 못 찾는 게 나쁜 겁니다.** 찾아서 조치를 적으면 점수가 됩니다."

3. (10분) **bring-up 순서.** 만든 보드를 처음 켜는 절차다.

   ```text
   1 무전원 단락·극성 확인
   2 MCU 없이 보조전원(12/5/3.3V) 전류 제한으로 확인
   3 드라이버 enable off·fault 출력 확인
   4 DC 링크 저전압에서 PWM 입력·게이트 출력만 측정
   5 모터 없이 스위칭 노드·dead time 확인
   6 저전압·저duty·무부하 모터
   ```

   > 🗣️ "이 순서를 건너뛰면 어떻게 됩니까? 처음 전원을 넣는 순간 **어디가 잘못됐는지 모르는 채로 부품이 탑니다.** 한 단계씩 올라가면 어느 단계에서 문제가 생겼는지 압니다."

**교수는 돌아다니며 두 가지만 확인한다**
- 체크 항목에 **검증 방법**이 붙었는가 (판정만 있으면 반려)
- fault chain에서 **하드웨어 경로와 소프트웨어 경로를 구분**했는가

> ✅ **이 블록이 끝났을 때** — 각 팀이 NG 항목과 조치 계획이 담긴 체크리스트를 가진 상태.

#### 블록 4 · 160~180분 — 워치독과 과제

1. (10분) **펌웨어가 멈추는 경우 — 워치독.**

   > 🗣️ "제어 루프가 무한 루프에 빠지면 어떻게 됩니까? TIM1의 **마지막 duty가 그대로 유지**됩니다. 모터는 명령 없이 계속 돕니다."

   | 설계 원칙 | 이유 |
   |---|---|
   | **주기 태스크가 한 바퀴 정상으로 돌 때만** refresh | ISR에서 무조건 refresh하면 main이 죽어도 워치독이 살아 있다 |
   | 리셋 후 `RCC->CSR` reset 원인 플래그 기록 | 워치독 리셋이었는지 알아야 한다 |
   | 리셋 후 **PWM은 꺼진 채로 시작** | 재시작은 명시적 명령으로 |
   | timeout은 제어 주기보다 길고, 위험해지는 시간보다 짧게 | 1ms 제어 주기면 **수십 ms**가 출발점 |

   **TIM1 Break Input**도 다시 짚는다.

   > ⚠️ BKIN이 동작하면 `BDTR`의 **MOE가 하드웨어적으로 클리어**되어 펌웨어와 무관하게 PWM이 차단된다. 극성(BKP)과 필터를 실제 fault 신호에 맞추고, **자동 복구(AOE)는 켜지 않는다.**

2. (5분) **형성평가 4문항**

   1. 션트 저항을 크게 하면 측정 정확도와 전력 손실은 각각 어떻게 변하는가?
   2. MCU 소프트웨어 과전류 차단만으로 부족한 상황을 설명한다.
   3. TIM1 break input이 소프트웨어 차단보다 확실한 이유를 `BDTR` MOE로 설명한다.
   4. bootstrap capacitor를 gate charge만으로 정할 수 없는 이유는?

3. (3분) **과제 안내**

   > 12주차 과제 — 회로 리뷰 체크리스트와 fault chain
   > 제출물: 체크 항목 **10개 이상**과 판정 / fault chain 도식 / bring-up 절차
   > 형식: PDF 2~3장 · 파일명 `W12_팀명_이름.pdf`
   > 마감: 다음 주 수업 시작 전 · 1일 지각당 20% 감점
   > 배점 5점 — 항목이 구체적이고 검증 방법이 붙음 2 / NG에 조치·리비전 1 / HW·SW 차단 경로 구분 1 / 경로 고장 시 안전성 검토 1

4. (2분) **다음 주 예고**

   > 🗣️ "다음 주는 이 회로를 **PCB로 옮깁니다.** 오늘 정한 게이트 루프와 션트 배선이 그때 배치 순서를 결정합니다."

### 2. 판서 목록

1. `Igate,peak ≈ Qg / tswitch` — 30nC/100ns = 0.3A vs MCU 20mA
2. `Igate,avg = Qg × fsw × 스위치 개수`, `Cboot ≥ Qtotal / ΔVboot`
3. 하드웨어 기본 안전 상태 4원칙
4. `Vshunt = I × Rshunt`, Kelvin 센싱
5. fault chain 두 갈래 (비교기→BKIN 수 µs / ADC→소프트 수백 µs)
6. bring-up 6단계
7. 워치독 refresh 위치 원칙

### 3. 자주 나오는 질문과 답

| 학생 질문 | 답 |
|---|---|
| "MCU로 직접 MOSFET을 못 켜나요?" | 전압도 전류도 모자란다. 12V·수백 mA가 필요한데 3.3V·20mA뿐이다 |
| "소프트웨어 차단이 있는데 하드웨어가 왜 또 필요하죠?" | **펌웨어가 멈추면 소프트 차단도 멈춘다.** 하드웨어 경로는 CPU와 무관하게 동작한다 |
| "부트스트랩 커패시터는 크면 클수록 좋나요?" | 크면 충전 시간이 길어져 **기동이 느려진다.** 필요량의 몇 배 여유가 적정이다 |
| "UVLO는 뭘 막나요?" | 드라이버 전원이 낮으면 게이트를 **어중간하게** 켠다. 그러면 MOSFET이 저항처럼 발열한다 |
| "워치독을 ISR에서 갱신하면 안 되나요?" | main이 죽어도 ISR은 돌 수 있다. 그러면 **워치독이 고장을 못 잡는다** |
| "NG가 너무 많은데요?" | NG를 찾은 것이 성과다. **조치와 리비전을 적으면** 배점을 받는다 |

### 4. 시간이 남거나 모자랄 때

| 상황 | 대응 |
|---|---|
| 15분 이상 남음 | 레퍼런스 보드에서 게이트 저항 36개·부트스트랩 12개를 실제로 세어 구성을 역산 |
| 10분 남음 | 실물 보드가 있으면 SWD·UART 시험 포인트 접근성을 눈으로 확인 |
| 15분 부족 | 체크리스트를 10항목 → **7항목**으로 줄이되 Critical 2건은 반드시 포함 |
| 30분 이상 부족 | bring-up 순서를 과제로 넘긴다. **fault chain 추적(추가 실습)은 반드시 그 자리에서** — 15주차 시험 항목의 원본이다 |

### 5. 안전 점검

이 주차는 회로도 리뷰 중심이라 물리적 위험은 낮다. 대신 **다음 주부터 만들 보드의 안전을 지금 정한다.**

- 실물 보드를 다룬다면 **전원을 넣지 않은 상태**로 관찰만 한다
- 부품 핀을 맨손으로 만지지 않는다 (ESD)
- bring-up 순서는 **다음 학기·캡스톤에서 실제로 쓰인다.** 순서를 건너뛰지 않도록 강조한다
- 오늘 NG로 판정된 Critical 항목(부팅 중 게이트 off, 하드웨어 과전류 차단)은 **15주차 시연 전까지 반드시 조치**되어야 함을 공지한다
