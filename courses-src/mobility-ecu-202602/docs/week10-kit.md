# 10주차 운영 키트 — STM32 펌웨어 2: EXTI·ADC·Timer·UART

### 교안 정보

| 항목 | 내용 |
|---|---|
| 교과목 | 모빌리티 전자제어유닛 실습 (3학점 · 전공) |
| 대상 | 미래모빌리티학과 3~4학년 |
| 차시 | 10주차 / 15주차 · 180분 |
| 강의실 | Physical AI 실습실 |
| 관련 자료 | 상세 강의자료 10번 · 과제집 18번 · 배포용 워크시트 U·V |
| 실습 하드웨어 | **STM32F767 학습보드** |

### 학습목표

이 시간이 끝났을 때 학생은 다음을 수행할 수 있다.

1. EXTI 인터럽트로 외부 이벤트를 처리한다.
2. ADC로 아날로그 센서 값을 읽고 물리량으로 변환한다.
3. Timer로 주기 작업과 PWM·속도 측정 기반을 만든다.
4. UART로 내부 상태를 외부에 출력한다.

### 핵심 질문

- 폴링과 인터럽트는 언제 각각 적합한가?
- ADC raw 값은 어떻게 전압, 전류, 온도로 바뀌는가?
- UART 출력은 디버깅에서 왜 중요한가?

### 지도 중점

9주차가 "핀 하나 켜기"였다면, 10주차는 **"네 가지 주변장치를 하나의 시간축 위에 올리는 것"** 이다. 각각은 어렵지 않은데 **동시에 돌리면 서로 방해한다.** 이 주차의 목표는 주변장치 설정 암기가 아니라 **그 충돌을 설계하는 감각**이다.

> 📌 **9주차에 검산한 클럭 값이 오늘 계산의 입력이다.** 타이머 주기와 UART baud가 모두 그 값에서 나온다. 클럭 값을 잘못 알고 있으면 오늘 모든 계산이 틀린다.

### 1. 180분 진행 대본

#### 블록 1 · 0~45분 — 네 주변장치를 시간축에 올리기

**목표** — 각 주변장치가 **어떤 시간 스케일**을 담당하는지 먼저 정리한다.

1. (5분) **9주차 과제 피드백.** 클럭 검산 결과를 확인한다.

   > 🗣️ "지난주에 구한 216MHz가 오늘 **타이머 주기 계산의 분자**가 됩니다."

2. (12분) **시간 스케일 지도.** 판서로 4계층을 그린다.

   > ✍️ 판서
   > ```text
   > 홀센서 edge   → 언제 올지 모른다        → EXTI (인터럽트)
   > 전류·온도     → 정해진 시점에 읽는다     → ADC (타이머 트리거)
   > 속도 제어     → 1ms 주기                → Timer (주기 태스크)
   > 상태 확인     → 100ms면 충분            → UART (저순위)
   > ```

   > 🗣️ "네 가지를 따로 만들면 다 쉽습니다. **같이 돌리면 서로 방해합니다.** 오늘은 그 충돌을 설계합니다."

3. (13분) **인터럽트 설계 원칙.**

   > ⚠️ **우선순위는 "자주 발생하는가"가 아니라 "얼마나 늦어도 되는가"로 정한다.**

   | 이벤트 | 최대 허용 지연 | 우선순위 |
   |---|---|---|
   | 과전류 차단 | 수 µs | 최상 |
   | 홀 정류 | edge 직후 | 상 |
   | 속도 제어 | 1ms | 중 |
   | UART 상태 | 100~500ms | 하 |

   ISR에서 할 일과 하지 말 일을 명확히 한다.

   | ISR에서 한다 | main으로 넘긴다 |
   |---|---|
   | 원인 확인, pending flag 클리어 | 긴 UART 전송 |
   | 최소한의 데이터 캡처 | 부동소수점 계산 |
   | event 플래그 표시 | 대기 루프 |

4. (15분) **ADC 샘플링 시점** — 이 주차에서 가장 중요한 개념.

   > 🗣️ "PWM이 켜지고 꺼지는 순간에 전류를 재면 어떻게 될까요? **스위칭 노이즈 한가운데**입니다. 값이 튑니다."

   > ✍️ 판서: 타이머 트리거(TIM1 TRGO)로 **PWM 중앙**에 ADC를 동기시킨다

   6주차의 center-aligned PWM이 여기서 쓰이는 이유를 연결한다.

   ```text
   Vpin    = raw / 4095 × Vref
   Vsensor = (Vpin − Voffset) / gain
   ```

   > ⚠️ offset은 **PWM off 상태에서 여러 번 평균**해 구한다. 이 값을 안 빼면 전류가 0인데도 0이 아니게 읽힌다.

> ✅ **이 블록이 끝났을 때** — 학생이 "왜 ADC를 아무 때나 읽으면 안 되는지" 설명할 수 있는 상태.

#### 블록 2 · 45~90분 — 설정과 계산 (활동 1·2)

**목표** — 설정값을 **CubeMX가 아니라 손으로** 먼저 구하게 한다.

1. (18분) **활동 1 — Timer 주기 계산** (워크시트 U 상단)

   > ✍️ 판서
   > ```text
   > fupdate = ftimer / ((PSC+1) × (ARR+1))
   > Tupdate = 1 / fupdate
   > ```

   1ms 주기와 20kHz PWM에 필요한 `PSC`·`ARR`를 각각 구하게 한다. **9주차 클럭 값(216MHz)을 쓴다.**

   > 🗣️ "설정만 하고 끝내지 마세요. **GPIO를 토글해서 실제 주기를 재야** 합니다. 설정과 실제가 다른 경우가 생각보다 많습니다."

2. (15분) **활동 2 — UART 처리량 예산** (워크시트 U 중단)

   > ✍️ 판서
   > ```text
   > 8-N-1 → 1byte ≈ 10bit
   > 115200bps ÷ 10 = 11,520 byte/s
   > ```

   판서로 두 경우를 비교한다.

   ```text
   50byte × 10Hz  =    500 byte/s  (4.3%)   → 여유 충분
   50byte × 1kHz  = 50,000 byte/s  (434%)   → 불가
   ```

   > 🗣️ "434%입니다. 이러면 어떻게 됩니까? blocking 전송이면 **1ms 태스크가 안 끝납니다.** 제어가 무너지죠. 출력 주기를 낮추거나 DMA를 씁니다."

3. (12분) **CubeMX 설정 ↔ 레지스터 대응.**

   | CubeMX 설정 | 확인할 레지스터 |
   |---|---|
   | GPIO External Interrupt + NVIC 우선순위 | `SYSCFG->EXTICR`, `EXTI->IMR/RTSR/FTSR` |
   | ADC 채널·sampling time·trigger = TIM1 TRGO | `ADC->SMPRx`, `ADC->CR2` EXTSEL/EXTEN |
   | TIM1 PWM CHx/CHxN, center-aligned, dead time | `TIM1->PSC/ARR/CCMRx/CCER/BDTR` |
   | USART2 115200 8-N-1 | `USART->BRR`, `USART->CR1` |

   > ⚠️ **dead time은 ns로 입력하지만 `BDTR`의 DTG 필드 값으로 양자화된다.** 6주차에 계산한 500ns를 넣고 생성값을 확인하게 한다. 정확히 500ns가 아닐 수 있다.

#### 블록 3 · 90~160분 — 통합 계측 실습

**목표** — 네 가지를 동시에 돌리고 **타임라인을 실측**하게 한다.

1. (25분) **통합 코드 구성.** 스로틀 ADC + 1ms/10ms 태스크 + UART 출력 + 홀 EXTI.

   출력 형식을 통일시킨다 (Teleplot).

   ```text
   >Throttle:1.24
   >Vdc:18.2
   >RpmFdb:120.0
   >Flt:0
   ```

   > 🗣️ "형식을 통일하면 **그래프로 바로 볼 수 있습니다.** 다음 주 정류와 15주차 검증에서 계속 씁니다."

2. (30분) **추가 실습 — 통합 타임라인 측정** (워크시트 V)

   debug pin을 토글해 로직 애널라이저로 잰다.

   | 이벤트 | 목표 | 측정 방법 |
   |---|---|---|
   | Hall EXTI 처리 시간 | 20µs 이하 | debug pin toggle |
   | ADC 트리거 지연 | PWM 중앙 ±2µs | PWM/ADC 핀 비교 |
   | 1ms 태스크 주기 | 1.00ms ±2% | 로직 애널라이저 |
   | UART 상태 출력 | 100ms 주기 | 터미널 타임스탬프 |

   > 🗣️ "1ms 태스크가 1.02ms로 나왔다면 2% 오차입니다. 허용 범위죠. 그런데 **2ms가 나오면** 그건 오차가 아니라 **코드가 주기 안에 안 끝난 것**입니다."

3. (15분) **일관성 확인.** 스로틀을 천천히 돌리며 `ADC raw → 보정 전압 → 명령 duty → UART 출력`이 **같은 시간축에서 함께 움직이는지** 확인시킨다.

   > ⚠️ 어느 한 단계에서 값이 멈추거나 튀면 그 지점이 문제다. 네 값을 **동시에** 봐야 찾을 수 있다.

**교수는 돌아다니며 두 가지만 확인한다**
- **실측값을 적었는가** (설정값만 적은 팀이 많다)
- ISR 안에서 UART를 blocking으로 부르고 있지 않은가

> ✅ **이 블록이 끝났을 때** — 각 팀이 자기 코드의 실제 타이밍 숫자를 손에 쥔 상태.

1. (7분) **오늘의 함정 3가지**를 정리한다.

   3. ISR 안의 blocking UART 출력이 만드는 문제를 두 가지 제시한다.
   4. CubeMX에 dead time을 1µs로 입력했을 때 생성된 `BDTR` DTG 값이 정확히 1µs가 아닐 수 있는 이유는?

3. (5분) **과제 안내**

   > 배점 5점 — raw 값을 물리량으로 변환하고 실측 대조 2 / 타이머 설정 계산과 실측 확인 1 / UART 처리량 예산 계산 1 / 출력 형식이 검증 가능하고 일관 1

   > 🗣️ "보드가 없으면 **예상 출력 예시**를 넣으세요. 다만 예상이라고 명시해야 합니다."

4. (3분) **다음 주 예고**

### 2. 판서 목록

1. 시간 스케일 4계층 (EXTI / ADC / Timer / UART)
2. 인터럽트 우선순위는 **최대 허용 지연**으로 결정
3. ISR에서 할 일 vs main으로 넘길 일
4. `Vpin = raw/4095 × Vref`, `Vsensor = (Vpin − Voffset)/gain`
5. `fupdate = ftimer / ((PSC+1)(ARR+1))`
6. UART 예산 `115200 ÷ 10 = 11,520 byte/s`, 두 경우 비교(4.3% vs 434%)
7. CubeMX 설정 ↔ 레지스터 4행 대응표

### 3. 자주 나오는 질문과 답

| 학생 질문 | 답 |
|---|---|
| "인터럽트를 많이 쓰면 좋은 거 아닌가요?" | 응답은 좋아지지만 **우선순위 설계가 없으면** 서로를 밀어낸다. 허용 지연 순서로 정한다 |
| "ADC 값이 계속 튀어요" | ① PWM과 동기됐는가 ② 샘플링 시간이 소스 임피던스에 충분한가(2주차) ③ offset을 뺐는가 |
| "1ms 태스크인데 1.02ms가 나와요" | 2% 오차는 정상 범위다. **2ms가 나오면** 코드가 주기 안에 안 끝난 것이다 |
| "UART로 다 찍으면 안 되나요?" | 처리량을 계산해 보라. 1kHz × 50byte는 **434%**다. 주기를 낮추거나 DMA를 쓴다 |
| "dead time을 1µs로 넣었는데 다르게 나와요" | `BDTR`의 **DTG 필드로 양자화**된다. 입력값과 생성값을 비교하는 것이 정답이다 |
| "ISR에서 printf 쓰면 안 되나요?" | 매우 느리고 blocking이다. **주기가 밀리고 이벤트가 유실된다.** 플래그만 세우고 main에서 출력한다 |

### 4. 시간이 남거나 모자랄 때

| 상황 | 대응 |
|---|---|
| 15분 이상 남음 | DMA로 UART 전송을 바꿔 보고 CPU 점유가 어떻게 달라지는지 관찰 |
| 10분 남음 | ADC 샘플링 시점을 일부러 PWM edge로 옮겨 값이 튀는 것을 보여 준다 |
| 15분 부족 | 타임라인 측정 항목을 **1ms 태스크 주기 + UART 주기 2개**로 줄인다 |
| 30분 이상 부족 | 통합 실습을 과제로 넘긴다. **활동 1·2(타이머·UART 계산)는 반드시 그 자리에서** — 과제 배점 2점이 걸려 있다 |

### 5. 안전 점검

로직 실습이라 전기적 위험은 낮으나, **다음 주부터 모터가 이 코드로 돈다.**

- 이번 주 코드에 **PWM 출력을 연결하지 않는다.** 정류 로직 없이 PWM만 내보내면 모터가 예측 불가하게 움직인다
- 홀센서 입력은 **손으로 모터를 돌려** 만든다. 전원을 넣고 돌리지 않는다
- 보드에 전원이 들어간 상태로 점퍼선을 옮기지 않는다
- 로직 애널라이저 GND를 보드 GND에 먼저 연결한 뒤 신호 프로브를 연결한다
- 가변저항으로 스로틀을 모의할 때 **3.3V를 넘기지 않도록** 결선을 확인한다
