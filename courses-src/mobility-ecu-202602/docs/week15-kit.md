# 15주차 운영 키트 — 통합 검증, 최종 발표, 로버 미션 시연

### 교안 정보

| 항목 | 내용 |
|---|---|
| 교과목 | 모빌리티 전자제어유닛 실습 (3학점 · 전공) |
| 대상 | 미래모빌리티학과 3~4학년 |
| 차시 | 15주차 / 15주차 · 180분 |
| 강의실 | Physical AI 실습실 |
| 관련 자료 | 상세 강의자료 15번 · 과제집 19번 · 배포용 워크시트 AE·AF |
| **평가 반영** | **최종 프로젝트 문서 25% + 최종 발표 및 시연 20% = 45%** |

### 학습목표

이 시간이 끝났을 때 학생은 다음을 수행할 수 있다.

1. 요구사항에서 출발해 회로, PCB, 펌웨어, 검증 결과를 하나의 이야기로 발표한다.
2. BLDC/로버 구동 제어유닛의 동작 흐름과 안전 차단 로직을 설명한다.
3. 최종 시연 또는 제한 조건 모듈 테스트를 수행하고 개선 방향을 제시한다.

### 핵심 질문

- 우리 시스템은 어떤 요구사항을 만족했고, 어떤 요구사항은 아직 검증하지 못했는가?
- 실패한 테스트는 나쁜 결과인가, 좋은 공학적 증거인가?
- 다음 버전에서 가장 먼저 고쳐야 할 것은 무엇인가?

### 지도 중점

마지막 주의 기준은 "**돌았다**"가 아니라 "**돌았다는 것을 남이 재현할 수 있는가**"다. 같은 시연이라도 전류 제한·펌웨어 버전·판정 기준이 적혀 있지 않으면 증거가 아니다.

> 📌 **실패도 좋은 결과다.** 요구사항·측정 증거·원인 가설·다음 시험이 연결되어 있으면 그것이 공학이다. 1주차 워크시트 C에 적은 요구사항 3개가 여기서 추적표의 첫 행이 되어 돌아온다.

> ⚠️ **평가 45%가 걸린 주차다.** 8주차와 마찬가지로 교수의 역할은 강의가 아니라 **진행·판정·안전 관리**다. 특히 시연 중 안전 사고가 나지 않도록 pre-flight gate를 예외 없이 적용한다.

**14주 산출물이 전부 모인다**

| 주차 | 가져올 것 |
|---|---|
| 1 | 워크시트 C — 요구사항 3개, 미니 FMEA |
| 4 | 워크시트 I — 전원 트리·전력 예산 |
| 5 | 워크시트 K·L — 모터 사양, 홀 실측 |
| 6 | 워크시트 M — 6-step 표, 데드타임 |
| 7 | 워크시트 P — PI 게인과 선택 근거 |
| 8 | 요구사항 추적 트리, HSI |
| 10·11 | 워크시트 V·X — 타임라인, 차단 지연 실측 |
| 12 | 워크시트 Z — 체크리스트 NG 항목과 조치 |
| 14 | 워크시트 AC — 개선안 3건 |

### 0. 전날 체크리스트

**인쇄물**

| 인쇄물 | 분량 | 용도 |
|---|---|---|
| 워크시트 AE — 요구사항 추적표와 시험 명세 | 팀 수 + 2 | 발표 준비·시연 |
| 워크시트 AF — pre-flight gate와 시연 기록 | 팀 수 + 2 | 시연 |
| 교수 평가표 (이 문서 6절) | 팀 수 | 채점 45% |
| [15주차 배포용 워크시트](week15-worksheets.md)에 AE·AF 양식이 있다 | | |

**시연 준비 — 안전이 최우선이다**

- **비상 정지 수단** — 전원공급기 출력 스위치를 시연자 손이 닿는 위치에
- 바퀴 공중 부양 거치대 (팀 수만큼)
- 지면 주행을 한다면 **주행 구역과 관람 구역을 분리**하고, 로버가 사람 쪽으로 향하지 않게 방향을 정한다
- 전원공급기(전류 제한), 멀티미터, 오실로스코프, 로직 애널라이저
- 소화기 위치 확인, 환기
- 5m 주행 시험을 한다면 **줄자로 구간을 미리 표시**해 둔다

**진행 준비**

- 발표 순서를 미리 정해 공지 (8주차와 같은 방식)
- 발표 자료를 **수업 전까지 제출**받아 한 노트북에 모아 둔다
- 타이머 (10분 발표 / 5분 질의)
- 시연 순서 — 발표를 모두 마친 뒤 시연할지, 팀별로 발표+시연을 붙일지 미리 정한다

**미리 열어 둘 자료**

1. [주차별 용어 정리 15주차](https://parclab-hsu.github.io/courses/202602/mobility-ecu/terms-by-week/#week15)
2. 과제집 「15주차 과제」의 **추적표 예시와 실패 분석 서술**
3. 8주차 교수 평가표와 **Critical 결함 조치 기한 기록**
4. 12주차 각 팀의 NG 항목 목록

**14주차 과제 회수** — 미제출자 확인. 개선안 3건이 최종 보고서에 반영됐는지 본다.

### 1. 시간 배분 — 팀 수에 따라 미리 계산한다

기본은 **발표 10분 + 질의 5분**, 시연은 팀당 **8분**이다.

| 팀 수 | 발표+질의 | 시연 | 합계 | 조정 |
|---|---|---|---|---|
| 4 | 60분 | 32분 | 92분 | 여유 있음 |
| 5 | 75분 | 40분 | 115분 | 적정 |
| 6 | 90분 | 48분 | 138분 | 빠듯함 — 질의 4분으로 |
| 7 | 105분 | 56분 | 161분 | **발표 8분 + 질의 3분 + 시연 6분** |

> ⚠️ **시연 시간을 먼저 확보한다.** 발표가 밀려 시연이 잘리면 45% 평가의 절반이 근거를 잃는다.

### 2. 180분 진행 대본

#### 블록 1 · 0~20분 — pre-flight gate

**목표** — 시연 전에 **안전과 재현 조건**을 확정한다.

1. (5분) **오늘의 진행과 평가 안내.**

   > 🗣️ "오늘 평가는 45%입니다. 그런데 **동작 성공 여부로 매기지 않습니다.** 요구사항별 판정과 증거가 연결되는지를 봅니다."

2. (15분) **팀별 pre-flight gate 통과 확인** (워크시트 AF 상단)

   교수가 **팀별로 직접 확인**하고 서명한다. 통과하지 못한 팀은 시연을 못 한다.

   | 확인 항목 | 통과 조건 |
   |---|---|
   | 기구 고정, 바퀴 공중 부양, 비상정지 접근 | 손이 닿는 위치 |
   | 전원 극성, 퓨즈, 전류 제한, DC 링크 전압 | 설정값 기록 |
   | 초기 PWM off, throttle plausibility, **Hall 000/111 검사** | 코드에 존재 |
   | fault LED/UART와 **하드웨어 차단 시험** 통과 | 신호 주입으로 확인 |
   | 시험 담당·관찰 담당·**비상차단 담당** 지정 | 이름을 적는다 |

   > 🗣️ "이 표에 하나라도 빈칸이 있으면 시연하지 않습니다. **예외는 없습니다.**"

   **펌웨어 버전 고정**도 여기서 한다.

   > ⚠️ 발표 직전에 결과가 바뀌지 않도록 **release candidate 펌웨어의 버전명 또는 hash와 설정값**을 기록한다. 이후 코드를 수정하면 그 시연은 무효다.

---

#### 블록 2 · 20~90분 — 팀별 최종 발표

**발표 구성 (칠판에 고정, 10분)**

```text
1  프로젝트 개요·팀 역할        (1분)
2  요구사항 요약                (1.5분)
3  시스템 블록도·HSI 핵심 신호   (1.5분)
4  전원/센서/인버터 회로         (1.5분)
5  PCB 배치와 노이즈 대책        (1.5분)
6  펌웨어 구조                  (1.5분)
7  검증 결과 (PASS/FAIL/PARTIAL) (1분)
8  실패·제한사항과 개선 계획      (0.5분)
```

> 🗣️ "7번과 8번이 배점의 중심입니다. **1~6번을 길게 하고 7·8번을 대충 넘기는 발표가 매년 나옵니다.** 시간을 지키세요."

**교수가 매 팀에서 반드시 확인할 5가지**

| 확인 항목 | 미흡하면 |
|---|---|
| 요구사항별 PASS/FAIL/PARTIAL 판정이 있는가 | 감점 |
| 판정마다 **증거 파일**이 연결되는가 | 감점 |
| 실패·미달을 **숨기지 않았는가** | 큰 감점 |
| **8주차 Critical 결함**이 조치됐는가 | 시연 불가 |
| **12주차 NG 항목**이 조치됐는가 | 감점 |

> ⚠️ 8주차에 Critical(부팅 중 게이트 off, 과전류 차단 경로)을 받은 팀은 **조치 여부를 먼저 확인**하고, 미조치면 시연을 허가하지 않는다.

**질의 5분 진행 방식** — 8주차와 동일하게 **청중 팀 2곳 + 교수** 순서로 고정한다.

#### 블록 3 · 90~160분 — 시연과 고장 주입

> 🔴 **pre-flight gate를 통과한 팀만 시연한다.**

**목표** — 요구사항별로 **증거를 만드는** 시간이다.

1. **단계적 시험 — 아래 단계의 증거 없이 위로 올라가지 않는다.**

   | 단계 | 조건 | 통과 기준 |
   |---|---|---|
   | 1 벤치 | 모터 분리, PWM만 | 파형·dead time 정상, fault 차단 동작 |
   | 2 무부하 회전 | 바퀴 공중 부양 | 좌우 방향 일치, RPM 추종, 전류 예상 범위 |
   | 3 차동 동작 | 바퀴 공중 부양 | v/ω 명령이 좌우 RPM으로 올바르게 분배 |
   | 4 저속 직진 | 지면, duty 제한 | 5m 주행의 경로 이탈·좌우 편차 기록 |
   | 5 선회·제자리 회전 | 지면 | 최소 회전반경 달성, 회전 시 전류 상승 확인 |
   | 6 경사·험지 | 목표 등판각부터 단계 상승 | 실패 지점 각도와 원인 기록 |

   > 🗣️ "1·2·3단계는 바퀴가 떠 있습니다. **4단계부터 지면입니다.** 그때부터 비상차단 담당이 로버 진행 방향 반대편에 섭니다."

   미션 판정 기준을 명시한다 — 미션 A는 4·5단계, 미션 B는 6단계, 미션 C는 6단계의 노면 조건 변경.

2. **fault injection** — 안전하게 만들 수 있는 고장만 주입한다.

   | 주입 | 확인할 것 |
   |---|---|
   | 저전압 전원 | UVLO 동작, 재기동 조건 |
   | Hall 신호 분리 | timeout → PWM 차단, **차단 지연 실측** |
   | 스로틀 범위 이탈 | plausibility 판정 |
   | 온도센서 모의 입력 | 과열 보호 |
   | **12주차 fault chain 신호 주입** | 비교기 stuck-at 검출 |

   > ⚠️ **실제 하드 단락으로 과전류를 시험하지 않는다.** 제한된 신호 주입 또는 저에너지 시험법만 쓴다.

   > 🗣️ "11주차에 잰 차단 지연과 오늘 값을 비교하세요. **하드웨어 경로를 넣었으면 훨씬 짧아졌어야** 합니다."

3. **튜닝 결과는 숫자로 기록한다.**

   > 🗣️ "'좋아졌다'는 결과가 아닙니다. **직진 편차(5m당 m), 최소 회전반경(m), 등판 실패각(°), 최대 전류(A)** 로 적으세요."

**교수는 시연 내내 두 가지만 본다**
- **안전 절차를 지키는가** (이것이 최우선, 어기면 즉시 중단)
- 측정값에 **조건과 버전**이 붙는가

#### 블록 4 · 160~180분 — 추적표와 회고

1. (10분) **요구사항 추적표 완성** (워크시트 AE)

   | 요구사항 ID | 내용 | Test ID | 방법 | 결과 | 증거 | 비고 |
   |---|---|---|---|---|---|---|
   | REQ-PWR-001 | 18~30V에서 3.3V ±5% | T-PWR-01 | DMM, 3전압 | PASS | `T-PWR-01.csv` | 3.29~3.31V |
   | REQ-SAFE-001 | 과전류 2ms 내 차단 | T-SAFE-02 | 신호 주입 | PASS | `T-SAFE-02.png` | 실측 0.4ms |
   | REQ-SAFE-002 | 홀 소실 시 안전 상태 | T-SAFE-03 | 커넥터 분리 | **FAIL** | `T-SAFE-03.png` | RPM 유지, 차단 없음 |
   | REQ-DRV-001 | 평지 0.5m/s로 5m | T-DRV-04 | 지면 주행 | PARTIAL | `T-DRV-04.mp4` | 0.42m/s, 편차 0.35m |
   | REQ-DRV-002 | 제자리 회전 | T-DRV-05 | 지면 회전 | BLOCKED | — | 타이어 미끄러짐, 재시험 예정 |

   > 🗣️ "FAIL과 BLOCKED가 있는 표가 **좋은 표**입니다. 전부 PASS인 표는 오히려 의심스럽습니다. 시험을 안 했거나 기준을 낮춘 거죠."

   > ⚠️ **증거 파일 이름은 Test ID와 일치**시킨다. "동작 영상"만으로는 전류 제한·펌웨어 버전·판정 기준을 재현할 수 없다.

2. (7분) **회고 — 다음 버전 우선순위.**

   각 팀이 **가장 먼저 고칠 것 하나**를 말하게 한다.

   > 🗣️ "시간이 무한하다면 다 고치겠죠. **하나만 고칠 수 있다면 무엇입니까?** 그 판단이 공학입니다."

3. (3분) **최종 제출 안내**

   > 15주차 과제 — 최종 보고서 + 발표자료 + 실습 증거 + 요구사항 추적표
   > 형식: 보고서 PDF + 발표 10분 분량 + 증거 파일 묶음 · 파일명 `W15_팀명.pdf` (**팀 단위**)
   > 필수: PASS/FAIL/PARTIAL 판정, 실패 원인 분석, 다음 개선 계획, **펌웨어 버전(해시·태그)과 설정값**
   > 배점 5점 — 요구사항별 판정과 증거가 1:1 연결 2 / 실패·미달을 숨기지 않고 원인 분석 1 / 버전·설정값으로 재현 가능 1 / 개선 계획에 우선순위와 재시험 ID 1

   > ⚠️ 이 과제는 **「최종 프로젝트 문서」 항목(25%)** 으로 평가한다. 오늘 발표·시연은 **「최종 발표 및 시연」(20%)** 이다.

### 3. 판서 목록

1. 시험 수준 `단위 → 모듈 → 통합 → 인수`
2. 시험 명세 필수 항목 (Test ID·조건·버전·기대값·판정·증거)
3. pre-flight gate 5항목
4. 섀시 통합 6단계와 통과 기준
5. 판정 4종 `PASS / FAIL / PARTIAL / BLOCKED`
6. 튜닝 결과 4지표 (직진 편차·최소 회전반경·등판 실패각·최대 전류)
7. 증거 파일명 = Test ID

### 4. 자주 나오는 질문과 답

| 학생 질문 | 답 |
|---|---|
| "동작을 못 했는데 발표할 게 있나요?" | 있다. **모듈 테스트 증거와 다음 검증 계획**을 제시하면 평가 대상이다. 이 과목은 처음부터 그렇게 설계됐다 |
| "FAIL을 적으면 감점 아닌가요?" | 반대다. **숨기는 것이 큰 감점**이다. FAIL에 원인 분석과 재시험 ID가 붙으면 점수를 받는다 |
| "BLOCKED와 FAIL의 차이는요?" | FAIL은 **시험했는데 기준 미달**, BLOCKED는 **시험 자체를 못 한 것**이다. 사유를 적는다 |
| "영상만 제출하면 안 되나요?" | 영상으로는 전류 제한·펌웨어 버전·판정 기준을 알 수 없다. **Test ID와 조건이 함께** 있어야 증거다 |
| "발표 직전에 코드를 고쳐도 되나요?" | 안 된다. **release candidate를 고정**한 뒤 시연한다. 고치면 그 시연은 무효다 |
| "전부 PASS면 좋은 거 아닌가요?" | 시험 기준이 느슨했는지 의심한다. **요구사항 수치가 충분히 엄격한지** 함께 본다 |

### 5. 시간이 남거나 모자랄 때

| 상황 | 대응 |
|---|---|
| 15분 이상 남음 | 팀 간 상호 질의를 한 라운드 더, 또는 우수 사례 1건을 전체 공유 |
| 10분 남음 | 다음 학기 캡스톤 연결 안내와 미해결 FAIL 정리 |
| 15분 부족 | 질의를 **교수 1건**으로 줄인다 |
| 30분 이상 부족 | 시연을 **단계 1~3(바퀴 공중 부양)까지만** 하고 지면 주행은 별도 시간에. **추적표 작성은 반드시 그 자리에서** |

> ⚠️ 시간이 부족하다고 **pre-flight gate를 생략하지 않는다.** 줄일 것은 발표 시간이지 안전 절차가 아니다.

### 7. 안전 점검 — 이 주차가 가장 위험하다

**지면 주행이 포함되는 유일한 주차다.**

- 🔴 **pre-flight gate를 통과하지 못한 팀은 시연하지 않는다.** 예외 없음
- 🔴 **주행 구역과 관람 구역을 분리**하고, 로버가 사람 쪽으로 향하지 않게 방향을 정한다
- 🔴 팀마다 **비상 차단 담당 1명**을 지정하고, 지면 주행 시 **로버 진행 방향 반대편**에 세운다
- 위험 회전체(프로펠러 등) 장착 상태로 구동하지 않는다
- 지면 시험 전에 **좌우 방향 정의, 한 채널 fault 시 양쪽 정지, 저전압 차단**을 다시 확인한다
- fault injection은 **신호 주입으로만.** 하드 단락 금지
- 전원공급기 전류 제한을 시연 조건에 맞게 설정하고 기록한다
- 이상 냄새·연기·과열 시 **즉시 전원 차단 후 전원 인가 금지**, 교수가 확인할 때까지 재시도하지 않는다
- 배터리를 쓴다면 시연 후 **분리하고 지정 장소에 보관**한다
