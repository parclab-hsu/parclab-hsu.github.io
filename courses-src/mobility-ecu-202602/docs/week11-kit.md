# 11주차 운영 키트 — BLDC 6-step 구동 펌웨어

### 교안 정보

| 항목 | 내용 |
|---|---|
| 교과목 | 모빌리티 전자제어유닛 실습 (3학점 · 전공) |
| 대상 | 미래모빌리티학과 3~4학년 |
| 차시 | 11주차 / 15주차 · 180분 |
| 강의실 | Physical AI 실습실 |
| 관련 자료 | 상세 강의자료 11번 · 과제집 19번 · 배포용 워크시트 W·X |
| 실습 하드웨어 | **STM32F767 학습보드** + BLDC 모터 |

### 학습목표

이 시간이 끝났을 때 학생은 다음을 수행할 수 있다.

1. 홀센서 입력으로 sector를 판단하고 6-step switching pattern을 생성한다.
2. TIM1 PWM 출력과 phase pattern의 관계를 이해한다.
3. 구동 코드에서 안전 차단 조건을 찾고 설명한다.

### 핵심 질문

- HallSum 값이 바뀔 때 어떤 상을 켜야 하는가?
- PWM duty와 상 패턴은 코드에서 어디서 만나는가?
- Fault가 발생하면 어떤 출력이 0이 되어야 하는가?

### 지도 중점

**이 주차는 앞선 세 주차가 합쳐지는 지점이다.** 5주차에 손으로 잰 홀 순서, 6주차에 만든 6-step 표, 10주차에 세운 EXTI·타이머 구조가 **하나의 제어 루프**가 된다.

> 📌 **학생이 세 장의 워크시트를 가져와야 수업이 성립한다.** 지난주에 강조하고, 오늘도 시작할 때 확인한다.
> 워크시트 L(5주차 홀 순서) · 워크시트 M(6주차 6-step 표) · 워크시트 V(10주차 타임라인)

> ⚠️ **이 주차부터 모터가 펌웨어로 돈다.** 정류 표가 틀린 채 duty를 올리면 상·하단이 동시에 켜져 관통 전류가 흐른다. 저전압·전류 제한·저 duty에서만 검증한다.

### 1. 180분 진행 대본

#### 블록 1 · 0~35분 — 정류와 RPM 복습

**목표** — 세 주차의 산출물을 **한 장으로 잇는다.**

1. (5분) **지참물 확인과 연결 선언.**

   > 🗣️ "5주차에 손으로 돌려서 잰 홀 순서, 6주차에 만든 6-step 표, 10주차에 세운 인터럽트 구조. **오늘 이 셋이 하나의 루프가 됩니다.**"

2. (12분) **Hall 순서와 회전 방향.**

   유효 6상태는 같지만 **방향에 따라 나타나는 순서가 다르다.**

   > ✍️ 판서
   > ```text
   > 정상  : 한 번에 1비트만 바뀐다 (Gray code)
   > 불법  : 2비트 이상 동시 변화 → 신호 이상
   > 오류  : 000, 111 → 단선·단락
   > ```

   > 🗣️ "이전 상태와 새 상태의 **조합**으로 정방향·역방향·불법 전이를 판정합니다. 표를 복사해 오면 배선이 다를 때 그대로 틀립니다."

3. (10분) **RPM 계산과 함정.**

   > ✍️ 판서: `mechanical_rpm = 60 × hall_edge_frequency / (6 × pole_pairs)`

   > ⚠️ **pole과 pole pair를 혼동하면 2배 틀린다.** 5주차에 실측한 극쌍 수를 쓰게 한다.

   저속과 노이즈 처리도 짚는다.

   | 상황 | 처리 |
   |---|---|
   | edge 간격이 너무 길다(저속) | **timeout으로 RPM을 0으로 갱신** |
   | 아주 짧은 pulse | 최소 간격 검사로 노이즈 제거 |

4. (8분) **구동 상태기계.**

   > ✍️ 판서
   > ```text
   > DISABLED → ALIGN/START → RUN → FAULT
   >     ↑          │          │       │
   >     └──────────┴── STOP ──┴───────┘
   > ```

   | 상태 | PWM | 해야 할 일 |
   |---|---|---|
   | DISABLED | 전부 off | 적분항·명령 상태 초기화 |
   | ALIGN/START | 제한 duty | 초기 위치·방향 확인 |
   | RUN | 정류 | Hall 전이마다 정류, 주기 태스크에서 속도 제어 |
   | FAULT | **즉시 차단** | 원인 latch, 명시적 재시작 전까지 유지 |

> ✅ **이 블록이 끝났을 때** — 학생이 자기 팀 표로 방향 판정 규칙을 말할 수 있는 상태.

#### 블록 2 · 35~90분 — 코드 흐름 분석 (활동 1·2)

**목표** — 코드를 **문맥(context)별로 나눠** 읽게 한다.

1. (25분) **활동 1 — 함수 호출·인터럽트 흐름도** (워크시트 W 상단)

   판서로 뼈대를 그린다. **문맥을 선 종류로 구분**하게 한다.

   ```text
   [TIM1 UP ISR 20kHz]  ADC 읽기 → 전류·온도 판정 → Fault 처리 → Set_Phases()
           │                                   ↓ (FltFlg 세트 시)
           │                              Disable_PWM()  ← MOE=0, 채널 마스크
   [EXTI0/1/2]  Hall edge → Update_Hall_Sequence() → SpeedCal() → calculated_rpm
           │                                                            │ (공유)
   [1ms Task]   RpmRef → PI → VoltageRef ───────────────────────────────┘
   [10ms Task]  UART 상태 출력      [500ms Task] 요약 로그
   ```

   **공유 데이터를 반드시 표시**하게 한다.

   > 🗣️ "`calculated_rpm`, `HallSum`, `FltFlg`, `VoltageRef` — 이 넷은 **ISR과 main이 같이 만집니다.** 여기가 버그가 사는 곳입니다."

   > ⚠️ `volatile`을 붙였다고 끝이 아니다. **여러 변수를 한 세트로 읽어야 하면** 일관성 보장이 따로 필요하다(9주차 연결).

2. (18분) **활동 2 — baseline 코드 결함 찾기** (워크시트 W 중단)

   **정답을 먼저 주지 않는다.** 힌트를 순서대로 준다.

   | 단계 | 힌트 |
   |---|---|
   | 1 | "홀 커넥터를 뽑으면 화면의 RPM은 어떻게 될까요?" |
   | 2 | "`SpeedCal()`은 edge가 **안 올 때** 무엇을 합니까?" |
   | 3 | "속도 지령에 음수를 넣으면 duty 변수에 무엇이 대입됩니까?" |

   찾아야 할 결함 예 (최소 2건).

   | 번호 | 위치 | 관측 | 위반 요구사항 | 개선안 |
   |---|---|---|---|---|
   | F-01 | `SpeedCal()` | Hall edge가 끊겨도 마지막 RPM 유지. 커넥터를 뽑아도 300rpm 표시 | REQ-SAFE-002 (센서 소실 시 안전 상태) | edge timeout 후 RPM 0, PWM 차단 |
   | F-02 | 속도 PI | 적분항 무제한 누적, 음수 지령이 부호 없는 변수에 대입되어 duty 최대로 뒤집힘 | REQ-CTL-001, REQ-SAFE-001 | 적분항 clamp, 하한 클램프 후 부호 처리 |

   > 🗣️ "결함을 찾는 것으로 끝나지 마세요. **어느 요구사항을 위반했는지** 적어야 점수가 됩니다. 8주차에 만든 요구사항 번호를 쓰세요."

3. (12분) **안전 차단 경로를 끝까지 따라간다.**

   > ✍️ 판서
   > ```text
   > 과전류 감지 → FltFlg=1 → Disable_PWM() → MOE=0 → 게이트 출력 Low
   >             → Fault LED ON → UART fault 코드 전송
   > ```

   > 🗣️ "소프트웨어 플래그 하나로 끝나면 안 됩니다. **하드웨어 수준(MOE=0, 게이트 Low)까지** 이어져야 합니다. 12주차에 이걸 회로로 한 겹 더 쌓습니다."

   > ⚠️ **복구는 자동이 아니다.** 원인 제거 후 **명시적 재시작 명령**으로만 RUN으로 돌아간다.

#### 블록 3 · 90~160분 — 계측과 고장 주입

> ⚠️ **시작 전 안전 확인.** 축 고정, 전류 제한, duty 상한, 비상 차단 담당을 팀별로 교수가 직접 확인한 뒤 전원을 켜게 한다.

**목표** — 정류가 **실제로 표대로 동작하는지** 눈으로 확인시킨다.

1. (30분) **Hall/PWM 동시 캡처** (워크시트 X 상단)

   로직 애널라이저로 **Hall A/B/C + PWM enable 3채널**을 동시에 잡는다.

   | 확인 항목 | 판정 기준 |
   |---|---|
   | 각 Hall 전이 직후 기대 sector가 적용되는가 | 워크시트 M의 표와 일치 |
   | Hall 전이 → PWM 갱신 지연 | 20µs 이하 (10주차 실측값 참조) |
   | 한 번에 몇 비트가 바뀌는가 | 1비트 |
   | dead time이 유지되는가 | 6주차 설정값 |

   > 🗣️ "표가 맞는지 **모터가 도는 걸로 판단하지 마세요.** 진동하면서 돌 수도 있습니다. 파형으로 확인해야 합니다."

   증상-원인 대조표를 칠판에 남긴다.

   | 증상 | 유력한 원인 |
   |---|---|
   | 진동만 하고 회전하지 않음 | 정류 순서가 뒤섞임 |
   | 한 방향만 회전 | 역방향 테이블 오류 |
   | 특정 구간에서만 덜컥거림 | 홀 1채널 노이즈·접촉 불량 |
   | 반대로 회전 | 시퀀스 방향 반전 |

2. (25분) **고장 주입** (워크시트 X 하단)

   **안전하게 만들 수 있는 고장만** 주입한다.

   | 주입할 고장 | 방법 | 기대 동작 |
   |---|---|---|
   | 홀 신호 소실 | 홀 커넥터 1개 분리 | timeout → RPM 0 → PWM 차단 |
   | 불법 Hall 값 | 000 또는 111 강제 입력 | 즉시 fault, PWM 차단 |
   | 명령 timeout | UART 명령 중단 | 감속 후 정지 |

   > ⚠️ **하드 단락으로 과전류를 만들지 않는다.** 전류 제한을 낮게 걸고 신호 주입으로만 시험한다.

   각 고장마다 **차단 지연 시간을 실측**하게 한다.

   > 🗣️ "'차단됐다'로 끝나면 안 됩니다. **몇 ms 만에** 차단됐는지 재세요. 8주차 HSI에 적은 최대 허용 지연과 비교해야 합니다."

3. (15분) **재시작 조건 확인.**

   | 확인 | 결과 |
   |---|---|
   | 고장 원인을 제거하면 자동으로 돌아가는가 | **자동 재시작이면 결함** |
   | 명시적 재시작 명령이 필요한가 | |
   | 재시작 시 PWM이 꺼진 상태에서 시작하는가 | |

   > 🗣️ "원인이 사라졌다고 저절로 다시 돌면 어떻게 됩니까? **같은 고장을 반복**합니다. 사람이 확인하고 다시 켜야 합니다."

4. **(선택) 2축 확장 논의.** 좌우 채널을 독립으로 두되 fault는 공통으로 묶는 구조를 레퍼런스 보드 시트 3·4로 보여 준다.

   > ⚠️ **한 채널만 정지시키면 로버가 제자리에서 돈다.** 한쪽 fault 시 양쪽을 함께 정지시킨다.

**교수는 돌아다니며 두 가지만 확인한다**
- 정류 표를 **자기 팀 실측값(워크시트 L·M)** 으로 검증하고 있는가
- 고장 주입 시 **차단 지연을 숫자로** 쟀는가

> ✅ **이 블록이 끝났을 때** — 각 팀이 고장 주입에 대한 차단 지연 실측값을 가진 상태.

#### 블록 4 · 160~180분 — 정리와 과제

1. (7분) **필수 고장 진단 목록**을 정리한다.

   | 진단 항목 | 무엇을 잡는가 |
   |---|---|
   | Hall 000/111, 불법 순서 | 센서 단선·단락, 노이즈 |
   | PWM 중 Hall timeout | stall 또는 센서 소실 |
   | 명령 방향 ≠ 측정 방향 | 배선·테이블 오류 |
   | 과전류·과열·저전압·과전압 | 전력단 이상 |
   | ISR 값 ≠ main 값 | 공유 데이터 일관성 |
   | **제어 주기 초과(overrun)** | 정류와 속도제어가 함께 어긋남 |
   | 상위 명령 timeout | 통신 두절 → 자율 감속·정지 |

   > 🗣️ "10주차에 잰 1ms 태스크 실행 시간 기억하시죠. **그게 overrun 판정의 기준선**입니다."

2. (5분) **형성평가 4문항**

   1. 4 pole-pair 모터에서 Hall edge가 초당 240회라면 기계 RPM은?
   2. Hall 신호가 멈췄는데 이전 RPM 값이 유지되면 어떤 위험이 있는가?
   3. FAULT 원인이 사라진 즉시 자동 재구동하지 않는 이유를 설명한다.
   4. 한쪽 모터만 fault로 정지시키면 안 되는 이유를 로버 거동으로 설명한다.

3. (5분) **과제 안내**

   > 11주차 과제 — 통합 펌웨어 구조도와 안전 차단 경로

### 3. 자주 나오는 질문과 답

| 학생 질문 | 답 |
|---|---|
| "모터가 진동만 하고 안 돌아요" | 정류 순서가 뒤섞인 것이다. **워크시트 L의 실측 순서**와 표를 대조한다 |
| "데이터시트 표를 그대로 썼는데 왜 틀리죠?" | **배선 순서에 따라 테이블이 달라진다.** 5주차에 직접 잰 값이 정답이다 |
| "RPM이 이상하게 2배로 나와요" | pole과 **pole pair**를 혼동했을 가능성이 가장 크다 |
| "홀 커넥터를 뽑아도 RPM이 그대로예요" | **그게 결함이다.** edge timeout이 없으면 마지막 값이 유지된다. 위험한 상태다 |
| "fault가 나면 그 채널만 끄면 되지 않나요?" | 한쪽만 멈추면 **로버가 제자리에서 돈다.** 양쪽을 함께 정지시킨다 |
| "`volatile`을 붙였는데도 값이 섞여요" | `volatile`은 최적화만 막는다. **여러 변수를 한 세트로 읽는 일관성**은 따로 보장해야 한다 |

### 5. 안전 점검

**펌웨어로 모터를 돌리는 첫 주차다.** 정류 표가 틀리면 관통 전류가 흐른다.

- 🔴 **저전압(12V 이하)·전류 제한·저 duty**에서 시작한다. 표가 검증되기 전에 전압을 올리지 않는다
- 🔴 **모터 축을 고정하거나 바퀴를 공중에 띄운다**
- 🔴 정류 표를 처음 적용할 때는 **duty를 10% 이하**로 두고 파형부터 확인한다
- 팀마다 **비상 차단 담당 1명**을 지정하고 전원 스위치 옆에 서게 한다
- 이상한 소리·진동·발열이 있으면 **즉시 전원을 내린다.** 원인을 찾은 뒤 다시 켠다
- 고장 주입은 **신호 주입으로만** 한다. 하드 단락을 만들지 않는다
- 로직 애널라이저 GND를 먼저 연결하고, **고측 게이트는 프로브를 대지 않는다**(6주차 규칙 유지)
- 연속 운전 후 MOSFET·모터는 뜨겁다. 손으로 확인하지 않는다
