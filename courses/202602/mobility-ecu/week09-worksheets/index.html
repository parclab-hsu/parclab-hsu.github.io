    9주차 배포용 워크시트¶

    진행 대본과 준비 체크리스트는 9주차 운영 키트에 있다.

    워크시트 인쇄 부수 사용 시점
    S. 레지스터 해석과 클럭 검산 수강생 수 50~130분
    T. 3종 비교와 디버깅 기록 팀 수 + 2 130~155분

    ⚠️ 워크시트 S의 클럭 검산표는 10주차 Timer·UART 계산의 입력이 된다.

    핀 번호 n
    MODER에서 이 핀이 쓰는 비트 비트 ___ ~ ___ n × 2
    출력 모드로 만들 값 (2비트)

    RCC->_________ |= ______________;   /* 왜 필요한가:                         */

GPIOx->ODR   ^=  (1U << ___);            /* 토글 */

    2. BSRR로 바꿔 쓰기¶

    GPIOx->BSRR = (1U << ___);          /* set   (LED ON)  */

GPIOx->BSRR = (1U << (___ + 16));   /* reset (LED OFF) */

    ODR ^= mask는 몇 번의 동작으로 이루어지는가
    그 사이에 인터럽트가 들어오면 무슨 일이 생기는가

    0x00003000을 2진수로 펴면

    그러면 몇 번 핀인가 PC___
    0x00001000이 넣는 2비트 값은
    그 값의 의미는
    결론: 이 두 줄이 하는 일

    AHB (HCLK) /___ MHz RCC->CFGR HPRE
    APB1 (PCLK1) /___ MHz RCC->CFGR PPRE1
    APB2 (PCLK2) /___ MHz RCC->CFGR PPRE2

    1. CubeMX · HAL · 레지스터 3종 비교¶

    같은 LED 동작을 세 방법으로 만들고, 디버거 register view로 최종 값을 확인한다.

    방법 작성한 코드(요약) 확인한 레지스터와 값 동작
    ① CubeMX 생성 MX_GPIO_Init() MODER=
    ② HAL 함수 HAL_GPIO_WritePin() ODR/BSRR=
    ③ 직접 레지스터 MODER= , BSRR=
    질문 우리 팀의 답
    세 방법의 최종 레지스터 값이 같은가 예 / 아니오
    다르다면 어디가 어떻게 다른가
    HAL_GPIO_WritePin()은 내부에서 무엇을 쓰는가

    2. 디버깅 기록 — 안 될 때 순서대로 확인한다¶

    코드를 다시 읽지 말고 register view를 연다. 코드는 의도이고, 레지스터는 실제로 일어난 일이다.

    단계 확인 항목 기대값 실제값 판정
    1 주변장치 clock enable 비트
    2 GPIO mode / AF / pull / output type
    3 ODR·IDR vs 실제 핀 전압(멀티미터)
    4 타이머 CNT 증가, status flag
    5 reserved bit 보존 여부

    막혔던 문제와 해결 과정 (해결하지 못했으면 "확인 필요"라고 적고 무엇을 더 봐야 하는지 쓴다)

    증상 의심한 원인 확인 방법 실제 원인 해결
