    9주차 운영 키트 — STM32 펌웨어 1: 레지스터·GPIO·클럭¶

    교안 정보¶

    항목 내용
    교과목 모빌리티 전자제어유닛 실습 (3학점 · 전공)
    대상 미래모빌리티학과 3~4학년
    차시 9주차 / 15주차 · 180분
    강의실 Physical AI 실습실
    관련 자료 상세 강의자료 09번 · 과제집 18번 · 배포용 워크시트 S·T
    실습 하드웨어 STM32F767 학습보드 (H723 레퍼런스 보드는 읽기용)

    학습목표¶

    이 시간이 끝났을 때 학생은 다음을 수행할 수 있다.

    1. STM32F767의 메모리맵과 주변장치 레지스터 개념을 이해한다.
    2. GPIO 출력과 입력을 레지스터 수준에서 제어한다.
    3. 시스템 클럭 설정이 타이머, UART, ADC에 영향을 주는 이유를 설명한다.

    핵심 질문¶

    • GPIOC->MODER와 같은 코드는 실제로 무엇을 쓰는 것인가?
    • 클럭 enable을 하지 않으면 주변장치는 왜 동작하지 않는가?
    • HAL 없이 레지스터를 직접 제어하는 장단점은 무엇인가?

    지도 중점¶

    8주차까지가 "무엇을 만들 것인지 정하는 일"이었다면, 9주차부터는 "정한 것을 코드로 옮기는 일" 이다. 이 주차의 목표는 레지스터 이름 암기가 아니라 추상화 아래의 하드웨어 상태를 읽는 능력이다.

    🧪 실습 기준은 STM32F767 학습보드다. 코드·측정·과제는 모두 F767 기준이며, 레퍼런스 보드의 H723은 회로를 읽는 대상이다. 9~11주차 내내 이 구분을 유지한다.

    📌 8주차에 확정한 HSI의 핀 배정이 오늘 그대로 레지스터 설정이 된다. HSI가 틀리면 코드도 틀린다는 것을 도입부에서 연결한다.

    0. 전날 체크리스트¶

    인쇄물

    인쇄물 분량 용도
    워크시트 S — 레지스터 해석과 클럭 검산 1장 / 인 활동 1·2·3
    워크시트 T — 3종 비교와 디버깅 기록 1장 / 팀 추가 실습
    9주차 배포용 워크시트에 두 양식 모두 있다

    실습 준비

    • STM32F767 학습보드 (팀당 1대 이상) + ST-LINK 또는 내장 디버거
    • 노트북 — STM32CubeIDE 설치 확인. 설치가 안 된 학생이 있으면 첫 30분이 통째로 날아간다
    • USB 케이블(데이터 전송용인지 확인 — 충전 전용 케이블 주의)
    • 브레드보드용 스위치와 점퍼선 (입력 실습용)
    • 멀티미터 (핀 전압 확인용)

    ⚠️ 전날 반드시 확인 — CubeIDE 설치, 보드 드라이버 인식, 예제 프로젝트 빌드가 되는지 교수 노트북에서 한 번 돌려 본다.

    미리 열어 둘 자료

    1. STM32F767 Reference Manual — GPIO와 RCC 레지스터 절 (프로젝터용)
    2. 주차별 용어 정리 9주차
    3. 실습 코드 페이지
    4. 과제집 「9주차 과제」의 주석 예시와 클럭 검산표

    8주차 수정본 회수

    • Critical 결함을 받은 팀의 조치 여부를 별도로 확인한다. 기한이 지났는데 안 고쳤으면 그 자리에서 지적한다
    • 회수한 HSI 표는 오늘 핀 배정의 근거이므로 팀이 계속 가지고 있게 한다

    1. 180분 진행 대본¶

    블록 1 · 0~50분 — 메모리맵과 클럭¶

    목표 — "레지스터에 값을 쓴다"가 물리적으로 무슨 뜻인지 납득시킨다.

    1. (5분) 8주차 피드백. Critical 결함 조치 상황을 확인한다.

    🗣️ "지난주에 확정한 HSI의 핀 번호가 오늘 코드의 비트 위치가 됩니다."

    1. (12분) 메모리맵과 레지스터.

    ✍️ 판서: 주소 0x40020800 = GPIOC — 이 주소에 값을 쓰면 핀이 켜진다

    🗣️ "변수에 값을 쓰면 메모리가 바뀝니다. 그런데 어떤 주소는 메모리가 아니라 하드웨어에 연결돼 있습니다. 그 주소에 쓰면 전압이 바뀌죠. 그게 레지스터입니다."

    GPIOC->MODER가 구조체 포인터를 통한 특정 주소 접근임을 코드로 보여 준다.

    1. (13분) GPIO 레지스터 7종. MODER OTYPER OSPEEDR PUPDR IDR ODR BSRR.

    레퍼런스 매뉴얼을 프로젝터로 열어 비트 필드 표를 직접 읽게 한다.

    🗣️ "핀 하나에 MODER 비트가 두 개 배정돼 있습니다. 그래서 6 * 2로 자리를 찾는 겁니다."

    1. (20분) RCC와 클럭 트리.

    ✍️ 판서 

    HSE 16MHz → PLLM/PLLN/PLLP → SYSCLK 216MHz → AHB 216MHz → APB1/APB2 54MHz

    가장 흔한 함정을 먼저 말한다.

    🗣️ "코드를 다 맞게 썼는데 핀이 안 움직입니다. 십중팔구 클럭 enable을 안 한 것입니다. 클럭이 없으면 그 주변장치는 아예 존재하지 않는 것과 같습니다."

    잘못 설정하면 증상
    Flash wait state 고속 동작 불안정 또는 fault
    APB 분주 UART baud, timer 주기 오차
    GPIO speed 불필요한 edge/EMI 또는 느린 전환
    pull-up/down 입력 부동, 가짜 인터럽트
    alternate function PWM/UART 핀 무출력

    ✅ 이 블록이 끝났을 때 — 학생이 "클럭 enable → 모드 설정 → 값 쓰기" 순서를 말할 수 있는 상태.

    블록 2 · 50~110분 — GPIO 코드 실습 (활동 1·2)¶

    목표 — 데이터시트를 보고 자기 손으로 비트를 계산하게 한다.

    1. (25분) 활동 1 — LED 출력 (워크시트 S 상단)

    PC6 Fault LED를 예로 판서한다.

    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOCEN;   /* 클럭 없으면 쓰기가 무시된다 */
GPIOC->MODER &= ~(3U << (6 * 2));      /* 두 비트를 먼저 지운다 */
GPIOC->MODER |=  (1U << (6 * 2));      /* 01 = general purpose output */
GPIOC->ODR   ^=  (1U << 6);            /* 토글 */

    ⚠️ &= ~(3U << ...)로 먼저 지우는 이유를 반드시 묻는다. 바로 |= 만 하면 이전 값이 남아 11(아날로그)이 될 수 있다. 예약 비트 보존 습관이다.

    그다음 BSRR로 바꿔 쓰게 한다.

    GPIOC->BSRR = (1U << 6);          /* PC6 set   */
GPIOC->BSRR = (1U << (6 + 16));   /* PC6 reset */

    🗣️ "ODR ^= mask는 읽고→고치고→씁니다. 그 사이에 인터럽트가 같은 포트를 건드리면 갱신이 사라집니다. BSRR은 한 번의 쓰기로 끝나서 그 틈이 없습니다."

    1. (20분) 활동 2 — 레지스터 비트 해석 (워크시트 S 중단)

    다음 두 줄이 무엇을 하는지 말로 설명하게 한다.

    GPIOC->MODER &= ~0x00003000;
GPIOC->MODER |=  0x00001000;

    답: 0x3000은 비트 12~13 → 핀 6. 두 비트를 지우고 01을 넣으므로 PC6를 출력 모드로 설정.

    🗣️ "16진수를 2진수로 펴 보세요. 어느 비트가 서 있는지 보이면 몇 번 핀인지 나옵니다."

    1. (15분) 스위치 입력. IDR 읽기, PUPDR로 풀업/풀다운 설정.

    ⚠️ 풀업/풀다운을 설정하지 않으면 입력이 부동(floating) 상태가 되어 값이 제멋대로 읽힌다. 멀티미터로 핀 전압을 직접 재게 한다.

    블록 3 · 110~155분 — 클럭 추적과 3종 비교 (활동 3·추가 실습)¶

    목표 — CubeMX 화면값과 레지스터를 대조하게 한다.

    1. (20분) 활동 3 — 클럭 설정 추적 (워크시트 S 하단)

    제공 코드의 Initialize_MCU()에서 다섯 가지를 찾게 한다 — I/D-cache enable, Flash wait state, PLL 설정, APB1/APB2 clock, 주변장치 clock enable.

    그다음 CubeMX Clock Configuration에 값을 넣고 손 계산과 대조시킨다.

    CubeMX 표시값          직접 확인할 레지스터
SYSCLK 216MHz     →  RCC->PLLCFGR (PLLM/PLLN/PLLP), RCC->CFGR SW
APB1 54MHz        →  RCC->CFGR PPRE1
TIM 클럭 216MHz   →  RCC->DCKCFGR1 TIMPRE
Flash latency     →  FLASH->ACR LATENCY

    🗣️ "APB1이 54MHz인데 타이머 클럭은 216MHz로 표시됩니다. 왜 4배입니까? 이걸 모르면 다음 주 PWM 주기가 4배 틀립니다."

    답: APB 분주비가 1이 아니면 타이머 클럭이 PCLK보다 높다. F7에서는 RCC->DCKCFGR1의 TIMPRE 비트가 배수를 정한다.

    1. (25분) 추가 실습 — CubeMX·HAL·레지스터 3종 비교 (워크시트 T)

    같은 LED 동작을 세 방법으로 만들고 최종 레지스터 값을 register view로 확인하게 한다.

    방법 확인할 것
    CubeMX 생성 코드 MX_GPIO_Init()이 실제로 건드리는 레지스터
    HAL 함수 HAL_GPIO_WritePin() 내부가 무엇을 쓰는가
    직접 레지스터 위 둘과 최종 값이 같은가

    🗣️ "목적은 CubeMX나 HAL을 쓰지 말자는 게 아닙니다. 그 아래에서 무슨 일이 일어나는지 읽을 수 있게 하려는 겁니다. 읽을 수 있으면 고칠 수 있습니다."

    ⚠️ CubeMX로 코드를 재생성하면 /* USER CODE BEGIN */~/* USER CODE END */ 사이만 보존된다. 그 밖에 직접 쓴 레지스터 코드는 사라진다.

    2. 판서 목록¶

    1. 주소 0x40020800 = GPIOC — 주소에 쓰면 전압이 바뀐다
    2. GPIO 레지스터 7종과 핀당 비트 폭 (MODER는 2비트)
    3. RCC_AHB1ENR → MODER → OTYPER/OSPEEDR/PUPDR → ODR/BSRR 순서
    4. BSRR set/reset 두 줄
    5. HSE 16MHz → PLL → SYSCLK 216 → AHB 216 → APB 54
    6. CubeMX 표시값 ↔ 레지스터 4행 대응표
    7. 레지스터 디버깅 5단계

    3. 자주 나오는 질문과 답¶

    학생 질문 답
    "코드는 맞는데 LED가 안 켜져요" 십중팔구 클럭 enable이다. RCC->AHB1ENR부터 register view로 확인한다
    "왜 &= ~(3U << n)을 먼저 하나요?" 그냥 |=만 하면 이전 값이 남는다. 01을 쓰려 했는데 11이 되어 아날로그 모드가 될 수 있다
    "ODR 쓰면 되는데 왜 BSRR인가요?" ODR은 읽고→고치고→쓰기라 인터럽트가 끼면 갱신이 유실된다. BSRR은 한 번의 쓰기로 끝난다
    "volatile을 붙였는데도 값이 이상해요" volatile은 최적화만 막는다. 원자성이나 상호배제는 보장하지 않는다
    "그냥 HAL 쓰면 안 되나요?" 써도 된다. 다만 안 될 때 원인을 찾으려면 아래를 읽을 수 있어야 한다. 그래서 지금 배운다
    "CubeMX로 만든 코드가 사라졌어요" 재생성하면 USER CODE 구간 밖은 덮어쓴다. 직접 쓴 코드는 그 안에 넣는다

    4. 시간이 남거나 모자랄 때¶

    상황 대응
    15분 이상 남음 스위치 입력에 인터럽트를 붙여 다음 주 EXTI를 미리 맛보게 한다
    10분 남음 레퍼런스 매뉴얼에서 OSPEEDR 설정이 EMI에 미치는 영향을 짚는다(14주차 예고)
    15분 부족 3종 비교(추가 실습)를 CubeMX와 레지스터 2종으로 줄인다
    30분 이상 부족 3종 비교를 과제로 넘긴다. 활동 1·2(레지스터 직접 제어)는 반드시 그 자리에서 — 과제 배점 2점이 여기에 걸려 있다

    5. 안전 점검¶

    이 주차는 저전압 로직 실습이라 전기적 위험은 낮다. 대신 장비 손상을 막는다.

    • 보드에 전원이 들어간 상태로 점퍼선을 옮기지 않는다
    • 출력으로 설정한 핀끼리 직접 연결하지 않는다. 두 출력이 반대 값이면 단락이다
    • 5V 신호를 3.3V 핀에 넣지 않는다. 5V tolerant 여부를 데이터시트에서 확인한다
    • USB 케이블을 뺄 때는 디버거 세션을 먼저 종료한다
    • 정전기(ESD) — 보드의 핀 헤더를 맨손으로 오래 만지지 않는다

    6. 종료 후 점검¶

    • 8주차 수정본 미제출 팀을 기록했는가

    • 학습보드와 케이블을 회수했는가
    • 다음 주 준비물(같은 보드 지참, Teleplot 준비)을 공지했는가
