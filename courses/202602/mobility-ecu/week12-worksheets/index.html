    12주차 배포용 워크시트¶

    진행 대본과 준비 체크리스트는 12주차 운영 키트에 있다.

    워크시트 인쇄 부수 사용 시점
    Y. HSI 핀 리뷰와 게이트드라이버 검토 수강생 수 50~105분
    Z. 회로 리뷰 체크리스트와 fault chain 팀 수 + 2 105~160분

    ⚠️ 워크시트 Z의 NG 항목과 조치 계획은 15주차에 조치 여부를 확인한다. 반드시 회수한다.

    워크시트 Y · HSI 핀 리뷰와 게이트드라이버 검토¶

    모빌리티 전자제어유닛 실습 · 12주차    팀명 __ 이름 ____

    1. HSI 핀 리뷰 — 한 신호를 세 곳에서 추적한다¶

    8주차에 제출한 HSI 표를 옆에 놓고, 회로도와 한 줄씩 대조한다.

    신호 핀 방향 회로 블록 펌웨어 심볼 검증 방법 회로도와 일치?

    상보 출력 쌍 확인 — 뒤바뀌면 상하가 반대로 켜진다.

    TIM1 채널 MCU 핀 드라이버 입력 일치?
    CH1 (U 상단) HIN
    CH1N (U 하단) LIN
    CH2 / CH2N
    CH3 / CH3N

    불일치를 발견했다면

    신호 HSI 표 회로도 어느 쪽이 맞는가 무엇을 고쳐야 하는가

    ⚠️ 핀 하나를 바꾸면 회로도 net · .ioc · HSI 표 · 시험 포인트가 함께 바뀐다.

    2. 게이트드라이버 구동 능력 계산¶

    항목 값 출처
    MOSFET Qg nC
    목표 스위칭 시간 tswitch ns
    스위칭 주파수 fsw kHz
    게이트 구동 전압 Vgate V
    스위치 개수 개 
    Igate,peak ≈ Qg / tswitch  =            /            =            A

Igate,avg  = Qg × fsw × 스위치 개수  =                             =            mA

Pgate      = Qg × Vgate × fsw        =                             =            mW
    질문 우리 팀의 답
    MCU 핀이 낼 수 있는 전류는 대략 mA
    필요한 피크 전류는 그보다 몇 배인가 배
    선택한 드라이버의 피크 출력 전류 정격 A
    여유가 있는가 예 / 아니오

    3. 부트스트랩 검토¶

    Cboot ≥ Qtotal / ΔVboot
    항목 값 근거
    Qg (게이트 전하만) nC
    드라이버 소비·누설 추정 nC
    여유 배수 배
    Qtotal nC
    허용 전압 강하 ΔVboot V
    계산한 Cboot 최소값 µF
    실제 선택한 값 µF
    질문 답
    Qg만으로 정하면 왜 부족한가
    부트스트랩 다이오드에서 확인할 항목 2가지
    duty 100%를 유지할 수 없는 이유

    4. 게이트드라이버 회로 리뷰 (레퍼런스 보드 시트 3)¶

    리뷰 항목 회로도에서 찾은 것 판정
    게이트 저항이 드라이버 출력과 게이트 사이에 있는가 OK / NG
    부트스트랩 다이오드 역전압 정격 OK / NG
    high-side supply는 어디서 오는가 OK / NG
    low-side return이 파워 GND와 만나는 지점 OK / NG
    PWM 입력이 3.3V 로직을 받는가 OK / NG
    fault 출력이 어디로 가는가 OK / NG

    ⚠️ fault 출력이 아무 데도 연결되지 않았다면 NG다. 드라이버가 이상을 알려도 받는 곳이 없다.

    5. 전류 센싱과 보호 연결¶

    항목 값
    션트 저항 Rshunt mΩ
    최대 상전류 Irms A
    Vshunt = I × Rshunt (최대) mV
    손실 P = Irms² × Rshunt W
    션트 정격 전력 W
    여유율 배
    질문 우리 팀의 답
    션트를 크게 하면 정확도와 손실은 각각 어떻게 되는가
    Kelvin 센싱을 안 하면 무엇이 측정값에 섞이는가
    과전류 임계값을 두 경로로 나누는 이유

    2. stuck-at 검토 — 경로가 고장 나면?¶

    고장 지점 어떻게 고착되면 최종 출력은 안전한가 어떻게 검출할 것인가
    션트 배선 단선
    증폭기 출력 고착
    비교기 출력 Low 고착
    MCU fault 입력 단선
    드라이버 enable 배선 단선

    ⚠️ 비교기 출력이 Low에 고착되면 하드웨어 차단이 영원히 동작하지 않는데 평소에는 아무 증상이 없다. 15주차에 신호 주입으로 경로를 시험한다.

    시험 계획 — 15주차에 이 경로를 어떻게 확인할 것인가

    3. 회로 리뷰 체크리스트 10항목¶

    # 체크 항목 판정 근거·검증 방법 NG면 조치·리비전
    1 OK / NG
    2 OK / NG
    3 OK / NG
    4 OK / NG
    5 OK / NG
    6 OK / NG
    7 OK / NG
    8 OK / NG
    9 OK / NG
    10 OK / NG

    반드시 포함해야 할 Critical 2항목 (8주차에 지적받은 것)

    항목 판정 조치 기한
    MCU 미전원·리셋 중 게이트 입력이 off로 고정되는가 OK / NG
    하드웨어 과전류 차단 경로가 존재하는가 OK / NG

    4. 하드웨어 기본 안전 상태 4원칙 점검¶

    원칙 우리 설계는 확인 방법
    MCU reset·미전원 시 게이트 off
    드라이버 UVLO/fault가 PWM 허용 조건에 포함
    enable 1개로 전 상 차단
    하드웨어 과전류가 펌웨어와 무관하게 동작

    5. 워치독 설계¶

    항목 우리 팀의 설계 근거
    사용할 워치독 (IWDG / WWDG)
    refresh를 어디서 하는가
    timeout 값 ms
    제어 주기 ms
    기계적으로 위험해지는 시간 ms
    리셋 원인을 어떻게 기록하는가
    리셋 후 PWM 초기 상태
    재시작 조건
    질문 답
    ISR에서 무조건 refresh하면 왜 안 되는가
    timeout을 제어 주기보다 길게, 위험 시간보다 짧게 잡는 이유

    6. bring-up 절차 — 우리 보드를 처음 켤 때¶

    각 단계의 통과 기준을 직접 적는다.

    단계 무엇을 하는가 통과 기준 실패하면
    1 무전원 단락·극성 확인
    2 보조전원 전류 제한 확인
    3 드라이버 enable off·fault 확인
    4 저전압에서 PWM 입력·게이트 출력
    5 모터 없이 스위칭 노드·dead time
    6 저전압·저duty·무부하 모터

    확정할 수 없으면 "확인 필요" 라고 적고 무엇을 더 봐야 하는지 쓴다.
