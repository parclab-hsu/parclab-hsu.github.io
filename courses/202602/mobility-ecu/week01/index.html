    1주차 · 오리엔테이션 및 로버 제어유닛 구조¶

    🔗 강의 흐름 — 1주차는 전체 지도를 본다. 다음 주부터 이 시스템을 이루는 부품 하나하나를 밑바닥부터 쌓는다.

    학습목표 — 로버(2륜 차동구동 베이스)·우주 로버 대회의 전기전자제어유닛(ECU) 전체 구조와 신호 흐름을 설명하고, 실습 키트 구성과 안전 수칙을 숙지한다.

    💡 기초 다지기 (쉽게 이해하기) — 제어유닛(ECU)이란? 로봇의 "두뇌+신경"이다. 사람/센서가 준 정보를 MCU가 판단해 모터를 움직이는 전자 시스템으로, 이 과정은 그 시스템을 밑바닥부터 직접 만드는 것이다.

    저작권 유의 — 원본 자료 사용 범위 확인

    이 주차의 원본 첨부 PDF 링크·슬라이드 미리보기 이미지(chcbaram 원본 자료)는 수업 활용 범위와 외부 배포 가능 여부를 확인해 사용한다. 공개 배포 전에는 인용 허가, 출처 표기, 자작 대체 자료 여부를 점검한다.

    🗺️ 한눈에 보는 개념도¶

    🔎 로버 전장 시스템 구성¶

    • 전원부: 배터리(예: 2S~) → 벅·LDO로 12V/5V/3.3V 생성
    • 구동부: 모터 드라이버(H-브리지) 또는 3상 인버터 → 좌/우 휠 모터(2륜 차동구동)
    • 제어부: STM32 — 명령→PWM 듀티, 속도·전류 제어, 보호
    • 센서부: 엔코더/홀(속도), 션트(전류), 초음파/IMU(주행), 배터리 전압(ADC)

    🚗 2륜 차동구동 기하¶

    좌·우 휠 속도차로 회전. 같으면 직진, 반대면 제자리 회전.

    🔁 신호 흐름¶

    원격 명령/센서 → MCU 듀티 계산 → 드라이버 → 휠 모터 이며, 엔코더·션트·IMU 피드백이 MCU로 되돌아온다.

    🔗 여기서부터 확장 자료 — 흐름 이어보기

    아래는 위 핵심 개념(개념도·공식·그림)을 더 깊이 파는 심화·실습·평가·사례 자료다. 처음 보는 학생은 페이지 맨 위 「💡 기초 다지기」로 큰 그림을 먼저 잡고, 심화 → 실습 → 평가 → 사례 순으로 읽으면 이번 주 흐름이 자연스럽게 이어진다.

    🧠 핵심 이론 보강¶

    이미지로 설명하기

    첫 화면에서는 첨부자료 이미지를 보여 주고, 바로 아래 도해로 원리를 단순화한다. 학생에게 “사진 속 실제 부품/단자”와 “도해 속 기능 블록”을 서로 연결하게 하면 추상 개념이 실습 대상으로 바뀐다.

    1. 이번 주 이론을 어디에 쓰는가¶

    • ECU는 MCU 하나가 아니라 전원부, 센서 입력, 구동 출력, 통신, 보호 로직이 합쳐진 시스템이다.
    • 전력 흐름은 배터리에서 모터로 향하고, 정보 흐름은 센서와 명령에서 MCU를 거쳐 PWM으로 향한다.
    • 차동구동은 조향 장치 없이 좌우 휠 속도 차이만으로 직진, 회전, 제자리 회전을 만든다.

    2. 강의 중 반드시 남길 판서¶

    판서 항목 설명 실습 연결
    핵심 관계식 v=(vR+vL)/2, omega=(vR-vL)/L 계산값을 먼저 예측하고 측정값으로 검증한다.
    입력 조건 전압, 전류, 주파수, RPM, 핀 상태 중 이번 주 주제에 해당하는 값을 정한다. 조건이 빠지면 결과 비교가 불가능하다는 점을 강조한다.
    정상/비정상 판단 정상 범위와 즉시 정지해야 할 조건을 분리한다. 최종 프로젝트의 안전 상태와 로그 항목으로 이어진다.

    3. 학생 눈높이 설명 순서¶

    1. 현상 관찰: 첨부 이미지에서 실제 부품, 커넥터, 파형, 코드 위치를 먼저 찾는다.
    2. 모델 단순화: 핵심 도해와 공식으로 “왜 그런 값이 나오는지”를 설명한다.
    3. 설계 판단: 부품값, 듀티, 샘플링 주기, 보호 기준처럼 학생이 직접 정해야 하는 값을 고른다.
    4. 검증 증거: 사진, 계산표, 오실로스코프 캡처, UART 로그 중 하나 이상으로 결과를 남긴다.

    학생들이 자주 헷갈리는 지점

    이번 주제는 암기보다 조건 확인이 중요하다. 회로·펌웨어·제어 문제는 같은 증상으로 보일 수 있으므로, 전원 조건 → 신호 조건 → 코드 조건 순서로 좁혀 가게 한다.

    최신 기술 연결

    SDV와 존 아키텍처에서는 여러 ECU가 차량 네트워크의 기능 노드가 되므로, 작은 로버 보드도 전원·제어·진단을 분리해 보는 훈련이 중요하다. SDV, Adaptive AUTOSAR, 엣지 AI MCU, 차량 사이버보안, ISO 26262 기능안전은 서로 다른 주제처럼 보이지만 모두 '측정 가능한 요구사항과 검증 가능한 로그'를 요구한다.

    4. 실습 전환 포인트¶

    전원 인가 전 전압, 극성, 바퀴 고정, 공통 GND를 확인하고 사진으로 증거를 남긴다. 이 활동은 확장 강의자료의 심화노트, 실습 코칭노트, 평가팩, 사례노트와 이어지며, 한 주차 안에서 “이론 설명 → 손으로 확인 → 평가 → 현장 사례”가 끊기지 않도록 구성한다.

    📦 용어 박스¶

    📚 이번 주 용어의 자세한 설명과 그림은 주차별 용어 정리 — 1주차 에 있다.

    이번 주 꼭 설명할 용어

    • ECU: 센서 입력을 읽고 MCU 판단으로 액추에이터를 제어하는 전자제어유닛.
    • MCU: CPU, 메모리, GPIO, ADC, Timer, UART가 한 칩에 들어간 제어용 컴퓨터.
    • 로버: Autonomous Mobile Robot. 이 강의에서는 2륜 구동 이동로봇 플랫폼을 의미한다.
    • HSI: 핀, 신호 방향, 전기적 조건을 정리한 HW-SW 계약서.
    • 차동구동: 좌우 바퀴 속도 차이로 직진과 회전을 만드는 구동 방식.

    • 성능 요구사항: 어느 수준까지 해야 하는가. 예: 정상상태 속도 오차를 ±5% 이내로 유지한다.
    • 안전 요구사항: 고장 때 허용할 상태는 무엇인가. 예: Hall 신호가 100ms 이상 갱신되지 않으면 PWM을 차단한다.

    요구사항 한 문장에는 주어, 조건, 행동, 수치, 단위를 넣고 시험 방법을 함께 정한다. “잘 동작한다”처럼 시험자가 PASS/FAIL을 결정할 수 없는 문장은 요구사항으로 사용하지 않는다.

    V-모델과 검증 증거¶

    미션 요구사항 ─ 시스템 설계 ─ 상세 설계 ─ 구현
      │              │            │          │
  인수 시험      통합 시험     모듈 시험   단위 확인

    설계 단계마다 대응 시험을 미리 연결한다. 멀티미터 값, 오실로스코프 파형, UART 로그, 주행 거리처럼 재현 가능한 증거를 요구사항 ID와 함께 보관한다.

    요구사항을 검증 문장으로 바꾸기¶

    팀에서 쓴 요구사항을 아래 표로 옮긴다. 검증 방법 칸을 채우지 못하는 요구사항은 아직 요구사항이 아니라 희망이다. 이 표는 뒤쪽 설계 리뷰의 추적표와 최종 인수시험 표의 첫 행이 된다.

    ID 요구사항 문장 구분 측정량과 판정 기준 검증 방법 검증 주차
    R-01 스로틀 입력에 비례해 좌우 바퀴 속도를 제어한다 기능 명령 대비 정상상태 오차 ±5% 이내 Teleplot 속도 응답 기록 7
    R-02 Hall 신호가 100ms 이상 갱신되지 않으면 PWM을 차단한다 안전 차단까지 지연 ≤ 120ms Hall 배선 분리 시험 15
    R-03
    • 한 문장에 동작 하나만 쓰고, 주어·조건·행동·수치·단위를 모두 넣는다.
    • “빠르게”, “안정적으로”, “충분히”는 수치로 바꾸거나 지운다.
    • 안전 요구사항은 정상 동작이 아니라 고장 났을 때 무엇이 되어야 하는가를 쓴다.
    • 검증 주차를 적어 두면 그 주차 실습이 왜 필요한지 학생이 스스로 연결한다.

    🔧 OT 소개: 15주 뒤에 읽어낼 실물¶

    담당 교수가 직접 설계한 2축 BLDC 드라이버 FM_SmartDriver V1 이 본 강의의 레퍼런스 보드다. 오늘 배우는 요구사항부터 15주차 통합 검증까지, 모든 주차가 이 한 장의 어딘가를 설명한다.

    항목 값
    용도 좌/우 2축 BLDC 구동 제어유닛 (로버 차동 구동)
    MCU STM32H723ZGT6 (LQFP-144)
    층수 · 크기 6층 · 약 220 × 220 mm
    부품 146종 546개, 실장 558점 전량 Top면
    전력단 100V MOSFET 12개 = 2축 × 3상 × (하이/로우)

    상단 절반이 Motor-1, 하단 절반이 Motor-2다. 같은 3상 인버터를 두 벌 놓은 좌우 대칭 구조가 곧 로버의 좌우 바퀴다. 5주차의 차동 구동 운동학, 7주차의 좌우 2채널 PI, 11주차의 채널별 정류 상태기계가 모두 이 대칭에서 나온다.

    회로도 9시트·BOM·CPL·6층 레이어 이미지는 레퍼런스 보드 페이지에서 모두 내려받을 수 있다.

    🎓 OT 소개: 스탠퍼드는 "제품 개발"을 어떻게 가르치는가¶

    세계 최고 수준의 공대도 "제품을 만든다"를 정규 과목으로 가르친다. 그 방식이 본 강의의 15주 구조와 상당 부분 같다.

    과목 무엇을 훈련시키는가 운영 방식
    ME218 A·B·C — Smart Product Design "스마트 제품 = 마이크로프로세서로 기능이 확장된 제품". 트랜지스터 스위칭, 상태기계, C 레지스터 프로그래밍, 타이머·PWM·인터럽트, OP앰프, 센서/액추에이터 인터페이싱, 노이즈, 전원 3개 분기 연속 수강. 매 분기 공통 주제로 팀별 경진
    ME103 / ME203 — Design and Manufacturing 의미 있는 제품을 골라 관점을 세우고 직접 만든다. 래피드 프로토타입·CAD·제조 시험 모델, 양산 관점 재설계 Product Realization Lab에서 제작, 공개 발표 "Meet the Makers"
    ME310 A·B·C — Design Innovation 기업이 낸 실제 과제를 국제 협업으로 푼다 9개월. 스탠퍼드 팀 3~4명 + 해외 파트너 대학 팀, 기업 후원. 6월 쇼케이스 "EXPE"
