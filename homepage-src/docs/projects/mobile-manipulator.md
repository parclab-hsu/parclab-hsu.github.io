# Mobile Manipulator (AMR + 매니퓰레이터)

:material-circle:{ style="color:#2e9e44" } **개발 중** · Autonomous Mobile Manipulator Platform

!!! abstract "프로젝트 한눈에 보기"
    자율주행 모바일 베이스(AMR) 위에 로봇 팔을 올려 **"이동 + 조작"을 하나의 작업으로
    수행**하는 플랫폼입니다. 고정형 매니퓰레이터가 작업 반경에 묶이는 한계를 넘어,
    작업 대상이 있는 곳으로 스스로 이동한 뒤 조작을 수행합니다.

    매니퓰레이터는 **FAIRINO FR16**(6축, 가반 16 kg, 리치 1034 mm)을 사용합니다.
    Jetson Orin NX 16GB 단일 보드 위에서 3D LiDAR-관성 오도메트리, 2D SLAM,
    자율주행, 팔 제어를 함께 구동하며, 기능별 컨테이너로 분리해 운용합니다.

> **현재 단계** — 소프트웨어 아키텍처 및 워크스페이스 구성 완료, 하드웨어 연동 진행 중.

---

## 왜 Mobile Manipulator 인가

제조·물류 현장에서 로봇 팔은 대개 고정되어 있고, 작업물이 컨베이어를 타고 로봇에게
옵니다. 다품종 소량 생산이나 비정형 작업 환경에서는 이 전제가 성립하지 않습니다.
작업 지점이 흩어져 있으면 로봇이 이동해야 합니다.

이때 생기는 문제는 단순히 "AMR과 로봇 팔을 합치는 것"이 아닙니다.

| 과제 | 내용 |
|---|---|
| **위치 정밀도의 전가** | 주행 정지 오차를 팔의 역기구학이 흡수해야 한다 |
| **동적 안정성** | 팔을 실어 무게중심이 높아져 급가감속·급회전 시 전도 위험 |
| **정적 전도 한계** | 리치 끝에서 가반하중을 드는 순간의 모멘트가 베이스 복원력을 넘을 수 있다 |
| **자원 경합** | SLAM·자율주행·팔 제어가 단일 보드의 CPU를 나눠 쓴다 |
| **센서 자기가림** | 360도 LiDAR 시야에 로봇 자신의 팔과 본체가 들어온다 |

## 시스템 구성

### 연산 플랫폼

| 항목 | 사양 |
|---|---|
| 연산 보드 | NVIDIA Jetson Orin NX 16GB |
| SDK | JetPack 7.2 |
| OS / 미들웨어 | Ubuntu 24.04 · ROS 2 Jazzy Jalisco |
| 배포 | 기능별 Docker 컨테이너 |

### 위치추정 파이프라인

3D LiDAR-관성 오도메트리와 2D SLAM을 **역할을 나눠** 함께 사용합니다.

``` mermaid
flowchart LR
    MID["Livox Mid-360<br/>3D LiDAR + IMU 200Hz"] --> LIO["FAST-LIO2<br/>LiDAR-관성 오도메트리"]
    WHEEL["휠 엔코더"] --> EKF
    LIO --> EKF["EKF 융합<br/>robot_localization"]
    LIO --> P2LS["2D 스캔 투영"]
    EKF --> TF["odom → base_footprint"]
    P2LS --> SLAM["slam_toolbox<br/>2D 지도 · 루프 클로저"]
    SLAM --> NAV["Nav2<br/>MPPI 로컬 플래너"]
    TF --> NAV
```

**FAST-LIO2**는 연속적인 상대 위치(오도메트리)를, **slam_toolbox**는 지도와 전역
보정(루프 클로저, 재위치추정)을 담당합니다. 역할이 다르므로 중복이 아닙니다.

**EKF 융합**을 끼운 이유는 두 센서의 실패 모드가 다르기 때문입니다. LiDAR 오도메트리는
특징이 부족한 공간(빈 복도, 유리벽)에서 흔들리고, 휠 오도메트리는 슬립에 취약합니다.
휠에서는 속도만, LiDAR에서는 위치와 방향을 받아 융합합니다.

### 매니퓰레이터 — FAIRINO FR16

| 항목 | 사양 |
|---|---|
| 자유도 | 6축 |
| 가반하중 | 16 kg (최대 20 kg) |
| 리치 | 1034 mm |
| 자중 | 40 kg |
| 반복정밀도 | ±0.03 mm |
| 보호등급 | IP54 / IP65 |

관절 가동범위가 축마다 다르고 **J2·J4는 +85°/−265°로 비대칭**입니다. 대칭으로
가정한 궤적은 실기 컨트롤러가 거부하므로, 팔 인터페이스 노드가 궤적을 수락하기
전에 사양표 범위를 검사합니다.

### 베이스 사이징 — 전도 안전율이 설계를 지배한다

FR16을 얹는 순간 베이스 설계 제약이 바뀝니다. 자중 40 kg에 리치 1034 mm이므로,
팔을 완전히 뻗어 16 kg을 드는 순간의 전도 모멘트가 소형 베이스의 복원 모멘트를
넘어섭니다.

기종 확정 전 가정했던 베이스(0.60 × 0.45 m, 40 kg)의 전도 안전율은 좌우 방향
**0.44** 였습니다 — 1 미만은 넘어진다는 뜻입니다. 이에 따라 베이스를 다시
설계했습니다.

| 항목 | 기종 확정 전 | FR16 반영 |
|---|---|---|
| 베이스 치수 | 0.60 × 0.45 m | 0.90 × 0.70 m |
| 베이스 질량 | 40 kg | 150 kg |
| 팔 장착 위치 | 후방 치우침 | 중심 |
| 최소 전도 안전율 | 0.44 | 3.89 |

팔을 베이스 중심에 두는 이유는 한쪽으로 치우치면 반대 방향으로 뻗을 때
안전율이 급락하기 때문입니다. 대신 LiDAR 마스트를 전방 모서리로 옮겨 팔의
작업영역과 간섭하지 않게 했습니다.

주행 속도와 가감속도 함께 낮췄습니다. 200 kg급에 무게중심이 높은 기계입니다.

### 자율주행

로컬 플래너로 **MPPI**(Model Predictive Path Integral)를 채택했습니다. 궤적 후보 중
최저비용 하나를 고르는 DWB와 달리, 샘플링한 궤적들의 비용 가중평균으로 제어를
만들기 때문에 좁은 통로나 U자 장애물에서 로컬 미니마에 갇힐 가능성이 낮습니다.

대신 크리틱 가중치가 많아 튜닝 표면이 넓고, 매 제어 주기마다 궤적 배치를 CPU에서
평가하므로 연산 부하가 큽니다. Orin NX에서 SLAM과 동시 구동을 고려해 배치 크기를
기본값보다 낮춰 시작하고, 동일 조건 A/B 비교가 가능하도록 DWB 설정을 함께
유지합니다.

### 주행-조작 협조 제어

주행과 조작을 **동시에 하지 않습니다.** 팔을 펼친 채 주행하면 무게중심 이동으로
전도 위험이 커지고, 관성으로 적재물이 이탈할 수 있습니다.

1. 목표 수신 → 팔을 스토우(접힘) 자세로 복귀
2. Nav2 자율주행
3. 정지 후 안정화 대기
4. 팔 동작 수행

주행 중에는 팔이 잠기며, 가감속 한계도 Nav2 기본값보다 보수적으로 설정합니다.

## 소프트웨어 아키텍처

기능별 ROS 2 패키지로 분리하고, 하드웨어 의존 코드를 좁은 경계 안에 가둬
실제 장비 확정 전에도 전체 배선을 검증할 수 있게 설계했습니다.

| 패키지 | 역할 |
|---|---|
| `mm_description` | URDF/xacro 로봇 모델 (베이스 + 6축 팔 + 센서 마스트) |
| `mm_lio` | Mid-360 드라이버, FAST-LIO2, EKF 융합, 2D 스캔 투영 |
| `mm_navigation` | slam_toolbox 매핑/위치추정, Nav2 설정 |
| `mm_base_control` | 차동 구동 제어, 휠 오도메트리 |
| `mm_arm_control` | FR16 인터페이스, 관절 한계 검사 |
| `mm_coordinator` | 주행↔조작 순차 실행 상태 기계 |
| `mm_bringup` | 통합 실행 및 런타임 파라미터 |

### 로컬 플래너 비교 측정

컨트롤러를 바꾸는 것은 런치 인자 하나지만, 어느 쪽이 나은지 판단하려면 숫자가
필요합니다. 계측 노드가 제어주기 유지율, 실패 횟수, 경로 효율, 재계획 횟수,
저크, 최소 장애물 거리를 기록하고, 같은 목표를 반복 주행해 평균과 편차로
비교합니다.

판단 순서에서 **제어주기 유지율이 1차 관문**입니다. 20 Hz를 못 맞춘 컨트롤러는
다른 지표가 좋아도 채택할 수 없습니다.

### 설정 일관성 검사

휠 반경, 속도 한계, 베이스 치수, LiDAR-IMU 외부 파라미터 같은 물리량이 URDF·제어
파라미터·Nav2 설정·SLAM 설정에 중복되어 있습니다. 한쪽만 고치면 **오류 없이 조용히
잘못 동작**하는 것이 이런 시스템의 대표적인 함정입니다.

이를 막기 위해 설정 파일 간 불변식을 검사하는 스크립트를 두고, 79개 항목을
자동으로 대조합니다. 전도 안전율도 별도 스크립트로 계산합니다. 둘 다 ROS 설치
없이 동작하므로 CI에서도 실행할 수 있습니다.

### 컨테이너 구성

기능 계층별로 컨테이너를 분리해 장애 격리와 재사용성을 확보합니다.

| 컨테이너 | 역할 |
|---|---|
| `bringup` | 로봇 하드웨어 계층 |
| `lio` | LiDAR 드라이버 + 오도메트리 |
| `slam` | 지도 작성 / 위치추정 |
| `nav2` | 자율주행 |
| `arm` | 매니퓰레이터 |
| `coordinator` | 태스크 조율 |

Nav2가 죽어도 SLAM과 베이스 제어는 유지되며, 해당 계층만 재시작할 수 있습니다.
