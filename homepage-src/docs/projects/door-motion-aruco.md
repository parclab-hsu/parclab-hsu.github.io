# 가전 도어 속도 측정 — ArUco marker 기반 profile 계측

:material-circle:{ style="color:#2e9e44" } **진행 중** · 산업체 수탁 과제

!!! abstract "문서 정보"
    고정 camera 하나와 도어에 붙인 **쌍 ArUco marker** 로 도어의 위치·속도·가속도 profile 을
    30 fps 로 잰다. 대상은 회전 도어(각도)와 슬라이드 서랍(직선)이다.

    이 페이지는 **추가 보정 없이 알고리즘만으로** 나쁜 촬영 조건(반사 띠·어두움·저대비·모션 블러)에서
    얼마나 개선되는지를 **기존 코드와 비교해** 정리한 공개 요약이다. 그림은 **합성 영상**과 수치만 싣는다.
    실측 녹화는 수치로만 인용한다.

    기준일 2026-10-29. 목표 플랫폼은 PC 와 Jetson Nano 급 CPU 다.
    **Jetson Nano 실기에서의 처리 시간은 아직 재지 않았다**(6 절).

    측정·해독·추적에 쓰는 식과 상수는 [9 절](#equations)에 모았다(2026-11-04 추가).

---

## 1. 측정 방식

- 도어 바디마다 marker 2개를 붙인다. 두 marker 의 corner 8개로 바디 자세를 푼다.
- 도어는 자유도가 하나(회전축 또는 직선 레일)이므로, 자세를 프레임마다 따로 푸는 대신
  **1-DOF 모델에 corner 를 직접 맞춘다.** rolling shutter 의 행별 시간차도 이 맞춤에 넣는다.
- 출력은 프레임별 위치·속도·가속도 CSV 와 stroke 별 요약(최고 속도, 이동량, 등속 구간 평균 등)이다.
  stroke 마다 **결측 표시**(`ok` / `incomplete`)와 그 이유가 함께 나간다(6.1 절).
- 저장할 때 6-DOF 자세를 rolling shutter 보정해 따로 낸다(6.3 절). 실시간 열은 그대로 둔다.

## 2. 기존 코드 대비 차이

### 2.1 비교한 세 판

| 판 | 내용 |
|---|---|
| **기존 코드** | 2026-10-27 개선 작업 전 측정 앱 폴더에 있던 코드(1-DOF 분석 포함). 회전 도어의 marker 배치 설정이 실물과 달라 회전 도어를 거의 잡지 못한다 |
| **중간 판** | 기존 코드 + 배치 설정 수정 + corner 변 정제 |
| **현재 판** | 중간 판 + corner 직접 맞춤, ROI 추적 검출, 블러 추적, 반사 띠 해독, 프레임 시간 예산 |

### 2.2 처리 단계별 변경

| 문제 | 원인 | 현재 판의 처리 |
|---|---|---|
| 회전 도어를 못 잡음 | marker 배치 설정이 실물과 다름 | 실물 배치로 등록(중간 판부터) |
| corner 가 안쪽으로 치우침 | SUBPIX 창이 marker 안쪽 bit 무늬에 끌림 | 변 전체로 직선을 맞춰 교점을 corner 로(중간 판부터) |
| 고속에서 위치·peak 오차 | 프레임마다 PnP, rolling shutter 무시 | 1-DOF corner 직접 맞춤 + readout 시간 모델 |
| 어두운 장면·저대비에서 검출 실패 | adaptive threshold 상수가 흑백 차보다 크다 | 직전 위치로 예측한 ROI 만 검출하고, ROI 밝기 범위가 좁으면 늘려서 다시 검출 |
| 장노출 모션 블러에서 검출 실패 | marker 경계가 번져 사각형 후보가 없다 | 3D 자세 등속 외삽 → 블러를 입힌 marker 템플릿 NCC 로 이어 가기 |
| **반사 띠(glare)가 marker 를 덮으면 0 %** | 3 절 | 경계(Canny) 사각형 + 띠 밝기장 보정 해독 |
| 반사 띠 안 corner 오차 0.9~1.4 px | 변 정제가 변마다 밝기 기준 하나를 쓴다 | 표본별 가산광 보정 → 0.16~0.20 px |
| 추가 처리로 30 fps 초과 위험 | 처리마다 비용 | 블러 추적·glare 해독에 **벽시계 예산**(프레임 시작부터 20 ms). 느린 기기에서는 저절로 덜 돈다 |

### 2.3 열화 없는 실측 녹화

같은 녹화(회전 도어 2, 슬라이드 4)를 같은 camera 파라미터로 돌렸다. 이 표의 기존 코드는 1-DOF 분석을 넣기 전 판(10/21)이고, 위치는 같은 방식(주축 투영)으로 재서 비교했다. 회전 도어는 배치 설정만 고친 값이다. 마지막 줄만 2.1 절의 기존 코드다.

| 정지 위치 σ, 슬라이드 4개 | 0.17~0.31 mm | 0.05~0.08 mm | 2.8~5.4배 |
| 정지 위치 σ, 회전 도어 2개 | 0.49~0.64 mm | 0.04 mm | 12~16배 |

### 2.4 사용상 차이

- **추가 파일**: `dof_corner_fit.py`(corner 직접 맞춤). 측정 앱 폴더에 함께 둔다.
- **CSV**: 기존 열은 그대로 두고 `dof_fit_*`(맞춤 잔차·readout·쌍 배치 보정)와 `dof_pos_source` 열을 더했다.
- **설정**: `ROI_TRACKING`, `BLUR_TRACK`, `GLARE_DECODE` 와 각 시간 예산 상수를 더했다. 모두 기본값이 켜짐이고, 끄면 그 단계만 빠진다.
- **필요 환경**: Python ≥ 3.7, OpenCV(contrib) ≥ 4.7, **권장 4.11 이상**. 4.7~4.10 은 빠른 구간 검출이 약하다(6 절). 현장 측정 PC 는 OpenCV 5.0.0 이다.

## 3. 반사 띠(glare) 해독

![반사 띠가 marker 를 덮은 합성 프레임, ArUco 가 보는 이진화, 경계 기반 해독 결과](../assets/door-aruco/glare_mechanism.png)

밝은 반사 띠가 marker 위를 지나가면 두 가지가 깨진다.

1. 띠의 밝기가 adaptive threshold 창 평균보다 높아서 띠 안이 전부 「흰색」이 된다. marker 바깥의 얇은 흰 여백선이
   묻혀 검정 테두리가 주변과 붙고, **사각형 후보 자체가 사라진다**((b)).
2. 띠가 흰 module 을 포화시키면 사각형은 잡혀도 비트 해독에서 떨어진다.

국소 정규화·black-hat·threshold 창 조정은 효과가 없었다(최대 23 %). 띠의 폭과 module 크기가 같아서 배경을 분리할 수 없기
때문이다. 대신 띠는 **매끄럽게 더해지는 빛**이라 marker 경계의 기울기는 살아 있다. 그래서 다음 순서로 읽는다((c)).

- **후보**: ArUco 탈락 후보, 추적 중인 marker 의 예측 corner, Canny 닫힌 사각형.
- **해독**: 늘 검정인 테두리 칸으로 띠 밝기장을 보간해 빼고 읽는다. 포화된 칸은 값이 하한일 뿐이므로 하한만으로 흰색이면
  흰색, 아니면 「모르는 칸」으로 지운다. 사전 전체와 대조해 오류가 12 % 이하이고 두 번째 후보와 3 비트 이상 벌어질 때만 받는다.
- **띠의 증거가 있을 때만**: 테두리가 포화됐거나 테두리 밝기장의 폭이 대비 이상일 때만 받는다. 이 조건이 없으면 블러·가림
  marker 까지 받아서 장노출 1 m/s peak 오차가 −0.4 % → −12 % 로 나빠졌다.
- **corner**: 윤곽 corner 는 3 px 안팎 틀리므로 변 직선 맞춤으로 다듬는다. 다듬지 못한 marker 는 버린다.

시험한 열화 녹화 전체에서 오검출은 0 건이었다.

### 3.1 여러 모양의 반사에 맞추기 (2026-10-28 추가)

위 해독은 한 가지 띠로만 맞췄다. 실제 반사는 폭·방향·세기·움직임이 제각각이므로 시험 반사를 9종으로 넓혔다.
폭은 marker module(한 변 / 7) 단위다.

![합성 marker 쌍에 입힌 반사 9종: 가는·세로·가로·사선·넓은·포화·멈춘 띠, 도는 반점, 깜박이는 띠](../assets/door-aruco/glare_zoo.png)

이 9종에서 실패는 세 가지였다.

1. **고정 경계 문턱이 작은 marker 에서 윤곽을 끊는다.** module 이 10 px 안팎이면 띠 옆면의 기울기가 경계 검출 문턱을 넘어
   사각형이 닫히지 않았다. 고정 문턱으로 못 찾으면 그 영역의 경계 세기(기울기 99 백분위)에 비례한 문턱으로 다시 찾는다.
   고정 문턱이 먼저다. 비례 문턱을 먼저 쓰면 고정 문턱으로 찾던 넓은 띠에서 다른 사각형을 먼저 받아 자세가 버려졌다.
2. **블러 추적의 상관이 반사에 끌려간다.** 반사는 빛을 더하기만 하므로, 그 marker 가 직접 잡혔을 때의 흰색보다 대비 1배
   넘게 밝은 화소와 포화 화소를 상관에서 뺀다. 예전 상관이 실패하고 움직임이 느릴 때만 쓰므로 열화 없는 녹화의 결과는 같다.
   대비 0.3배로 두었을 때는 도어가 움직이며 바뀌는 조명만으로 켜졌다.
3. **0 위치가 열린 자세로 잡힌다.** 닫힌 자세를 반사 때문에 못 보고 열리는 도중에 처음 잡으면, 처음 샘플을 0 으로 삼아
   각도 전체가 33~37° 밀렸고 경고도 없었다. 이제 **첫 정지 구간**을 0 으로 삼고, 그것이 처음 샘플이 아니면 저장 로그에
   경고를 남긴다.

실측 녹화 9개(슬라이드 4, 회전 도어 2, 작은 회전 도어 3: 40 mm marker)에 반사 9종을 입혀 움직이는 동안의 확보율을 비교했다
(열화 seed 고정, 녹화 범위, 이전 판 → 현재 판).

| 반사 | 슬라이드 | 회전 도어 | 작은 회전 도어 | 작은 회전 도어 위치 RMS 최대 |
|---|---|---|---|---|
| 가는 띠 | 22~52 → 22~80 % | 72~83 → 72~89 % | 41~67 → 29~80 % | 13.1 → 1.19° |
| 세로 띠 | 67~100 → 67~100 % | 95~99 → 95~99 % | 35~82 → 47~85 % | 1.70 → 0.92° |
| 가로 띠 | 89~100 → 89~100 % | 88~95 → 94~95 % | 64~94 → 81~94 % | 1.60 → 0.34° |
| 사선 띠 | 56~93 → 56~93 % | 95~100 → 97~100 % | 80~93 → 82~95 % | 1.81 → 0.28° |
| 넓은 띠 | 95~100 % | 100 % | 65~100 % | 0.30° |
| 포화 띠 | 0~2 → 0~3 % | 51~52 % | 0~41 → 0~43 % | 19.7 → 5.9° |

- 열화 18종 전체 평균 확보율은 79.5 → 81.8 % 다. 1 %p 넘게 좋아진 조합이 33개, 나빠진 조합이 4개다.
  열화 없는 녹화와 반사가 아닌 열화(어둡게·잡음·대비·JPEG·블러)는 결과가 같다.
- **나빠진 곳**: 슬라이드 70 의 기존 반사 띠 98.5 → 95.5 %(비례 문턱이 거친 corner 로 marker 를 먼저 받아 그 프레임이 재투영
  기준에서 빠진다), 같은 녹화의 가림 조건 위치 RMS 0.057 → 0.277 mm(흰색보다 밝은 가림판을 반사로 본다).
- **포화 띠는 고치지 못했다.** 띠 안이 255 라 marker 정보가 없다.
- 반사가 있는 프레임은 처리 시간이 중앙값 1.3~1.5 ms 늘었다(PC). 열화 없는 프레임은 같다.
- 비교 도중 bench 자체의 결함을 찾았다. 열화 seed 가 실행마다 바뀌어서(문자열 hash), 같은 판을 다시 돌려도 가림·누락
  조건이 몇~수십 % 흔들렸다. 고친 뒤에는 같은 판을 두 번 돌리면 결과가 같다. 위 표는 고친 bench 의 결과다.

## 4. 결과

### 4.1 실측 녹화 + 합성 열화

30 fps 의 프레임 예산은 33.3 ms 다. 아래는 데스크톱 1 스레드에서 1080p 실측 녹화 6개를 하나씩 처리한 시간(중앙값 / p99)이다.

### 6.1 Stroke 결측 표시 (2026-10-28 추가)

틀린 요약값을 고칠 수는 없으므로, **믿으면 안 되는 stroke 를 표시**한다. 값은 바꾸지 않는다.
아래 넷 중 하나라도 걸리면 그 stroke 는 `incomplete` 이고, 이유가 같은 행에 적힌다.

| 기준 | 문턱 | 잡는 경우 |
|---|---|---|
| 확보율(속도 샘플 / 구간 프레임) | < 80 % | 전체적으로 성긴 stroke |
| 샘플 사이 최대 빈틈 | > 0.20 s | 한 구간이 통째로 빠짐 |
| 잘림 | 움직이는 중에 구간이 시작·끝나고, 그 너머 0.10 s 에 샘플 없음 | 추적이 끊겨 이동량·지속 시간이 짧게 나옴 |
| peak 창(최고 속도 ±0.10 s) 확보율 | < 80 % | peak 근처만 성김 |

peak 창 기준이 핵심이었다. 처음에는 앞의 셋만 두었는데, **전체 확보율이 83~90 % 로 정상인데 peak 가 +9~12 % 틀린 stroke** 를
놓쳤다. peak 는 최대값이라 그 주변이 성기면 잡음이 값을 끌어올린다.

실측 녹화 6개 × 열화 9종에서, 열화 실행의 stroke 를 열화 없는 실행의 같은 stroke 와 짝지어 대조했다
(「틀림」 = peak 5 % 초과 또는 이동량 3 % 초과 차이).

| 항목 | 결과 |
|---|---|
| 틀린 stroke 중 표시된 것 | **6 / 6** (놓침 0) |
| 열화 없는 실행에서 잘못 표시된 것 | 0 |
| 값이 맞는데 표시된 것 | 16 / 102 (데이터가 성겨 근거가 약한 경우) |
| 반복성(슬라이드 100, 전 조건) 이동량 CV | 표시된 stroke 제외 **0.1 %** · 포함 24.8 % |

- 그림에서는 표시된 stroke 에 빗금과 「!」를 붙이고, 반복성 리포트는 기본으로 뺀다(옵션으로 포함 가능).
- 위 「슬라이드 100 + 반사 띠」 사례(측정이 일찍 끊겨 이동량이 짧게 나온 경우)는 「잘림」으로 잡혔다.

### 6.2 속도 구간: 가속 · 등속 · 감속 (2026-10-28 추가)

stroke 마다 속도 profile 을 **가속 → 등속 → 감속**으로 나누고, 저장할 때 구간 그림을 따로 만든다.
가로로 긴 그림의 위 칸은 기록 전체의 속도다. 아래 칸은 stroke 마다 앞뒤 0.3 s 를 붙여 확대한 진행 방향 속도와 가속도다.
구간마다 시간, 평균 가속·감속(구간 양 끝 속도 차 / 시간), 이동량을 적는다. 등속 구간에는 평균 ± σ 띠를 그린다.

![합성 슬라이드(0.4 m/s) 녹화의 속도 구간 그림: 열림·닫힘 모두 가속-등속-감속 사다리꼴](../assets/door-aruco/velocity_phases_slide.png)

![합성 회전 도어 녹화의 속도 구간 그림: 열림은 짧은 등속이 있는 사다리꼴, 닫힘은 등속 없는 삼각형](../assets/door-aruco/velocity_phases_rot.png)

**나누는 기준**

- 등속은 진행 방향 속도가 **처음 0.9·peak 에 닿은 때부터 마지막으로 그 위에 있던 때까지**다. 그 사이에 잠깐 내려간 것은
  등속 중 리플로 보고 σ 에 남긴다. 연속 구간으로 자르면 저속 녹화의 4.0 s 등속이 리플 때문에 0.43 s 로 끊겼다.
- 등속이 0.25 s 보다 짧으면 등속 없는 **삼각형** profile 로 보고 peak 에서 가속·감속을 나눈다.
- peak 둘레에 0.20 s 넘는 속도 공백이 있으면 구간을 나누지 않는다(`unknown`). 공백을 건너 경계를 이으면
  **없는 등속이 생긴다**. 합성 1 m/s 블러 녹화에서 0.37 s 공백이 「0.62 m/s 등속」으로 나왔던 것을 게시 전에 고쳤다.

**참값 대비 (합성 녹화)**

| 항목 | 슬라이드 0.4 m/s | 회전 도어 |
|---|---|---|
| 사다리꼴 / 삼각형 판정 | 참값과 같음 | 참값과 같음 |
| 등속 시작·끝 시각 | ±1 frame (0.033 s) | ±1 frame |
| 등속 속도 | 0.397 / 참값 0.398 m/s | 169.9 / 참값 172.1 deg/s |
| 가속 시간 | 0.37 / 참값 0.23 s | 0.53 / 참값 0.50 s |
| 평균 가속 | 1.02 / 참값 1.40 m/s² (−27 %) | 297 / 참값 318 deg/s² (−7 %) |

- 등속 경계와 등속 속도는 참값에 맞는다. **가속·감속 시간은 길고 평균 가속·감속은 작게** 나온다. 속도 미분 창(±0.10 s)이
  급출발·급정지를 번지게 해서 stroke 시작이 0.03~0.10 s 앞당겨지기 때문이다. 합성 슬라이드는 가속이 계단처럼 바뀌어 이 효과가 가장 크다.
- 실측 녹화 6개 × 열화 9종에서 열화 없는 실행과 짝지은 정상 stroke 82개는 판정이 모두 같았고, 등속 경계는 최대 1 frame 움직였다.
- 실측 슬라이드는 저속·중속에서 사다리꼴(등속 3.97 s · 0.63 s), 고속 두 단계에서 삼각형으로 나뉜다. 열림·닫힘이 대칭이다.
- 반복성(실측 슬라이드 중속, 같은 녹화 × 조건 10종): 등속 시작·끝 시각 CV 0~3 %, 등속 속도 CV 0.1~0.4 %.
  등속이 평평하면 peak 가 그 안 어디서든 잡히므로 「시작부터 peak 까지 시간」은 CV 9~14 % 다. 시점 비교에는 등속 경계를 쓴다.

### 6.3 Rolling shutter 보정 자세 (2026-10-28 추가)

실측 슬라이드 녹화에서 X-Y 궤적은 한 줄인데 **X-Z 궤적은 열림·닫힘이 두 줄로 갈라졌다.** 경로 차이가 아니라 rolling shutter 가
만든 깊이 오차다. 옆으로 움직이면 위·아래 marker 가 다른 시각에 찍혀 화면에서 기울어지고(shear), 프레임마다 푸는 PnP 가 이를
기울어짐·깊이 변화로 읽는다. 진행 방향이 바뀌면 부호도 바뀌어 두 줄이 된다.

- 근거: 저장된 corner 로 readout 을 0 → 45 ms 로 바꿔 가며 다시 풀면 열림−닫힘 Z 차의 부호가 26.5 ms 에서 바뀐다.
  1-DOF corner 맞춤이 따로 추정한 readout 과 같은 값이다. marker 의 화면 크기로 본 깊이 차는 약 1 mm 다.
- 보정: 저장할 때 corner 맞춤 모델로 corner 마다 노광 시각 차만큼의 화면 변위를 빼고 PnP 를 다시 푼다(`rs_pos_*`·`rs_rot_*`).
  고속에서 marker 하나만 보인 프레임은 4점 PnP 가 불안정해(회전 4~24° 튐) 회전을 모델 값으로 고정하고 위치만 푼다.
  1-DOF 결과와 실시간 열은 바뀌지 않는다.

### 6.4 실시간 속도 열은 늦다 (2026-10-28 추가)

화면 표시용 실시간 속도 열은 지난 프레임만 쓰는 이동평균 미분이라 늦다. 실측에서 직선 속도는 **0.09 s**, 각속도는 **0.21 s**
늦었고, 슬라이드 peak 는 저장 시 계산한 1-DOF 값보다 2~6 % 컸다.

- 실시간 열은 표시용이라 그대로 둔다. 속도 분석에는 저장 시 계산한 1-DOF 값(앞뒤 대칭 미분, 위상 지연 없음)을 쓴다.
- 3D 분석 그림의 속도·각속도 칸에 1-DOF 속도를 점선으로, 속도 구간을 색으로 겹치고 이 지연을 주석으로 적었다.

### 6.5 삼각형 profile 의 peak · 녹화 누락 원인 · 맞춤 잔차 (2026-10-28 추가)

10-28 슬라이드 실측 녹화 3개(보통 1회·5회, 빠르게 2회)를 검증하다가 세 가지를 찾아 반영했다.

**① 등속 없는 stroke 의 peak 를 꼭짓점 모형으로 잰다.** 슬라이드 빠르게 녹화는 peak 가 0.86~0.88 m/s 로 나왔다.
처음에는 행정이 짧아 1 m/s 에 못 닿은 것으로 보았지만 틀렸다. 실측 가속 2.3 m/s² 로 계산하면 v²/a = 0.43 m 로 행정(0.432 m)과 같다.
즉 약 1 m/s 까지 가속한 뒤 등속 없이 바로 감속한 것이고, ±0.10 s 다항식 미분이 그 뾰족한 꼭짓점을 깎았다.

- 고친 방법: 삼각형 profile 로 판정된 stroke 는 peak 앞뒤의 **위치** 샘플에 속도 모형을 적분해 맞춘다. 모형은 가속 직선 → 감속 직선이고, 꼭짓점을 너비 w 로 둥글린다.
  맞춤의 최고 속도를 peak 로 쓴다.
- 받는 조건: 잔차 RMS ≤ 이동량의 1 %, 결과가 다항식 peak 의 0.98~1.25 배. 조건을 못 넘으면 종전 다항식 값을 그대로 쓰고, 어느 쪽인지 열에 남긴다.
- 등속이 있는 사다리꼴 stroke 는 바뀌지 않는다. 단 등속 구간이 평평하지 않으면 예외다(6.9 절, 10-29 추가).

![합성 삼각형 속도 profile 두 가지. 다항식 미분은 뾰족한 꼭짓점을 1.000 → 0.901 m/s 로 깎고, 꼭짓점 모형은 참값과 같은 1.000 을 낸다. 둥근 꼭짓점은 0.885 → 0.855 대 0.885](../assets/door-aruco/apex_peak.png)

| 대상 | 다항식(종전) | 꼭짓점 모형 |
|---|---|---|
| 합성 삼각형·둥근 꼭짓점 10종(참값 있음) | 참값보다 작다(최대 −17 %) | **±2.2 % 안** |
| 실측 슬라이드 빠르게(10-28), stroke 4개 (m/s) | 0.861 / 0.874 / 0.884 / 0.875 | **0.962 / 0.956 / 0.979 / 0.966** |
| 실측 슬라이드 100 열림 / 닫힘 (m/s) | 0.871 / 0.874 | **0.958 / 0.963** |
| 실측 슬라이드 70 열림 / 닫힘 (m/s) | 0.695 / 0.690 | 0.716 / 0.714 |
| 사다리꼴 stroke, 회전 도어 | — | 바뀌지 않음 |

- 실측 녹화에는 참값이 없다. 실측 값이 맞다는 근거는 합성 시험과 v²/a = 행정 계산뿐이다. 엔코더 동시 측정으로 확인할 예정이다.
- 속도 그림의 곡선은 다항식 미분 그대로 두고, peak 표기에만 두 값을 함께 적는다.

**② 녹화에서 빠진 frame 의 원인을 남긴다.** 10-28 녹화 3개에 1 frame 짜리 빈틈이 16개 있었고, 모두 움직이는 중이었다.
camera 쪽 frame 번호는 이어져 있으므로 앱 안에서 빠진 것이다. 이 PC 의 재현 bench(8.1 절)에서는 0개라 원인을 가리지 못했다.

- 이제 빠진 frame 마다 원인을 별도 CSV 에 남긴다. 원인은 넷이다: 캡처 대기열 넘침, 저장 중 건너뜀, 녹화 인코더 대기열 넘침, 기록 밖. 그때의 적체도 함께 남긴다.
- 녹화를 끝낼 때 빠진 frame 수와 원인별 수를 출력한다. 현장 PC 에서 다시 녹화하면 원인을 가를 수 있다.

**③ corner 맞춤 잔차를 정지·움직임으로 나눠 본다.** 한 녹화(5회 왕복)만 정지 frame 의 corner 맞춤 잔차가 2.38 px 였다. 다른 녹화는 0.23~0.61 px 다.
움직임 frame 은 블러·rolling shutter 가 섞여 원래 잔차가 크므로, 정지 frame 만 따로 보고 1.5 px 를 넘으면 경고를 남긴다.
이동이 축 하나가 아니거나(레일 유격, camera 흔들림) marker 가 들떴을 때 나타나는 값이다. 그 녹화의 원인은 확인하지 못했다.

이 반영으로 단위 시험은 133 → 144건이 됐다(6.6 절 뒤 162건).

### 6.6 블러 corner 와 180° 넘는 회전 (2026-10-29 추가)

stroke 요약값이 아니라 **marker 하나하나의 위치·자세**를 참값과 비교하는 합성 bench 를 새로 만들었다.
장면은 슬라이드 도어(0.4·1.0 m/s), 회전 도어, 손잡이 노브, 다이얼 노브 다섯 가지이고, 조건은 노출 2·8·16 ms 와 어둡게·저대비·반사·잡음·흔들림·초점·가림 등 10종이다.
이 bench 로 결함 셋을 찾았고, 그중 두 개를 고쳤다.

**① 블러 marker 가 짧게 잡힌다 — 고침.** 1 m/s · 8 ms 에서 움직이는 frame 의 marker 3D 중심 오차가 8~11 mm 였다. 원인은 두 가지가 겹친 것이다.

- 블러 폭 문턱이 빠른 frame 을 기본 corner(SUBPIX)로 돌렸다. 기본 corner 는 블러 marker 를 블러 길이의 약 절반만큼 짧게 낸다.
- 문턱을 꺼도 변 정제가 marker 를 3.9 px 짧게 냈다. marker 둘레 흰 여백(약 12 px)이 블러(17.5 px)보다 좁아, 밝기가 흰색까지 오르지 못하고 꺾인다.
  그 봉우리를 흰 레벨로 쓰면 50 % 기준이 어두운 쪽으로 내려가 교차점이 안으로 들어간다.

고친 방법은 세 단계다.

1. 블러는 운동에 나란한 변을 넓히지 않는다. 그래서 블러로 넓어진 변은 경사가 가장 좁은 두 변의 안·밖 밝기 레벨을 빌려 기준을 다시 잡는다.
2. 빌린 기준에도 닿지 못한 변은 경사 아래쪽(대비 20·40 %)을 잇는 직선을 50 % 까지 늘려 잡는다. 경사 아래쪽에는 밖의 배경이 아직 섞이지 않는다.
   **이 단계는 같은 날 껐다**(아래 ③). 합성에서는 맞았지만 실측에서 corner 를 밖으로 밀었다.
3. 둘 다 안 되면 그 marker 는 기본 corner 를 쓴다. 블러 폭 문턱은 없앴다. 문턱을 중간값에 두면 한 stroke 안에서 두 방식이 frame 마다 바뀌어 1-DOF 샘플이 버려졌다.

![합성 녹화에서 움직이는 frame 의 marker 3D 중심 오차. 수정 전, 늘려 잡기를 켠 판, 지금(늘려 잡기 끔). 노출 8 ms 슬라이드 1.0 m/s 는 8.16 → 0.70 → 1.63 mm, 회전 도어는 10.92 → 3.32 → 6.01 mm 다](../assets/door-aruco/blur_corner_fix.png)

- 지금 판(1·3단계)은 늘려 잡기를 켠 판보다 개선이 작지만 수정 전보다는 작다. 블러가 흰 여백보다 좁은 경우(슬라이드 0.4 m/s 노출 16 ms: 7.64 → 0.59 mm)는 1단계만으로 고쳐진다.
- 정지 frame 과 노출 2 ms 는 그대로다.
- 블러 6 px 에서 임의 방향·자세 20 회의 깊이 오차는 기본 corner 14~15 mm → 지금 2.9~5.8 mm 다(늘려 잡기를 켜면 0.31~0.42 mm). 정제 처리 시간(12 marker, p99 1.88 ms)은 그대로다.
- 정제가 빠른 frame 에서도 맞게 되자, 상대 기준(주변 잔차의 중앙값)으로 이상 frame 을 고르는 1-DOF 판정이 원래 잔차가 큰 블러 추적 frame 을 버렸다.
  그래서 주변 중앙값을 직접 검출과 블러 추적으로 나눠 따로 낸다. 늘려 잡기를 켰을 때는 요구사항 밖의 반사 조건에서 확보율이 낮아졌다(슬라이드 1 m/s 반사 100 → 92.5 %, 회전 도어 반사 97.3 → 90.5 %). 끈 지금은 100 %·97.3 % 로 돌아왔다.
- 실측 녹화(참값 없음)는 ③ 에 있다.

**② 회전 1-DOF 가 180° 를 넘지 못한다 — 고침.** 회전 1-DOF 는 기준 자세 대비 회전 벡터를 축에 투영한 값이다. 회전 벡터의 크기는 0~180° 라서 180° 를 넘으면 −(360° − θ) 로 접혔다.
이제 축 투영각을 시간 순으로 이어 붙인다. 축 밖 잔차가 큰 frame 은 잇는 데 쓰지 않고 이웃 값의 2π 배수에 맞춘다. 자세 하나를 잘못 잡았다고 360° 가 계속 더해지지 않게 하려는 것이다.

| 합성 다이얼 노브 | 1-DOF 위치 RMS 전 → 후 | 속도 RMS 전 → 후 |
|---|---|---|
| 180° | 127.07 → **0.026°** | 519 → 5.0 deg/s |
| 270° | 115.61 → **0.033°** | 599 → 7.6 deg/s |

180° 를 넘지 않는 장면(도어 3종·다이얼 150°)은 값이 그대로다.

**③ 실측에서 늘려 잡기가 corner 를 밀었다 — 껐다.** 현장에서 이 판을 돌리자 「슬라이드 100」 녹화의 세 frame 이 재투영 오차 4 px 를 넘어 버려졌다(4.11~4.68 px).
세 frame 이 최고 속도 구간에 있어 그 stroke 의 peak 가 0.963 → **0.762 m/s** 로 낮게 나왔다.

- 원인은 2단계(늘려 잡기)다. 늘려 잡은 변의 점이 변을 따라 ±3 px 흩어졌다(블러 없는 변은 ±0.2 px). 그래서 변 직선이 기울고 한쪽 corner 가 10 px 가까이 밖으로 나갔다. 한 frame 은 marker 위 변이 186.5 px 로 다른 세 변(173 px)보다 길었다.
- 점의 오차가 marker 무늬 경계에서 계단처럼 바뀐다. 그래서 경사 아래쪽에 테두리 안쪽의 흰 무늬가 섞이는 것으로 본다. 합성 블러 장면에서는 나타나지 않았다.
- 2단계만 껐다. 1단계(레벨 빌리기)와 블러 폭 문턱 없앰은 그대로 둔다.

| 실측 6개 녹화 | 수정 전 | 늘려 잡기 켬 | 지금 |
|---|---|---|---|
| 재투영으로 버린 frame | 0 | 3(슬라이드 100) | **0** |
| 슬라이드 100 stroke peak (m/s) | 0.958 / 0.963 | 0.958 / 0.762 | 0.958 / 0.963 |
| 슬라이드 70 stroke peak (m/s) | 0.720 / 0.713 | 0.706 / 0.702 | 0.716 / 0.714 |
| 회전 도어 빠르게 stroke peak (deg/s) | 176.0 / 174.6 | 176.1 / 172.3 | 175.4 / 173.9 |
| 빠른 frame 1-DOF 축·레일 이탈: 슬라이드 100 / 70 / 회전 도어 빠르게 | 2.90 / 3.19 mm / 1.93° | 1.59 / 1.90 mm / 3.39° | 3.00 / 3.24 mm / 1.91° |

- 이동량은 세 판 모두 0.2 % 안에서 같다. 늘려 잡기를 켰을 때 회전 도어 빠르게의 축 이탈이 늘었던 것도 같은 원인이었다.
- 실측 빠른 frame 은 블러가 흰 여백보다 넓어 1단계에서 기준을 못 빌리는 일이 많다(슬라이드 100 의 가장 빠른 5 frame 전부). 그래서 지금 판은 수정 전과 거의 같다. 빠른 frame 의 6-DOF 자세를 맞히려면 노출을 줄이는 것이 먼저다.

**④ 검출 한계 — 그대로.** marker 한 변이 약 48 px 보다 작으면 검출되지 않는다(40 mm marker 는 약 1.0 m). 이것은 거리·marker 크기 선택의 문제로 남긴다.

대부분 시험이 다루지 않던 경로(정지한 바디, 녹화 쓰기 실패, 보정 옵션, 기준 바디 방식)였다.

### 6.8 빠른 여닫기: readout 오추정과 검출 빈틈 (2026-10-29 추가)

소형 회전 도어를 빠르게 2회 여닫은 실측 녹화(10-28)에서 stroke 가 1개만 잡혔다(확보율 22 %). rolling shutter readout 은 57 ms 로 추정됐다. 30 fps 의 frame 주기는 33.3 ms 라서, readout 이 그보다 길 수는 없다. 원인은 둘이다.

**① readout 추정에 블러 추적 corner 가 섞였다 — 고침.** 빠른 frame 18개 중 9개가 블러 추적 corner 였다. 블러 추적 corner 는 그린 템플릿을 맞춘 값이라 rolling shutter 시차를 담지 않는다. 직접 검출 corner 만 쓰면 26 ms 에서 잔차가 최소다.

- 블러 추적 frame 은 readout 추정에서 뺀다. 탐색 범위의 상한은 frame 주기다.
- 최소가 상한에 붙거나, 블러 추적을 빼서 빠른 frame 이 10개 미만이 되면 추정하지 않는다. 이때는 기본값 26 ms 를 쓰고 이유를 저장 로그에 남긴다.
- 그 녹화는 57.1 → 26.0 ms 가 됐다. 다른 슬라이드 도어의 보통 1회·7회 왕복(10-28)도 45.1·32.4 ms 로 상한 근처였는데 기본값으로 바뀌었다. 느린 녹화라 결과에 거의 영향이 없다.
- 실측 12녹화의 stroke 값은 최대 0.88 % 바뀌었다.

**② marker 가 frame 당 1 module 의 수 배를 움직여 검출이 끊긴다 — 오프라인 도구로 채운다.** marker 한 module 이 약 9 px 인데, stroke 가운데에서는 frame 당 약 100 px 움직인다. 66 px/frame 부터는 사각형 후보 자체가 생기지 않는다. 검출 설정을 바꿔도 58 frame 중 7 frame 만 돌아왔다.

- 오프라인 도구(측정 중에는 쓰지 않음)를 새로 만들었다. 녹화와 저장된 결과를 읽어 다음 순서로 빈 frame 을 채운다.
  1. 맞춘 1-DOF 기하(축, 기준 자세, marker 배치)를 그대로 쓴다.
  2. 두 marker 를 노출 블러와 rolling shutter 까지 넣어 그린다.
  3. 그린 그림을 영상과 맞춰(NCC) 빈 frame 의 위치를 찾는다. 빈틈 양쪽에서 앞뒤로 따라가고, 노출 비율도 함께 고른다.
- 직접 검출값과 블러 추적값은 건드리지 않는다. 처음 판은 블러 추적값도 모형 값으로 바꿨다. 그런데 합성에서 바꾼 8녹화 모두 오차가 커졌다(0.09~0.20 → 0.12~0.63°). 그래서 같은 날 기본으로 껐다. 처음 켠 근거(블러 추적 오차 2.26°)는 readout 이 57 ms 로 틀리던 판의 값이었다.

![합성 소형 회전 도어의 빠른 여닫기. 왼쪽: 90° 를 0.6 s 에 여닫는 녹화(노출 12 ms)의 각속도. 채우기 전에는 두 stroke 가운데가 비어 있고, 채운 frame 19개가 참값 곡선을 따라간다. 오른쪽: 12녹화의 움직이는 frame 확보율이 38~95 % 에서 모두 100 % 가 된다](../assets/door-aruco/gapfill_synthetic.png)

합성 소형 회전 도어(실측 기하, 90°, readout 26 ms)로 확인했다. 소요는 0.8·0.6 s, 노출은 4·8·12 ms, seed 는 2개로 모두 12녹화이며 영상 생성부터 다시 돌렸다.

### 6.9 사람이 여닫은 도어의 peak: 꼭짓점 모형이 맞다 (2026-10-29 추가)

  - 평평한 등속은 이 비가 1.00~1.03 이라 바뀌지 않는다. 합성 사다리꼴은 리플 0·3 %, 실측 로봇 구동 슬라이드는 1.013~1.023 이다.

    혹 0.88 × peak 는 12 stroke 중 1개가 아직 다항식으로 재져 −12.5 % 다. 그 stroke 의 다항식 peak / 등속 평균이 1.049 로 문턱 바로 아래였다.
    나머지 11개는 1.052~1.061 이고 −5.8 ~ −2.0 % 다. 문턱으로 나누는 한, 문턱 근처에서는 방식이 바뀌어 값이 크게 달라질 수 있다.
    (2026-11-04 정정: 10-29 판은 「0.80~0.88 은 −5.8 ~ −1.6 %, seed 에 따라 뒤집히지 않는다」로 이 1개를 빠뜨렸다.)
- **해 보고 버린 방법 두 가지:**
  - 꼭짓점 모형에 등속 길이를 더하는 방법. 짧은 등속의 넘침은 +0.3 % 로 줄었지만, 뾰족한 peak 에서는 잡음에 등속을 맞춰 −9 ~ −11 % 깎았다.
  - 등속 있는 stroke 전부에 꼭짓점 모형을 쓰는 방법. 진짜 등속(0.5~0.9 s)에서 +4 ~ +6 % 넘쳤다.

|---|---|

- 남는 한계: 다항식 peak / 등속 평균이 문턱 바로 아래(1.04~1.05)인 뾰족한 peak 는 여전히 다항식으로 재져 −12 % 안팎 깎일 수 있다. 또 등속이 0.2~0.3 s 로 짧은 stroke 에서는 꼭짓점 모형이 최대 +7 % 넘칠 수 있다. 위치만으로는 짧은 등속과 뾰족한 peak 를 가르지 못하므로, 엔코더 동시 측정으로 확인할 예정이다.
- 단위 시험에 6건을 더했다. 같은 합성 녹화에 이전 규칙을 쓰면 −12 % 가 나오는지도 함께 확인한다.

## 7. 한계

- 반사 해독은 **합성한 반사 10종**(3·3.1 절)으로만 검증했다. 실제 반사로는 아직 확인하지 않았다.
- 포화 띠는 읽지 못한다. 흰색보다 밝은 가림판을 반사로 보아 가림 조건의 위치가 나빠진 경우가 있다(3.1 절).
- 띠가 marker 경계까지 포화시켜 경계 기울기가 사라지면 읽지 못한다(슬라이드 100 + 반사 띠 59~71 %). 이때 틀린 stroke 요약값은 **고쳐지지 않고 표시만 된다**(6.1 절) — 재측정이 필요하다.
- 블러 추적은 이미 한 번 잡은 marker 만 잇는다. 처음부터 심하게 번진 녹화에서는 효과가 없다.
- 회전 도어 장노출의 빠른 닫힘 stroke 는 peak 가 여전히 낮다(−18 %).
- 블러가 marker 둘레 흰 여백보다 넓으면(1 m/s · 노출 8 ms 이상) 움직이는 frame 의 marker 3D 중심 오차가 남는다. 8 ms 1.6~7.9 mm, 16 ms 9.7~13.7 mm 다(6.6 절). 이 경우를 고치는 늘려 잡기는 실측에서 corner 를 밀어 껐다. 6-DOF 자세가 필요하면 노출을 줄이는 것이 먼저다.
- 빠른 여닫기 빈틈 채우기(6.8 절)는 합성 회전 도어로만 참값과 대조했다. 슬라이드 도어는 참값 대조가 없고, 실측에서 채운 값은 모형 맞춤값이다.
- 회전 1-DOF 는 frame 사이 회전이 180° 보다 작다고 가정한다. 추적이 끊긴 동안 180° 넘게 돌면 360° 틀린 값으로 이어진다.
- 속도 구간은 가속 → 등속 → 감속을 한 번씩만 나눈다. 사람이 연 도어처럼 속도가 중간에 여러 번 머물면 그 머묾이 가속·감속 구간에 들어간다.
  평균 가속·감속은 미분 창 때문에 작게 나온다(6.2 절, 급출발 합성 −27 %).
- 삼각형 stroke 와 등속 구간이 평평하지 않은 stroke 의 peak 는 꼭짓점 모형으로 잰다(6.5·6.9 절). 꼭짓점의 둥글기가 모형(상자 둥글기)과 다르면 수 % 오차가 남고, 등속이 0.05~0.30 s 로 짧으면 최대 +7 % 넘친다. 조건을 못 넘은 stroke 는 종전 다항식 값이다.
- Rolling shutter 보정 자세는 블러가 심한 고속 stroke 에서 깊이가 흔들린다(6.3 절, 최악 조합 최대값 9.1 → 13.9 mm).
  심한 열화에서 readout 추정이 틀리면 보정도 틀린다.
- 캡처 대기열은 0.4 s 보다 긴 main loop 멈춤은 막지 못한다. 카메라 드라이버·USB 쪽에서 빠진 프레임도 대기열과 무관하다(따로 센다).
  현장 카메라로는 아직 다시 재지 않았다(8.1 절).
- Jetson Nano 기본 구성(JetPack 4.x: Python 3.6, OpenCV 4.1.1)은 기존 코드와 마찬가지로 조건에 맞지 않는다. Python 3.8 과 OpenCV 4.11 을
  따로 설치해야 하며, 실기 처리 시간은 그 뒤에 잰다.

### 8.1 프레임 누락: 창 멈춤과 캡처 대기열 (2026-10-28 추가)

현장 구동에서 500 프레임마다 1~2개가 빠졌다. 실제 main loop 를 창·키 처리까지 그대로 돌리고, 카메라 자리에
녹화 영상을 30 fps 벽시계로 흘리는 재현 bench 를 만들어 반복마다 단계별 시간을 쟀다.

- 누락은 모두 **화면 창 갱신(`cv2.waitKey`)이 한 번에 40~176 ms 멈춘 반복**에서 생겼다. 검출(2~7 ms), 실시간 그래프(2~5 ms),
  가비지 컬렉션(최대 0.6 ms)은 원인이 아니었다. 멈춤은 1.4 s 동안 몰려 오기도, 홀로 오기도 했다.
- 최신 프레임 하나만 두면 main loop 가 두 프레임(약 66 ms) 넘게 멈출 때 그 사이 프레임이 덮어써진다.
  창 라이브러리가 Qt 라 창 처리를 다른 thread 로 옮길 수도 없다.
- 대응: capture thread 가 프레임을 **대기열 12장**에 쌓고, main loop 는 밀린 프레임이 있으면 화면 그리기·그래프·키 처리를 건너뛰고
  측정부터 따라잡는다. 키 입력이 막히지 않게 연속 건너뛰기는 15번까지로 묶었다.

### 9.1 1-DOF 운동 모형과 corner 직접 맞춤 (1·2.2 절)

바디의 기준 자세를 \\(R_0, t_0\\), 운동 축을 단위 벡터 \\(a\\), 회전축 위의 한 점을 \\(c\\) 라 하자.
프레임마다 남는 미지수는 \\(q\\) 하나다(슬라이드는 m, 회전 도어는 각도).

<div class="math">
\[
\begin{aligned}
&\text{slide:} && R(q) = R_0, && t(q) = t_0 + q\,a \\
&\text{hinge:} && R(q) = \mathrm{Rot}(a,q)\,R_0, && t(q) = \mathrm{Rot}(a,q)\,(t_0 - c) + c
\end{aligned}
\tag{1}
\]
\[
\mathrm{Rot}(a,q) = \cos q\, I + \sin q\, [a]_\times + (1-\cos q)\, a a^\top
\tag{2}
\]
</div>

marker \\(m\\) 의 corner \\(j\\) 는 바디 좌표에서 \\(X_{mj}\\) 다. 쌍 marker 의 실제 배치는 설정값과 몇 mm·1° 안팎 다르므로,
첫 marker 를 고정하고 나머지 marker 에 작은 보정 \\((\Delta R_m, \Delta t_m)\\) 을 둔다. 스케일은 고정한 첫 marker 의 한 변에서 온다.
rolling shutter 는 corner 가 찍힌 행 \\(v\\) 에 따라 노광 시각이 다르다는 것으로 넣는다. 프레임 시각은 가운데 행 기준이고,
\\(\tau\\) 는 한 프레임을 읽는 시간(readout), \\(H\\) 는 영상 높이다.

<div class="math">
\[
q_{ij} = q_i + \dot q_i \left(\frac{v_{ij}}{H} - \frac12\right)\tau
\tag{3}
\]
\[
\hat u_{ij} = \pi\!\left(K, d;\; R(q_{ij})\,(\Delta R_m X_{mj} + \Delta t_m) + t(q_{ij})\right)
\tag{4}
\]
</div>

\\(\pi\\) 는 camera 행렬 \\(K\\) 와 왜곡 계수 \\(d\\) 로 투영하는 함수(OpenCV `projectPoints` 와 같다)다. 전체 녹화의 재투영 오차를
Huber 손실로 줄인다. 반사·가림으로 틀린 corner 의 영향을 줄이기 위해서다.

<div class="math">
\[
\min_{\{q_i\},\,R_0,\,t_0,\,a,\,c,\,\{\Delta R_m,\Delta t_m\},\,\tau}\;
\sum_{i}\sum_{j} \rho_k\!\left(\lVert \hat u_{ij} - u_{ij} \rVert\right),
\qquad
w(r) = \min\!\left(1, \frac{k}{r}\right),\quad k = 1.5\ \text{px}
\tag{5}
\]
</div>

한꺼번에 풀지 않고 세 단계를 3번 번갈아 돈다.

1. 기하를 고정하고 프레임마다 \\(q_i\\) 를 가중 Gauss–Newton 으로 푼다. \\(\dot q_i\\) 는 직전 \\(q\\) 의 미분(9.3 절)이다.
2. \\(q\\) 를 고정하고 기하·배치 보정을 Levenberg–Marquardt 로 푼다. 녹화 전체에서 고르게 고른 150 프레임을 쓴다.
3. \\(\tau\\) 는 LM 변수로 두지 않는다. 축 기울기·배치 보정과 맞바꿔져 틀린 값이 나왔기 때문이다. 대신
   \\(\tau \in [0, \min(60\ \text{ms}, T)]\\) 를 1차원 격자로 훑어 빠른 프레임의 잔차가 가장 작은 값을 고른다. \\(T\\) 는 프레임 주기다.
   빠른 프레임은 corner 화면 속도가 300 px/s 를 넘는 프레임이고, 10개 이상 있어야 추정한다. 블러 추적(9.6 절) 프레임은 뺀다.
   최소가 상한에 붙으면 추정을 버리고 기본값을 쓴다.

맞춘 뒤 프레임 잔차 \\(e_i\\)(RMS, px)가 크면 그 샘플을 버린다. \\(\tilde e_i\\) 는 ±0.25 s 안에서 같은 종류(직접 검출 / 블러 추적) 샘플의 중앙값이다.

<div class="math">
\[
e_i \gt \max\!\left(6\ \text{px},\; 4\,\tilde e_i\right) \;\Rightarrow\; \text{reject}
\tag{6}
\]
</div>

### 9.2 축 초기값, 운동 종류, 0 위치 (3.1 절 ③)

PnP 자세 \\((R_i, P_i)\\) 로 9.1 절의 초기값을 만든다. 기준 자세 \\(R_0\\) 은 정지 구간 자세의 chordal 평균,
\\(P_0\\) 는 위치 평균이다. 기준 자세에 대한 상대 회전 벡터는 축이 고정이면 한 직선 위에 놓인다.

<div class="math">
\[
r_i = \log\!\left(R_i R_0^\top\right)^\vee,\qquad
a_h = \operatorname{PC}_1\{\, r_i : \lVert r_i\rVert \gt 2^\circ \,\},\qquad
\theta_i = r_i^\top a_h,\qquad
\epsilon_i = \lVert r_i - \theta_i a_h \rVert
\tag{7}
\]
\[
a_s = \operatorname{PC}_1\{\, (P_i - P_0) - \overline{(P - P_0)} \,\},\qquad
s_i = (P_i - P_0)^\top a_s
\tag{8}
\]
</div>

\\(\operatorname{PC}_1\\) 은 SVD 첫 주축이다. 주축을 구한 뒤 축에서 \\(\max(3\cdot\text{median}, \text{문턱}/2)\\) 보다 먼 점을 빼고 한 번 더 구한다.
\\(\max_i\lvert\theta_i\rvert \ge 10^\circ\\) 이면 회전 도어, 아니고 \\(\max_i\lVert P_i - P_0\rVert \ge 20\\) mm 이면 슬라이드로 본다.
축 밖 성분이 회전 15°, 슬라이드 30 mm 를 넘는 샘플은 버린다. 부호는 0 에서 가장 크게 벗어난 쪽을 + 로 둔다.
회전각은 180° 를 넘어도 이어지게 펼친다(6.6 절).

**0 위치**는 처음부터 훑어 만나는 첫 정지 구간이다. 연속 15 샘플 \\(\mathcal W\\) 가 다음을 만족하면 정지로 본다.
샘플이 띄엄띄엄 잡힌 구간(프레임 수 > 2 × 샘플 수)은 쓰지 않는다.

<div class="math">
\[
P_{90}\!\left\{\lVert P_i - \bar P_{\mathcal W}\rVert\right\}_{i\in\mathcal W} \le 5\ \text{mm},
\qquad
P_{90}\!\left\{\angle\!\left(R_i \bar R_{\mathcal W}^\top\right)\right\}_{i\in\mathcal W} \le 2^\circ
\tag{9}
\]
</div>

### 9.3 시간축과 미분 (6.2·6.4 절)

프레임 번호 \\(f_i\\) 를 호스트 시각 \\(t^{\text{host}}_i\\) 에 직선으로 맞춰 시간축을 만든다. USB·스케줄링 지터가 빠진다.
camera 가 고정 주기로 찍지 않아 맞춤 잔차가 크면 호스트 시각을 그대로 쓴다.

<div class="math">
\[
(\hat t_0, T) = \arg\min \sum_i \left(t^{\text{host}}_i - \hat t_0 - T\,(f_i - f_0)\right)^2,
\qquad t_i = \hat t_0 + T\,(f_i - f_0)
\tag{10}
\]
</div>

속도·가속도는 샘플마다 대칭 창 안에서 2차 다항식을 최소제곱으로 맞춰 낸다(불균일 시간 간격의 Savitzky–Golay).
창이 대칭이므로 위상 지연이 없다. 결측(nan)과 추적 공백을 넘는 점은 쓰지 않고, 한쪽에만 점이 있으면 값을 내지 않는다.

<div class="math">
\[
\hat\beta = \arg\min_\beta \sum_{\lvert t_k - t_i\rvert \le h'} \Big(y_k - \sum_{p=0}^{2} \beta_p (t_k - t_i)^p\Big)^2,
\qquad \dot y_i = \hat\beta_1,\quad \ddot y_i = 2\hat\beta_2
\tag{11}
\]
</div>

\\(h' = h + T/4\\) 이고 \\(h\\) 는 속도 0.10 s, 가속도 0.15 s 다. \\(T/4\\) 여유가 없으면 창 경계가 프레임 주기의 정수배에 걸려,
주기 추정값의 끝자리에 따라 녹화마다 5점 또는 7점이 들어갔다.

### 9.4 꼭짓점 모형의 peak 속도 (6.5·6.9 절)

±0.10 s 다항식 미분(식 11)은 뾰족한 peak 를 깎는다. 삼각형 profile 은 꼭짓점 시각 \\(t_p\\) 앞뒤를 직선 속도 둘로 보고,
그것을 너비 \\(w\\) 상자로 둥글린 모형을 위치 샘플에 맞춘다. \\(u = t - t_p\\) 다.

<div class="math">
\[
v(u) = c_1 + \begin{cases} c_2\,u, & u \lt 0 \\ -c_3\,u, & u \ge 0 \end{cases}
\qquad c_2,\,c_3 \ge 0
\tag{12}
\]
\[
\bar v_w(u) = \frac{1}{w}\int_{u-w/2}^{u+w/2} v(s)\,ds,
\qquad
x(u) = c_0 + \int_0^u \bar v_w(s)\,ds
\tag{13}
\]
</div>

\\(x(u)\\) 는 \\(c\\) 에 대해 선형이다. 그래서 \\((w, t_p)\\) 격자마다 최소제곱 한 번으로 \\(c\\) 를 구하고, 평균 제곱 잔차가 가장 작은 조합을 고른다.

- \\(w \in \\{0, 0.02, \dots, 0.40\\}\\) s, \\(t_p\\) 는 다항식 peak 시각 ±0.10 s 를 4 ms 간격으로 훑는다.
- 맞춤 창은 \\(\lvert u\rvert \le \min(0.25\ \text{s},\, 0.4 \times \text{stroke 길이})\\) 이다. 8 샘플 이상이 있어야 하고, 창 안 샘플 간격이 공백 한도를 넘으면 안 된다.
- peak 는 \\(\max_u \bar v_w(u)\\) 다. 다음 두 조건을 모두 만족할 때만 받는다.

<div class="math">
\[
\mathrm{RMS}(x - \hat x) \le 0.01 \times \text{travel},
\qquad
0.98 \le \frac{\max_u \bar v_w(u)}{v^{\text{poly}}_{\max}} \le 1.25
\tag{14}
\]
</div>

적용 대상은 삼각형 profile 이다. 등속 구간이 있는 사다리꼴도 다항식 peak 가 등속 구간 평균의 1.05 배를 넘으면 적용한다(6.9 절).

<div class="math">
\[
v^{\text{poly}}_{\max} \gt 1.05\,\bar v_{\text{cruise}}
\tag{14a}
\]
</div>

### 9.5 반사 띠 해독 (3 절)

사각형 후보를 marker 격자 \\((n+2)\times(n+2)\\) 칸으로 펼친다. \\(n\\) 은 비트 수이고, 바깥 한 줄은 늘 검정인 테두리다.
칸마다 8×8 px 로 펼쳐, 가운데 절반 화소의 평균 \\(V_{rs}\\) 와 최대값으로 포화 여부 \\(S_{rs}\\) 를 잰다(최대 ≥ 250 이면 포화).
포화 칸은 값이 하한일 뿐이다.

반사 띠는 매끄럽게 더해지는 빛이다. 그래서 테두리 네 변의 밝기로 안쪽 「검정」 밝기장을 Coons 보간한다.
테두리의 포화 칸은 같은 변의 이웃 칸으로 보간해 메운다.
\\(L, R\\) 은 왼쪽·오른쪽 변을 행 좌표 \\(\eta\\) 의 함수로, \\(U, B\\) 는 위·아래 변을 열 좌표 \\(\xi\\) 의 함수로 본 것이다.
\\(\xi, \eta \in [0,1]\\) 이다.

<div class="math">
\[
\begin{aligned}
F(\eta,\xi) = {}& (1-\xi)L(\eta) + \xi R(\eta) + (1-\eta)U(\xi) + \eta B(\xi) \\
& - \big[(1-\xi)(1-\eta)U(0) + \xi(1-\eta)U(1) + (1-\xi)\eta B(0) + \xi\eta B(1)\big]
\end{aligned}
\tag{15}
\]
\[
D_{rs} = V_{rs} - F_{rs},\qquad
h = P_{90}(D),\qquad
b_{rs} = \big[D_{rs} \gt h/2\big],\qquad
\kappa_{rs} = \neg\big(S_{rs} \wedge D_{rs} \le h/2\big)
\tag{16}
\]
</div>

\\(b\\) 는 읽은 비트, \\(\kappa\\) 는 「아는 칸」이다. 포화 칸이 흰색 문턱을 못 넘으면 실제 값을 알 수 없으므로 지운다.
사전의 모든 ID \\(m\\) 과 방향 \\(k \in \\{0,1,2,3\\}\\) 의 비트 \\(B_{m,k}\\) 와 대조한다.

<div class="math">
\[
E_{m,k} = \sum_{r,s} \kappa_{rs}\,\big[B_{m,k,rs} \ne b_{rs}\big],
\qquad N_\kappa = \sum_{r,s}\kappa_{rs}
\tag{17}
\]
</div>

오류가 가장 작은 후보 \\(E_{(1)}\\) 과 두 번째 후보 \\(E_{(2)}\\) 에 대해 다음을 모두 만족할 때만 받는다.

<div class="math">
\[
h \ge 20,\quad N_\kappa \ge 12,\quad E_{(1)} \le 0.12\,N_\kappa,\quad E_{(2)} - E_{(1)} \ge 3,\quad
\Big(\textstyle\bigvee_{\partial} S \;\;\lor\;\; \max F - \min F \ge h\Big)
\tag{18}
\]
</div>

마지막 항이 「띠의 증거」다. 테두리 칸 중 하나가 포화됐거나, 테두리 밝기장의 폭이 대비 이상이어야 한다.
그리고 등록된 바디의 ID 여야 한다.

**비례 경계 문턱 (3.1 절 ①).** 사각형 후보는 Canny 경계의 닫힌 볼록 사각형이다. 문턱 \\((\lambda_{\text{lo}}, \lambda_{\text{hi}})\\) 은
고정값 (40, 80)으로 먼저 쓴다(칸 훑기는 ½ 축소 영상에서 (60, 120)). 기대 ID 를 다 못 찾으면 영역의 기울기 크기 99 백분위 \\(P\\) 에 비례한 문턱을
높은 쪽부터 쓴다. \\(P\\) 는 2 화소마다 솎은 Sobel 크기로 잰다. 앞 문턱과 \\(\lambda_{\text{hi}}\\) 가 10 % 안으로 같으면 건너뛴다.

<div class="math">
\[
(\lambda_{\text{lo}}, \lambda_{\text{hi}}) \in
\begin{aligned}
\Big\{&(40, 80),\;\; \big(\max(40, 0.35P),\, \max(80, 0.7P)\big),\\
&\big(\max(40, 0.25P),\, \max(80, 0.5P)\big)\Big\},
\qquad P = P_{99}\,\lVert\nabla I\rVert
\end{aligned}
\tag{19}
\]
</div>

### 9.6 블러 추적과 반사를 뺀 상관 (2.2·3.1 절 ②)

**3D 등속 외삽.** 직전 두 자세 \\((R_0, t_0)\\) 와 \\((R_1, t_1)\\) 가 \\(d\\) 프레임 떨어져 있으면(\\(1 \le d \le 3\\)),
\\(k\\) 프레임 뒤의 자세는 다음과 같다. 이 자세로 corner 를 투영해 예측 corner 를 만든다.

<div class="math">
\[
\omega = \frac{1}{d}\log\!\left(R_1 R_0^\top\right)^\vee,\qquad
R(k) = \exp\!\left(k\,[\omega]_\times\right) R_1,\qquad
t(k) = t_1 + \frac{k}{d}\,(t_1 - t_0)
\tag{20}
\]
</div>

예측 corner 자리에 그 ID 의 이상 marker(흰 여백 1 module 포함)를 그리고, 예측 화면 속도 방향으로 노출 비율
\\(e \in \\{0.15, 0.30, 0.45, 0.60\\}\\) 만큼 번지게 해 템플릿 \\(T\\) 를 만든다. 예측 둘레 ±2.5 module 에서 평균을 뺀 정규화 상관(NCC)이
가장 큰 이동을 찾는다. 최고점은 축마다 포물선으로 부화소 위치를 낸다.

<div class="math">
\[
\delta^\ast = k + \frac{\rho_{k-1} - \rho_{k+1}}{2\,(\rho_{k-1} - 2\rho_k + \rho_{k+1})}
\tag{21}
\]
</div>

받는 조건은 \\(\rho \ge 0.55\\)(예측 블러가 1 module 보다 짧으면 0.8)이다. 또 marker ID 를 맞바꿔 그린 템플릿보다 0.05 이상 높아야 한다.

**반사를 뺀 상관.** 반사는 빛을 더하기만 한다. 그래서 그 marker 가 직접 잡혔을 때의 흰색보다 크게 밝은 화소에는 marker 정보가 없다고 본다.
직접 검출된 marker 의 비트 영역 화소를 10·90 백분위의 중점에서 둘로 나누고, 각 쪽의 중앙값으로 검정 \\(\ell_b\\)·흰색 \\(\ell_w\\) 을 5 프레임마다 잰다.
반사가 걸린 채 잰 값은 흰색을 부풀리므로, 내려갈 때는 빨리, 올라갈 때는 천천히 따라간다.

<div class="math">
\[
\ell \leftarrow \ell + \alpha\,(\hat\ell - \ell),\qquad
\alpha = \begin{cases} 0.5, & \hat\ell \lt \ell \\ 0.05, & \hat\ell \ge \ell \end{cases}
\tag{22}
\]
\[
\vartheta = \min\!\big(\ell_w + K(\ell_w - \ell_b),\; 249\big),\quad K = 1
\tag{23}
\]
\[
\omega(x) = 1 - \big[x \in \operatorname{dilate}_{r}\{\, I \gt \vartheta \,\}\big],\quad r = 0.5\ \text{module}
\tag{23a}
\]
</div>

템플릿 지지 영역 \\(\Omega\\) 에서 이동 \\(\delta\\) 마다 가중 합을 낸다. 여기서 \\(I\\) 는 영상, \\(T\\) 는 템플릿이다.

<div class="math">
\[
\begin{gathered}
N = \sum_\Omega \omega,\quad
S_1 = \sum_\Omega \omega I,\quad
S_2 = \sum_\Omega \omega I^2,\quad
\\
T_1 = \sum_\Omega \omega T,\quad
T_2 = \sum_\Omega \omega T^2,\quad
X = \sum_\Omega \omega I T
\end{gathered}
\tag{24}
\]
\[
\rho_\omega(\delta) = \frac{X - S_1 T_1 / N}{\sqrt{\left(S_2 - S_1^2/N\right)\left(T_2 - T_1^2/N\right)}},
\qquad
\rho_\omega(\delta) = -1 \;\;\text{if}\;\; N \lt 0.35\,\lvert\Omega\rvert
\tag{25}
\]
</div>

\\(\omega \equiv 1\\) 이면 식 25 는 보통의 NCC 와 같다. 각 합은 `matchTemplate`(TM_CCORR) 여섯 번으로 낸다. 반사를 뺀 상관은 다음을 모두 만족할 때만 쓴다.

- 예전 상관(\\(\omega \equiv 1\\))으로 못 찾았다.
- 예측 이동이 1 module/프레임보다 작다. 빠른 블러에서는 틀린 자리를 받았다.
- 흰색이 포화보다 15 이상 낮다: \\(\ell_w \le 235\\). 흰색이 이미 포화 근처이면 밝기로 반사를 가를 수 없다.
- 예측 marker 자리(흰 여백까지, 한 변 × 9/7) 안에서 \\(I > \vartheta\\) 인 화소가 3 % 이상이다.
- 같은 바디에서 2번 잇달아 실패하면 한동안 쉰다.

### 9.7 시험용 합성 반사 (3.1 절)

**반사는 시험용 합성이다.** 학습에 쓰는 데이터 증강이 아니다. 측정 경로는 고전적 영상 처리이고 학습하는 모델이 없다.
합성 반사는 두 군데에 쓴다. 실측 녹화에 반사를 더해 확보율을 비교하는 bench(3.1·4.1 절)와, 참값 궤적으로 다시 그린 합성 녹화(4.2 절)다.
**실제 반사가 있는 녹화로는 아직 검증하지 않았다**(7 절).

반사는 가우시안 밝기를 더하고 0~255 로 자른다. 띠는 화면 전체를 가로지르는 직선 띠, 반점은 둥근 점이다.

<div class="math">
\[
I'(x) = \operatorname{clip}_{[0,255]}\!\Big(I(x) + A_i \exp\!\Big(-\frac{\delta_i(x)^2}{2\sigma^2}\Big)\Big),
\qquad
\delta_i(x) = \begin{cases} n^\top\big(x - p_i\big), & \text{band} \\ \lVert x - p_i\rVert, & \text{spot} \end{cases}
\tag{26}
\]
</div>

\\(n = (\cos\alpha, \sin\alpha)\\) 는 띠의 법선이다(\\(\alpha = 0^\circ\\) 이면 세로 띠). 폭은 \\(\sigma = \sigma_{\text{mod}}\cdot s/7\\) 이고,
\\(s\\) 는 그 프레임 marker 한 변의 평균 길이(px)다. 따라서 폭이 marker 크기를 따라간다.
\\(\bar c\\) 를 marker corner 중심, \\(S = \tfrac12\operatorname{ptp}(n^\top q) + s/7\\) 을 띠가 marker 묶음을 법선 방향으로 넘나드는 진폭이라 하면,
프레임 \\(i\\) 의 위치와 세기는 다음과 같다.

<div class="math">
\[
\text{sweep: } p_i = \bar c + S\sin(0.15\,i)\,n,\qquad
\text{static: } p_i = \bar c,\qquad
\text{orbit: } p_i = \bar c + 0.6\,S\,(\cos 0.15\,i,\; \sin 0.15\,i)
\]
\[
\text{flicker: } p_i = \bar c,\quad A_i = \tfrac12 A_0\big(1 + \sin 0.4\,i\big);\qquad \text{그 밖에는 } A_i = A_0
\tag{27}
\]
</div>

| 반사 | 모양 | \\(\alpha\\) | \\(\sigma_{\text{mod}}\\) | \\(A_0\\) | 움직임 |
|---|---|---|---|---|---|
| 가는 띠 | band | 0° | 0.5 | 200 | sweep |
| 세로 띠 | band | 0° | 1.0 | 180 | sweep |
| 가로 띠 | band | 90° | 1.0 | 180 | sweep |
| 사선 띠 | band | 45° | 1.5 | 180 | sweep |
| 넓은 띠 | band | 20° | 4.0 | 150 | sweep |
| 포화 띠 | band | 0° | 1.5 | 400 | sweep |
| 멈춘 띠 | band | 0° | 1.0 | 180 | static |
| 도는 반점 | spot | — | 1.5 | 250 | orbit |
| 깜박이는 띠 | band | 0° | 1.0 | 180 | flicker |

- 4.1 절의 「반사 띠」는 9종을 만들기 전의 조건이다. marker 묶음 상자 안에만 가우시안 띠(최대 +180)를 그린다. 비교를 위해 남겨 두었다.
- 4.2 절의 합성 녹화는 화면에 고정된 가우시안 띠(식 26 의 band, 움직이지 않음)를 장면에 더한다. 광택 표면의 정반사처럼 판이 지나갈 때만 판 위에 얹힌다.
- 열화 seed 는 조건 이름의 CRC32 로 정한다. 같은 판을 다시 돌리면 결과가 같다(3.1 절).
