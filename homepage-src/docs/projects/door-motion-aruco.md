# 가전 도어 속도 측정 — ArUco marker 기반 profile 계측

:material-circle:{ style="color:#2e9e44" } **진행 중** · 산업체 수탁 과제

!!! abstract "문서 정보"
    고정 camera 하나와 도어에 붙인 **쌍 ArUco marker** 로 도어의 위치·속도·가속도 profile 을
    30 fps 로 잰다. 대상은 회전 도어(각도)와 슬라이드 서랍(직선)이다.

    이 페이지는 **추가 보정 없이 알고리즘만으로** 나쁜 촬영 조건(반사 띠·어두움·저대비·모션 블러)에서
    얼마나 개선되는지를 정리한 공개 요약이다. 그림은 **합성 영상**과 수치만 싣는다.
    실측 녹화는 수치로만 인용한다.

    기준일 2026-10-27. 목표 플랫폼은 PC 와 Jetson Nano 급 CPU 다.
    **Jetson Nano 실기에서의 처리 시간은 아직 재지 않았다**(5 절).

---

## 1. 측정 방식

- 도어 바디마다 marker 2개를 붙인다. 두 marker 의 corner 8개로 바디 자세를 푼다.
- 도어는 자유도가 하나(회전축 또는 직선 레일)이므로, 자세를 프레임마다 따로 푸는 대신
  **1-DOF 모델에 corner 를 직접 맞춘다.** rolling shutter 의 행별 시간차도 이 맞춤에 넣는다.
- 출력은 프레임별 위치·속도·가속도 CSV 와 stroke 별 요약(최고 속도, 등속 구간 평균 등)이다.

## 2. 무엇을 고쳤나

| 문제 | 원인 | 개선 |
|---|---|---|
| 고속에서 위치·peak 오차 | 프레임마다 PnP, rolling shutter 무시 | 1-DOF corner 직접 맞춤 + readout 시간 모델 |
| 어두운 장면·저대비에서 검출 실패 | adaptive threshold 상수가 흑백 차보다 크다 | 직전 위치로 예측한 ROI 만 검출하고, ROI 밝기 범위가 좁으면 늘려서 다시 검출 |
| 장노출 모션 블러에서 검출 실패 | marker 경계가 번져 사각형 후보가 없다 | 3D 자세 등속 외삽 → 블러를 입힌 marker 템플릿 NCC 로 이어 가기 |
| **반사 띠(glare)가 marker 를 덮으면 0 %** | 아래 3 절 | 경계(Canny) 사각형 + 띠 밝기장 보정 해독 |
| 반사 띠 안 corner 오차 0.9~1.4 px | 변 정제가 변마다 밝기 기준 하나를 쓴다 | 표본별 가산광 보정 → 0.16~0.20 px |
| 프레임 시간 30 fps 초과 위험 | 추가 처리마다 비용 | 블러 추적·glare 해독에 **벽시계 예산**(프레임 시작부터 20 ms). 느린 기기에서는 저절로 덜 돈다 |

## 3. 반사 띠(glare) 해독

![반사 띠가 marker 를 덮은 합성 프레임, ArUco 가 보는 이진화, 경계 기반 해독 결과](../assets/door-aruco/glare_mechanism.png)

밝은 반사 띠가 marker 위를 지나가면 두 가지가 깨진다.

1. 띠의 밝기가 adaptive threshold 창 평균보다 높아서 띠 안이 전부 「흰색」이 된다. marker 바깥의 얇은 흰 여백선이
   묻혀 검정 테두리가 주변과 붙고, **사각형 후보 자체가 사라진다**((b)).
2. 띠가 흰 module 을 포화시키면 사각형은 잡혀도 비트 해독에서 떨어진다.

국소 정규화·black-hat·threshold 창 조정은 효과가 없었다(최대 23 %). 띠의 폭과 module 크기가 같아서 배경을 분리할 수 없기
때문이다. 대신 띠는 **매끄럽게 더해지는 빛**이라 marker 경계의 기울기는 살아 있다. 그래서 다음 순서로 읽는다((c)).

- **후보**: ArUco 탈락 후보, 추적 중인 marker 의 예측 corner, Canny 닫힌 사각형.
- **해독**: 늘 검정인 테두리 칸으로 띠 밝기장을 보간해 빼고 읽는다. 포화된 칸은 값이 하한일 뿐이므로 하한만으로 흰색이면
  흰색, 아니면 「모르는 칸」으로 지운다. 사전 전체와 대조해 오류가 12 % 이하이고 두 번째 후보와 3 비트 이상 벌어질 때만 받는다.
- **띠의 증거가 있을 때만**: 테두리가 포화됐거나 테두리 밝기장의 폭이 대비 이상일 때만 받는다. 이 조건이 없으면 블러·가림
  marker 까지 받아서 장노출 1 m/s peak 오차가 −0.4 % → −12 % 로 나빠졌다.
- **corner**: 윤곽 corner 는 3 px 안팎 틀리므로 변 직선 맞춤으로 다듬는다. 다듬지 못한 marker 는 버린다.

시험한 열화 녹화 전체에서 오검출은 0 건이었다.

## 4. 결과

### 4.1 실측 녹화 + 합성 열화

실측 녹화 6개(회전 도어 2, 슬라이드 4: 구동 속도 설정 10·40·70·100)에 같은 열화를 입혀 **움직이는 동안 측정값이 나온
프레임 비율**을 비교했다. Before 는 납품 원본 코드, After 는 현재판이다.

![실측 녹화 6개에 열화 4종을 입혔을 때 확보율 비교](../assets/door-aruco/availability_real.png)

| 열화 | Before | After |
|---|---|---|
| 반사 띠, 슬라이드 4개 | 0 % | 59~100 % |
| 반사 띠, 회전 도어 2개 | 61~67 % | 94~100 % |
| 어둡게(×0.25 + 잡음), 슬라이드 | 0~36 % | 98~100 % |
| 대비 35 %, 슬라이드 | 34~53 % | 100 % |
| 블러 + 어둡게 + JPEG | 0~73 % | 42~100 % |
| 열화 없음 | 100 % | 100 % |

- 잡음 σ10·가림 조건은 Before 와 같은 수준이다(실행마다 몇 % 흔들린다).
- 가장 나쁜 칸은 「슬라이드 100 + 반사 띠」(59 %)와 「회전 도어 빠르게 + 블러·어둡게·JPEG」(42 %)다.

### 4.2 합성 녹화(참값 있음)

실측 장면 위에 참값 궤적으로 marker 를 다시 그려 만든 합성 녹화 36개(속도 3종 + 회전 도어 × 조건 9종)로 참값 대비 오차를 쟀다.

![합성 녹화 세 경우의 속도 profile: 참값, Before, After 와 결측 프레임](../assets/door-aruco/profile_synthetic.png)

| 경우 | Before | After |
|---|---|---|
| 슬라이드 1 m/s, 정상 노출 | 위치 2.34 mm, peak +2.7 % | 위치 0.31 mm, peak +0.1 % |
| 회전 도어, 정상 노출 | 0.61° | 0.026° |
| 슬라이드 1 m/s, 장노출(블러) | 확보 60 %, peak −24 % | 확보 95 %, peak −0.4 % |
| 회전 도어, 장노출 | 확보 85 %, peak −47 % | 확보 88 %, peak −18 % |
| 반사 띠, 슬라이드 0.4 m/s | 확보 85 %, 위치 1.32 mm | 확보 98 %, 위치 0.15 mm |
| 반사 띠, 회전 도어 | 확보 91 %, 위치 0.62° | 확보 97 %, 위치 0.060° |

나머지 조건(광량 15 %, 대비 25 %, 가림, 지터)에서 회귀는 없었다.

## 5. 처리 시간과 30 fps

30 fps 의 프레임 예산은 33.3 ms 다. 아래는 데스크톱 1 스레드에서 1080p 실측 녹화를 처리한 시간이다.

| 조건 | 중앙값 | p99 |
|---|---|---|
| 원본 코드, 열화 없음 | 4.2~4.6 ms | — |
| 현재판, 열화 없음 | 2.3~2.8 ms | 6.9~9.1 ms |
| 현재판, 반사 띠 | 4.8~4.9 ms | 8.6~12.1 ms |

- 직전 위치 주변만 검출하므로, 추가 처리를 넣고도 열화 없는 녹화는 원본보다 빠르다.
- 블러 추적과 glare 해독은 프레임 시작부터 20 ms 를 넘을 것 같으면 건너뛴다. 예산을 1/10 로 줄인 시험에서 프레임 시간은 예산 안에
  묶였지만, 반사 띠 확보율은 0 % 로 떨어졌다. **느린 기기에서는 30 fps 를 지키는 대신 확보율이 PC 결과보다 낮을 수 있다.**
- **Jetson Nano 실기 시간은 아직 재지 않았다.** 실기에서 경고 로그와 두 예산 값을 먼저 확인할 예정이다.
- 필요 환경: Python ≥ 3.7, OpenCV(contrib) ≥ 4.7 — 원본 코드와 같고 이번 개선으로 늘지 않았다. Python 3.8 + numpy 1.19 + OpenCV 4.7.0 과
  Python 3.13 + OpenCV 5.0 에서 시험 5종과 bench 를 돌려 같은 결과를 확인했다. JetPack 4.x 기본 구성(Python 3.6, OpenCV 4.1.1)은
  원본과 마찬가지로 조건에 맞지 않으므로 Python 3.8 과 OpenCV ≥ 4.7 을 따로 설치해야 한다.

## 6. 한계

- 반사 띠 해독은 **합성한 띠**(가우시안 모양)로만 검증했다. 실제 반사로는 아직 확인하지 않았다.
- 띠가 marker 경계까지 포화시켜 경계 기울기가 사라지면 읽지 못한다(슬라이드 100 + 반사 띠 59 %).
- 블러 추적은 이미 한 번 잡은 marker 만 잇는다. 처음부터 심하게 번진 녹화에서는 효과가 없다.
- 회전 도어 장노출의 빠른 닫힘 stroke 는 peak 가 여전히 −18 % 낮다.
