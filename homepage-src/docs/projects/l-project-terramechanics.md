# 달 탐사 로버 HILS를 위한 차륜–월면토 상호작용 모델 고도화 및 실측 기반 검증

:material-circle:{ style="color:#f0ad4e" } **차년도 과제 제안** · 현대자동차 L-Project · 기준일 **2026-09-07**

!!! abstract "요약"
    실물 제어기(Hardware Controller)가 루프 안에 포함된 **HILS**는 구축되어 동작 중입니다.
    다만 그 제어기가 마주하는 플랜트는 **강체 지형** 위에 있습니다. 월면토는 하중을 받으면
    침하하고 침하 상태에 따라 견인력이 달라지는데, 그 층이 비어 있습니다.

    관련 기능은 시뮬레이터(OmniLRS)에 **두 가지**가 존재합니다 — 바퀴자국을 생성하는
    **지형 변형(Deformation/Sinkage) 엔진**과, 견인력·주행 저항을 산출하는
    **Terramechanics 기반 차륜–토양 상호작용 솔버**입니다. 계측 결과 전자는 현행 설정에서
    변형이 발생하지 않고, 후자는 비활성 상태이며, 무엇보다 **두 모델을 잇는 물리 경로가 양방향 모두 끊겨
    있습니다.**

    이 둘을 **침하–견인 연성(Coupled) 모델로 통합하고 실측 자료로 검증하는 것**을 차년도
    과제로 제안합니다. 연구 범위는 12개 WP(4절), 판정 지표는 9개(5절), 추진은 3단계(6절)입니다.

## 1. 연구 필요성

달 탐사 로버의 주행 성능은 **토양의 침하 거동과, 침하 상태에서 발생하는 견인력**으로
결정됩니다. 바퀴가 침하한 만큼 주행 저항이 증가하고, 토양의 전단 특성에 따라 견인력이
정해지기 때문입니다.

현재 플랜트는 이 층이 없는 **강체 지형**을 전제로 합니다. 따라서 여기서 산출된
슬립·견인력·등판 한계·자세 값은 모두 강체 조건의 결과입니다. 차년도에 자율 주행이나
크레이터 탈출 거동을 다루기 위해서는 이 층을 우선 확보해야 합니다.

!!! info "착수 시점으로 적절한 이유"
    2026-08-25에 장기 미해결 상태였던 계측 문제를 해소하면서 **현재 플랜트의 슬립이 사실상
    0임을 확인**했습니다. 토양 모델 적용 시 발생하는 변화를 명확히 귀속시킬 수 있는
    **기준선(Baseline)**이 이번에 처음 확보되었습니다. 기준선 없이 모델을 도입하면 변화의
    원인을 분리할 수 없습니다.

## 2. 현재 상태 — 침하·견인 모델의 기능적 한계 및 통합 필요성

### 2.1 침하 모델 — 현행 설정에서 지형 변형 미발생 및 파라미터 정합 필요

기능을 활성화하고 로버를 주행시키며 계측했습니다(2026-08-26). 동일 지령·동일 시간
조건입니다.

| | 현행 설정 | 접지 폭을 실측 휠 폭으로 조정 |
|---|---|---|
| **로버 이동 거리** | **12.156 m** | **0.054 m** |
| 지형 격자 변화 셀 수 | **0** | 40 → 49 |
| 최대 침하량 | **0.000000 m** | 0.208 m |
| 연산 비용 | 30 → **26.5 Hz** (−11.7 %) | — |

현행 설정에서는 **연산 비용은 발생하나 지형 변형이 일어나지 않습니다.** 근사적으로 0이
아니라 정확히 0이며 **오류도 보고되지 않아**, 기능이 동작 중인 것으로 오인될 수 있습니다.
접지 폭을 실측값으로 조정하면 변형은 발생하지만, 이번에는 침하량이 과대하여 **로버의
주행이 사실상 불가능해집니다.**

**실행 파라미터 13개를 전수 점검한 결과**(2026-09-08), 출처가 분명한 것은 지형
해상도·폭·높이 **3개뿐**이며 나머지는 예제값이거나 출처가 확인되지 않습니다. 그중 세
항목은 별도 조치가 필요합니다.

| 항목 | 상태 |
|---|---|
| **`gravity`** | 설정에 자리가 있으나 **코드에서 참조되지 않음** — 견인 솔버의 중력 하드코딩과 같은 계열 |
| **`footprint.shape`** | **미사용** — 접지면이 항상 직사각형으로 생성됩니다. 실제 접지는 진입각~이탈각 사이의 원호입니다 |
| **`num_links`** | 대상 링크 설정과 **연결되어 있지 않음**. 기본값 4로 동작하며 현재 휠 수와 우연히 일치합니다 |

### 2.2 견인 모델 — 비활성 상태 및 대상 로버·토양 파라미터 정합 필요

견인력(Drawbar Pull)·주행 저항·조향 저항 토크를 산출하는 솔버가 별도로 구현되어
있습니다. Bekker–Wong 계열의 차륜–토양 상호작용 모델입니다. 확인 결과입니다.

| 확인 항목 | 현재 상태 |
|---|---|
| 시뮬레이션 루프 호출 | **주석 처리되어 실행되지 않음** |
| 코드 성숙도 | 클래스 설명에 **`WIP`(작업 중)** 로 명시 |
| 침하량 입력 | **0으로 고정** — 지형 변형 모델과 연계되어 있지 않음 |
| 힘 적용 | 동일 힘이 **2회 연속 적용** |
| 로버 제원 | **기본값** — 질량 20 kg, 휠 반경 0.09 m |
| 토양 계수 | **기본값** — 월면토 조건이 반영되지 않은 일반값 |
| **중력 가속도** | **9.81 m/s² 하드코딩** — 달 중력(1.62)이 아님 |
| **그라우저 항** | 파라미터가 **선언만 되어 있고 계산에 미사용** |

!!! warning "대상 로버 제원과의 불일치"
    본 과제 로버는 **450 kg · 휠 반경 0.2133 m**이며, 솔버는 **20 kg · 0.09 m** 기준으로
    생성되어 있습니다. 질량 **22.5배**, 반경 **2.4배** 차이입니다.

    현 상태로 활성화할 경우 대상 로버가 아닌 **소형 로봇 조건의 외력**이 로버에 인가됩니다.

### 2.3 침하–견인 모델 간 연계 부재 — 양방향 모두

두 모델을 잇는 물리 경로는 **두 방향**입니다. 현재 두 방향 모두 끊겨 있습니다.

| 경로 | 물리적 의미 | 현재 상태 |
|---|---|---|
| 접지력 → 침하 | 하중이 클수록 깊이 침하 | 구현되어 있음 |
| 슬립 + 침하 → 견인 | 침하 상태에서 전단이 결정 | 솔버에 구현, **침하량을 0으로 수신** |
| **슬립 → 침하** | **슬립이 클수록 토양을 배출하며 더 침하** | **모델에 없음** |

침하량 산출은 **접지력만** 입력으로 받습니다. 따라서 **바퀴가 헛돌아도 침하가 깊어지지
않습니다.** 반대로 견인 산출은 슬립을 사용하지만 침하량을 0으로 받으므로, 침하가 견인에
반영되지 않습니다.

**바퀴자국이 생성되어도 주행 거동에 반영되지 않고, 힘을 산출하는 쪽은 침하 상태를 알지
못하며, 슬립이 침하를 키우지도 않습니다.** 이 **양방향 되먹임**을 성립시키는 것이 본
과제의 **침하–견인 연성(Coupled)** 모델입니다(WP3·WP10).

## 3. 핵심 기술 이슈 및 원인 분석 결과

분석 과정에서는 **① 접지력 신호, ② 침하량 산출, ③ 지형 좌표·갱신 여부**의 3개 진단
경로를 동시에 계측하였습니다. 세 경로는 외부에서 관찰할 때 동일한 증상으로 나타나기
때문입니다. 이를 통해 침하 및 견인 모델 전반에서 **총 6개의 구체적인 원인**을
확인하였습니다.

| # | 원인 | 근거 |
|---|---|---|
| 1 | 접지 폭이 격자 2셀 미만이어서 경계 분포가 전부 0 | 접지력이 **최대 907 N**으로 충분히 인가되나 침하량이 0 |
| 2 | **힘–침하 관계식의 출처 미확인** | 적용 토양·휠·중력 조건이 문서화되어 있지 않으며, 접촉력 0에서도 침하가 산출되는 형태 |
| 3 | 정지 상태에서 접지력이 **0으로 계측**되어, 침하가 하중이 아닌 **과도 응답**에 비례 | 실제 바퀴자국의 물리와 반대 |
| 4 | **초기 낙하 충격이 지형에 반영됨** | 주행 개시 전 **21 cm** 깊이가 생성 |
| 5 | 견인 솔버가 **침하량을 0으로 수신** | 두 모델 간 연계 부재 |
| 6 | 솔버의 로버·토양 제원이 **기본값** | 20 kg / 0.09 m / 월면토 미반영 계수 |

!!! info "안식각(`angle_of_repose`)에 대한 확인 결과"
    현행 값은 **60°**이며, 월면토에 대해 통상 보고되는 **30~45°보다 높습니다.** 출처는
    설정에도 상류 문서에도 없습니다.

    **원인 1번을 이 값으로 해결할 수는 없음을 확인했습니다.** 접지 폭이 격자 2셀일 때는
    두 표본점이 모두 경계에 위치하여, **안식각과 무관하게 분포가 0**이 됩니다. 폭을
    조정해 3셀 이상으로 만드는 것 외의 방법이 없습니다.

    다만 **폭을 조정한 뒤에는 침하 깊이를 최대 2.6배까지 좌우합니다**(폭 0.159 m 기준
    60° 대 30°). 2.1절에서 확인된 과대 침하에 이 값이 기여하고 있을 가능성이 있어
    WP2에서 함께 검토합니다.

3번에 대해서는 **대체 계측 경로를 확인**하였습니다. 접지력이 0으로 계측되는 동일 상태에서
서스펜션 하중 신호는 유효하였으며(표준편차 0.000), 네 바퀴 합이 **정적 자중의 1.083배**로
산출되었습니다.

!!! warning "해석상 유의점"
    위 1.083배는 **하중 정보가 존재한다는 근거**이며 환산식이 확정되었다는 의미가
    아닙니다. 좌우 부호가 상이하므로 서스펜션 4절 링크 기구학을 거쳐야 실제 휠 하중이
    되며, **총합 일치가 휠별 분배의 정확성을 보장하지 않습니다**(5절 지표 4·5 참조).

## 4. 제안 연구 범위

### 4.1 침하 (Sinkage)

| WP | 내용 | 선행 |
|---|---|---|
| **WP1** | **하중 계측 경로 전환** — 접지력 대신 서스펜션 하중에서 역산. 4절 링크 기구학 반영 | — |
| **WP2** | **힘–침하 관계 재정립** — Bekker 압력–침하 이론 기반. 달 중력·그라우저 휠 조건 명시. **안식각 출처 확보**(현행 60°, 침하 깊이를 2.6배까지 좌우) | WP1 |
| **WP3** | **슬립–침하(slip-sinkage) 연성 및 반복 통과 누적** — 슬립에 따른 침하 증가를 모델에 도입하고, 같은 셀을 반복 통과할 때의 누적 규칙을 재정립 | WP2 |
| **WP4** | **접지 형상 산정** — 접지 폭·길이를 접지 역학으로 결정. 길이는 침하량의 함수이므로 상수 가정 불가. **접지면 형상을 직사각형에서 실제 접지 형상으로**(`footprint.shape` 미사용 상태 해소) | WP2 |
| **WP5** | **초기 조건 및 설정 정합** — 낙하·안착 완료 후 변형 개시. **`gravity` 미사용·`num_links` 미연결 해소** | — |

!!! danger "WP3이 없으면 크레이터 탈출 거동을 재현할 수 없습니다"
    현재 침하량 산출은 **접지력만** 입력으로 받습니다. 슬립은 들어가지 않습니다.
    즉 **바퀴가 헛돌아도 파고들지 않습니다.**

    그런데 크레이터 탈출은 정확히 그 메커니즘입니다 — 슬립이 커지면 바퀴가 토양을
    배출하며 더 깊이 침하하고, 침하가 깊어지면 주행 저항이 늘어 다시 슬립이 커집니다.
    **본 과제의 주요 응용이 이 되먹임 위에 성립하므로, 이 항목 없이는 모델을 완성해도
    해당 거동에 사용할 수 없습니다.**

    **반복 통과 누적을 함께 다루는 이유**도 같습니다. 현행 규칙은 같은 셀의 2회차
    기여를 1 %로 감쇠시켜, **제자리 슬립 상황에서 누적이 즉시 소멸**합니다. 누적
    규칙을 그대로 두면 slip-sinkage를 도입해도 무력화됩니다.

### 4.2 견인 (Traction)

| WP | 내용 | 선행 |
|---|---|---|
| **WP6** | **솔버 활성화 및 결함 정정** — 루프 연계 · 힘 중복 적용 제거 · **중력 상수 하드코딩 정정** · **`wheel_base` 인자 의미 확정** · `WIP` 구간 정리 | — |
| **WP7** | **그라우저 전단 모델 도입** — 그라우저가 전단면을 림 표면에서 토양 내부로 이동시키는 효과를 모델에 반영 | WP6 |
| **WP8** | **대상 로버 제원 반영** — 질량·휠 반경·휠 폭·그라우저 제원을 자산 실측값으로 | WP6 |
| **WP9** | **월면토 계수 확보 및 반영** — 문헌값으로 선구현 후 실측값으로 보정 | 실측 반영 시 **토질·주행 시험 자료** |

!!! warning "WP6에 포함된 두 가지는 그대로 두면 WP9를 무의미하게 만듭니다"
    **① 중력 상수가 지구 기준으로 고정되어 있습니다.** 최대 정상응력 산출식에 중력
    가속도가 **9.81 m/s²로 하드코딩**되어 있습니다. 달 중력은 1.62 m/s²이므로, 토양
    계수를 정확히 확보해 입력해도 지지 응력이 약 **6배** 어긋납니다.

    **② `wheel_base` 인자는 축거가 아니라 Bekker 식의 접지 폭 `b`입니다.**
    `(r/b)^n` 형태로 사용됩니다. 명칭만 보고 본 과제 로버의 축거 **1.4910 m**를
    입력하면 값이 조용히 어긋납니다 — 입력해야 하는 값은 휠 폭 **0.159 m**입니다.

!!! info "WP7 — 시험 자료 요청과 모델의 정합"
    현재 솔버에는 그라우저 관련 파라미터가 **선언만 되어 있고 계산에 사용되지
    않습니다.** 그라우저는 전단 파괴면을 휠–토양 계면에서 **토양 내부**로 옮겨 견인력을
    크게 변화시키므로, 이 항이 없으면 그라우저 조건이 맞는 시험 자료를 확보해도
    **반영할 자리가 없습니다.** 자료 요청과 모델 범위를 일치시키기 위한 항목입니다.

### 4.3 연성 및 검증

| WP | 내용 | 선행 |
|---|---|---|
| **WP10** | **침하–견인 양방향 연성 통합** — 침하량을 솔버 입력으로 연결(WP3의 슬립→침하와 합쳐 되먹임 성립). **본 과제의 핵심** | WP3·WP4·WP6·WP8 |
| **WP11** | **연산 성능 개선** — 변경 셀만 갱신하는 부분 갱신 도입 또는 갱신 주기 분리. 현재는 40개 셀 변경을 위해 정점 배열 전체를 매 스텝 재기록 | WP10 |
| **WP12** | **실측 기반 검증** — Slip–Drawbar Pull 곡선 및 바퀴자국(깊이·폭·단면) 대조 | WP10 · **토질·주행 시험 자료** |

!!! danger "WP12가 과제 성과의 성격을 결정합니다"
    나머지 작업이 완료되어도 **대조할 실측 자료가 없으면**, 「수치는 산출되나 근거가
    확보되지 않은」 상태가 반복됩니다. 이번 분석에서 확인된 원인 2번(3절)이 정확히
    그 사례이며, 본 과제를 제안하는 이유이기도 합니다.

    **월면토 시뮬런트 시험 자료 확보를 과제 범위에 포함**해 주시기를 요청드립니다.
    필요 항목은 특성별로 시험 방법이 다릅니다.

| 구분 | 필요 계수 | 확보 방법 |
|---|---|---|
| 지지 특성 | `k_c`, `k_φ`, `n` (압력–침하) | **Bevameter 관입 시험** |
| 전단 특성 | `c`(점착력), `φ`(내부마찰각), `K`(전단변형계수) | **직접전단 / Bevameter 전단 시험** |
| 차륜–토양 상호작용 계수 | `a₀`, `a₁` (최대응력각), 필요 시 `θ_r` 관련 계수 | **단일 휠 주행시험 및 Slip–Drawbar Pull 데이터 기반 식별** |
| **슬립–침하 특성** | 슬립비별 침하 증분 | **단일 휠 주행시험 — 슬립 제어 조건별 침하 계측** |
| 토양 상태 | `ρ` (다짐도별 밀도) | 상대밀도 시험 |
| 조건 명세 | 시뮬런트 종류(JSC-1A·KLS-1 등)·입도·하중 범위 | — |

!!! note "차륜–토양 상호작용 계수는 토양 고유값이 아닙니다"
    최대 정상응력 위치는 통상 `θ_m = (a₀ + a₁·s)·θ_f` 형태로 표현되며, `a₀`·`a₁`은
    **휠–토양 상호작용에 대한 경험적 파라미터**입니다. 압력–침하 시험만으로 확보되는
    토양 고유계수가 아니므로 **단일 휠 주행시험 결과로 식별**해야 합니다. 지지·전단
    특성과 시험 항목을 분리한 이유입니다.

**그라우저 조건이 일치해야 합니다** — 본 과제 휠은 그라우저 24개, 높이 19.1 mm입니다.
평활 휠 기준 시험 자료만으로는 전단 거동이 정합하지 않습니다.

### 5.2 지표 정의

목표치와 별개로, **측정 정의는 착수 시점에 확정합니다.** 정의가 모호하면 값이 나와도
합격 여부를 다툴 수 있기 때문입니다.

| # | 측정 정의 |
|---|---|
| 1 | 동일 수직하중·동일 슬립 조건에서 **자국 최대 깊이**의 상대오차. 하중은 정적 휠 하중의 0.5·1.0·1.5배 3점 |
| 2 | 자국 **횡단면 프로파일**을 자국 폭으로 정규화한 뒤의 RMSE |
| 3 | 슬립비 0–60 % 구간에서 **Drawbar Pull 곡선의 RMSE**를 최대 견인력으로 정규화 |
| 4 | 네 휠 추정 수직하중 합 대 정적 자중(729.0 N)의 상대오차 |
| 5 | 휠별 추정 하중 대 **기준 정적 배분값**의 최대 상대오차 |
| 6 | 주행 중 휠 하중 시계열 대 Reference의 RMSE (Reference 확보 후 정의 확정) |
| 7 | 침하량 변화가 견인력에 반영되는지 · 슬립 변화가 침하량에 반영되는지 **각각 성립/미성립** |
| 8 | 모델 적용 전후 시뮬레이션 시간 배율(RTF)의 상대 저하율 |
| 9 | 12축 계약·기구학 회귀 중 **기하에만 의존하는 항목**의 통과 여부 |

!!! note "지표 9에 단서를 두는 이유"
    12축 계약·기구학 회귀는 **기하(치수·조인트 한계·좌표 규약)만 사용**하므로 토양
    모델을 넣어도 값이 바뀌지 않아야 하며, 바뀐다면 결함입니다.

    반면 **슬립·견인력·주행 거리처럼 토양에 의존하는 기대값은 바뀌는 것이 정상입니다.**
    이를 구분하지 않고 「전 항목 통과」로 두면, 모델이 제대로 동작할수록 실패하는
    지표가 됩니다. 착수 시 회귀 항목을 **기하 의존 / 토양 의존**으로 분류하고, 후자는
    Baseline을 다시 취득합니다.

### 5.3 지표 1·2·3·6의 목표치를 현 시점에 확정하지 않는 이유

!!! warning "의도적으로 유보합니다"
    대조 시험 자료를 확보하기 전에 「재현오차 ≤ 20 %」와 같은 수치를 명시하는 것은
    **근거가 확보되지 않은 목표치를 추가하는 것**이며, 본 과제가 해결하려는 문제
    (3절 원인 2번, 힘–침하 계수의 출처 미확인)와 **동일한 성격의 오류**입니다.

    해당 지표는 **WP9·WP12 자료 확보 시점에 시험 산포를 근거로 확정**하고, 확정 시 그
    근거를 함께 기록합니다. **착수 전 평가 기준 확정이 필요한 경우 사전에 알려 주시면**
    문헌값을 잠정 기준으로 설정하되 잠정임을 명시하는 방식으로 조정하겠습니다.

지표 4·5·8·9는 기준이 외부 자료가 아닌 **내부 측정값**이므로 현 시점에 확정
가능합니다 — 정적 자중 729.0 N(450 kg × 1.62 m/s²), 침하 모델 단독 연산부하 실측치,
기존 회귀 항목.

**지표 5를 4와 분리한 이유**는 총합 일치가 분배 정확성을 보장하지 않기 때문입니다.
예를 들어 좌전륜 +30 %, 우전륜 −20 %인 경우에도 총합은 일치할 수 있습니다. 이 지표는
WP1(4절 링크 기구학 기반 휠 하중 역산)과 직접 연결됩니다.

**지표 7은 수치가 아닌 성립 여부**이며, **양방향을 각각 판정**합니다. 현재는 침하량이
견인 산출에 0으로 입력되고 슬립이 침하 산출에 들어가지 않으므로 **양방향 모두
미성립**입니다. 이 항목이 본 과제의 핵심을 가장 간결하게 나타냅니다.

### 5.4 HILS 실시간성에 대한 구분

!!! info "연산부하 목표와 실시간화 목표를 분리합니다"
    현재 플랜트는 실시간 대비 **약 0.5배 속도**로 동작합니다. 물리 적분 주기와 실시간
    페이싱 설정이 상이한 데서 기인하며, 본 과제 이전부터 존재하는 별도 사안입니다.

    | 구분 | 목표 | 범위 |
    |---|---|---|
    | **모델 추가 연산부하** | 침하–견인 모델 적용에 따른 **RTF 상대 저하 ≤ 20 %** | **본 과제** |
    | **HILS 실시간화** | 최종 통합 플랜트 **RTF ≥ 1.0** | **연계 과제** |

    본 과제에서는 물리 모델 추가에 따른 연산부하를 **≤ 20 %로 제한**하며, 전체 플랜트의
    **RTF ≥ 1.0 확보는 HILS 실시간화 과제와 연계하여 추진**합니다. 실시간화에는 계산
    자원 증설 또는 솔버 구성 변경이 필요하며, 계측 결과 현 하드웨어에서는 접지 정합성을
    유지한 채 실시간을 달성할 수 없음을 확인하였습니다.

    본 과제의 모든 계측은 **시뮬레이션 시간 기준**으로 수행하므로, 실시간 배율은 모델
    검증 결과에 영향을 주지 않습니다.

## 6. 추진 단계

WP 간 선행 관계에 따른 구성입니다. 월 배분은 **12개월 기준**이며, 시험 자료 확보
시점에 따라 3단계가 이동합니다.

| 단계 | 기간(가정) | 내용 | 산출 | 외부 의존 |
|---|---|---|---|---|
| **1단계** 기반 정비 | M1–M4 | WP1 하중 계측 · WP5 초기 조건 · WP6 솔버 활성화·결함 정정 · WP8 제원 반영 | 검증된 하중 신호, 정상 동작 솔버 | 없음 |
| **2단계** 연성 모델 수립 | M3–M9 | WP2 힘–침하 · WP3 슬립–침하·누적 · WP4 접지 형상 · WP7 그라우저 전단 · **WP10 양방향 연성 통합** | 연성 모델 초판 (문헌값 기반) | 없음 |
| **3단계** 정합·검증 | M7–M12 | WP9 계수 실측 반영 · WP11 성능 · **WP12 검증** | 검증된 모델, 지표 1·2·3·6 확정 | **토질·주행 시험 자료** |

!!! info "1·2단계는 외부 자료 없이 수행 가능합니다"
    토질 시험 자료 확보가 지연되어도 **1·2단계는 진행됩니다.** 하중 계측 경로 전환과
    두 모델의 양방향 연계는 내부 작업이며, 토양 계수는 문헌값으로 선구현합니다(WP9).

    다만 **3단계 없이는 「검증된 모델」이 성립하지 않습니다.** 자료 확보 시점이 과제
    성과의 성격을 결정합니다 — 「문헌 기반 정식화」에 머무를지, 「실측 검증 모델」이
    될지의 차이입니다.

### 6.1 위험 및 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| **토질·주행 시험 자료 미확보** | WP9·WP12 불성립. 결과물이 「문헌 기반 정식화」에 머무름 | 문헌값(Apollo 토질 자료·시뮬런트 공개 물성)으로 선구현하고 **잠정임을 명시**. 자료 확보 시 재적합 |
| 상류(OmniLRS) 코드가 예상보다 미성숙 | WP6·WP7 공수 증가, 수리보다 재작성이 필요할 수 있음 | 1단계에서 **수리/대체를 판정**하고 판단 근거를 기록. 인터페이스를 우리 쪽에 두어 교체 가능하게 설계 |
| 연산부하가 20 %를 초과 | 실시간성이 더 악화 | WP11을 2단계로 앞당기고, 갱신 주기 분리(물리 매 스텝 / 지형 N 스텝)로 절충 |
| 모델 도입으로 기존 회귀가 실패 | 회귀가 방어선 역할을 못 함 | 지표 9 정의대로 **기하 의존 / 토양 의존을 분류**하고 후자는 Baseline 재취득 |
| 시뮬런트–실제 레골리스 차이 | 검증했더라도 실물 적용 시 오차 | 8절에 범위를 명시. 시뮬런트 종류·조건을 결과와 함께 기록 |

## 7. 기대 효과

- **주행 성능 예측 근거 확보** — Slip–Drawbar Pull 곡선, 등판 한계, 주행 저항을 강체
  지형이 아닌 조건에서 산출
- **HILS 플랜트 충실도 향상** — 실물 제어기가 마주하는 부하 조건이 실제에 근접합니다.
  루프 내 실물 제어기라는 HILS의 이점이 **플랜트 물리 영역까지 확장**됩니다
- **크레이터 탈출 거동 연구의 전제 확보** — 슬립 증가 → 침하 증가 → 저항 증가의
  되먹임이 성립해야 탈출 거동을 다룰 수 있습니다(WP3·WP10)
- **반복 통과 영향 평가** — 같은 경로를 반복 주행할 때 누적되는 자국이 이후 주행에
  미치는 영향(WP3의 누적 규칙 재정립 범위)

## 8. 확인되지 않은 사항

!!! note "본 절을 함께 확인해 주십시오"
    본 과제로도 **확인할 수 없는 범위**입니다. 과제 종료 시 잔여 사항을 사전에
    명시합니다.

- **실제 월면 레골리스가 아닙니다.** 지상 시뮬런트 기준이며, 진공·정전기·입도 이력 등
  실제 레골리스의 조건은 재현하지 않습니다.
- **실물 로버 주행으로 검증하지 않습니다.** 검증은 시뮬레이터 내부에서, 문헌 및
  토질·주행 시험 자료와의 대조로 수행합니다.
- **토질·주행 시험 자료가 확보되지 않으면 WP12가 성립하지 않습니다.** 이 경우 결과물은
  「문헌 기반 정식화」까지이며, **검증된 모델로 제시할 수 없습니다.**
- **정량 지표 1·2·3·6은 목표치가 미확정 상태입니다**(5.3절). 대조 자료 확보 전 목표치
  설정은 본 과제가 해결하려는 문제를 반복하는 것이므로 의도적으로 유보하였습니다.
- **토양 다짐 이력은 모델링 범위에 포함하지 않습니다.** WP3에서 반복 통과 누적 규칙을
  재정립하나, 셀별 밀도 변화를 상태로 관리하는 본격적 다짐 모델은 범위 밖입니다.
- **플랜트 실시간화는 본 과제 범위가 아닙니다**(5.4절). 연계 과제로 추진합니다.
- 시뮬레이터 상류(OmniLRS) 구조 변경이 포함되어 포크 유지 부담이 증가합니다.

과제 착수 시 즉시 활용 가능한 상태로 정리되어 있습니다.

!!! tip "부수적 확인 사항"

    다만 접지 길이 자체의 근거가 확보되지 않아, 계수 치환만으로는 해결되지 않습니다(WP3).
