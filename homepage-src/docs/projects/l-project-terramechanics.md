# 달 탐사 로버 HILS 를 위한 월면토 침하·견인 통합 모델 고도화 개발

:material-circle:{ style="color:#f0ad4e" } **차년도 과제 제안** · 현대자동차 L-Project · 기준일 **2026-09-07**

!!! abstract "요약"
    실기 제어기가 루프 안에 있는 **HILS** 는 구축되어 동작 중입니다. 그런데 그 제어기가
    마주하는 플랜트는 **완전 강체 지형** 위에 있습니다. 월면토는 밟으면 꺼지고, 꺼진
    만큼 견인력이 달라지는데, 그 층이 비어 있습니다.

    관련 기능이 시뮬레이터(OmniLRS)에 **두 개** 들어 있습니다 — 바퀴자국을 그리는
    **침하(deformation) 엔진**과, 견인력·주행 저항을 계산하는 **견인(terramechanics)
    솔버**입니다. 실측해 보니 **전자는 아무 일도 하지 않고, 후자는 아예 꺼져 있으며,
    무엇보다 둘이 서로 연결되어 있지 않습니다.**

    이 둘을 **하나의 모델로 통합하고 실측으로 검증하는 것**을 차년도 과제로 제안합니다.

## 1. 왜 필요한가

달 탐사 로버의 주행 성능은 **토양이 어떻게 꺼지고, 꺼진 상태에서 얼마나 밀어주는가**로
결정됩니다. 아폴로·VIPER 기록이 공통으로 말하는 것이 이것입니다.

현재 저희 플랜트는 그 층이 없는 **단단한 달** 위에서 돕니다. 거기서 얻은 슬립·견인·
등판 한계·자세 수치는 전부 강체 지형의 값입니다. 차년도에 자율 주행이나 크레이터 탈출
거동을 다루려면 이 층을 먼저 세워야 합니다.

!!! info "지금이 착수 시점인 이유"
    2026-08-25 에 오래 미해결이던 계측 문제가 해소되면서 **현재 플랜트의 슬립이 사실상
    0 임을 확인**했습니다. 토양 모델을 넣었을 때 생기는 변화를 **깨끗하게 귀속시킬 수
    있는 기준선**이 이번에 처음 확보되었습니다. 기준선 없이 모델을 넣으면 무엇이 무엇
    때문에 바뀌었는지 구분할 수 없습니다.

## 2. 현재 상태 — 두 엔진이 있고, 둘 다 제 역할을 못 한다

### 2.1 침하 엔진 — 켜도 아무 일이 없고, 고치면 로버가 파묻힌다

기능을 실제로 켜고 로버를 몰면서 측정했습니다(2026-08-26). 같은 지령·같은 시간입니다.

| | 현행 설정 | 접지 폭만 실측 휠 폭으로 |
|---|---|---|
| **로버 이동 거리** | **12.156 m** | **0.054 m** |
| 지형에서 변한 격자 칸 | **0** | 40 → 49 |
| 최대 침하 | **0.000000 m** | 0.208 m |
| 연산 비용 | 30 → **26.5 Hz** (−12 %) | — |

현행 설정은 **비용만 지불하고 지형이 전혀 바뀌지 않습니다.** 근사적으로 0 이 아니라
정확히 0 이며 **오류도 나지 않아**, "켰다"고 믿는 상태가 됩니다. 접지 폭을 실측값으로
고치면 이번에는 로버가 **자기 구덩이를 파고 갇힙니다.**

### 2.2 견인 솔버 — 꺼져 있고, 켜도 다른 로봇을 계산한다

견인력(drawbar pull)·주행 저항·조향 저항 토크를 계산하는 솔버가 별도로 들어 있습니다.
Bekker–Wong 계열의 고전적 차륜–지반 모델입니다. 상태를 확인한 결과입니다.

| 확인 항목 | 상태 |
|---|---|
| 시뮬레이션 루프에서의 호출 | **주석 처리되어 실행되지 않음** |
| 코드 성숙도 | 클래스 설명 첫 줄이 **`WIP`** |
| 침하량 입력 | **0 으로 고정** — 침하 엔진과 연결되어 있지 않음 |
| 힘 적용 | 같은 힘을 **두 번 연속 적용** |
| 로버 제원 | **기본값** — 질량 20 kg, 휠 반경 0.09 m |
| 토양 계수 | **기본값** — 월면토 값이 아닌 일반값 |

!!! danger "제원이 맞지 않습니다"
    저희 로버는 **450 kg · 휠 반경 0.2133 m** 입니다. 솔버는 **20 kg · 0.09 m** 로
    생성되어 있습니다. 질량 **22.5 배**, 반경 **2.4 배** 차이입니다.

    즉 지금 이 솔버를 그대로 켜면, 로버의 주행 성능이 아니라 **전혀 다른 소형 로봇의
    값**이 로버에 외란으로 실립니다.

### 2.3 그래서 로버는 토양 반력을 전혀 받지 않는다

정리하면 이렇습니다.

| | 무엇을 하는가 | 지금 상태 |
|---|---|---|
| 침하 엔진 | 지형의 **모양**을 바꾼다 (바퀴자국) | 켤 수 있으나 결과가 0 |
| 견인 솔버 | 로버가 받는 **힘**을 바꾼다 (견인·저항) | 실행되지 않음 |
| **둘의 연결** | 꺼진 만큼 견인이 달라져야 한다 | **연결 없음** |

**바퀴자국이 생겨도 주행은 바뀌지 않고, 힘을 계산해도 침하를 모릅니다.** 이 둘을 잇는
것이 이 과제에서 말하는 **「통합」** 입니다.

## 3. 막는 원인 — 특정되어 있다

추정이 아니라 계측 결과입니다. 지형이 안 변하는 이유는 세 갈래(접지력 없음 · 침하량 0 ·
좌표 범위 밖)인데 **겉으로는 모두 똑같이 보이기 때문에**, 세 값을 한 기록에 함께 남기는
도구를 만들어 갈랐습니다.

| # | 원인 | 근거 |
|---|---|---|
| ① | 접지 폭이 격자 두 칸보다 좁아 분포가 전부 0 | 접지력이 **최대 907 N** 으로 충분히 들어오는데 침하가 0 |
| ② | **힘–침하 관계식의 출처가 없다** | 어떤 토양·휠·중력에서 맞춘 계수인지 자료가 없고, 접촉력 0 에서도 침하가 나오는 형태 |
| ③ | 정지 시 접지력이 **0 으로 읽혀** 침하가 하중이 아니라 **충격**에 비례 | 실제 바퀴자국과 반대 |
| ④ | **스폰 낙하 충격이 지형에 새겨짐** | 주행 전에 이미 **21 cm** 깊이가 생김 |
| ⑤ | 견인 솔버가 **침하량을 0 으로 받음** | 두 엔진 사이에 연결이 없음 |
| ⑥ | 솔버의 로버·토양 제원이 **기본값** | 20 kg / 0.09 m / 비월면토 계수 |

③ 에 대해서는 **대체 계측 경로를 이미 확인**했습니다. 접지력이 0 으로 읽히는 바로 그
상태에서 서스펜션 하중 신호는 살아 있었고(표준편차 0.000), 네 바퀴 합이 **기대 자중의
1.08 배**로 나왔습니다.

!!! warning "다만 정확히 해 둡니다"
    위 1.08 배는 **정보가 존재한다는 근거**이지 환산식이 완성되었다는 뜻이 아닙니다.
    좌우 부호가 갈리므로 서스펜션 4절 링크 기구학을 거쳐야 실제 바퀴 하중이 됩니다.

## 4. 제안하는 작업 범위

### 4.1 침하 (Sinkage)

| WP | 내용 | 선행 |
|---|---|---|
| **WP1** | **하중 계측 경로 교체** — 접지력 대신 서스펜션 하중에서 역산. 4절 링크 기구학 반영 | — |
| **WP2** | **힘–침하 관계 재수립** — Bekker 압력–침하 이론 기반 재정식화. 달 중력·그라우저 휠 조건 명시 | WP1 |
| **WP3** | **접지 형상 산정** — 폭·길이를 접지 역학에서 결정. 길이는 침하량의 함수라 상수로 둘 수 없음 | WP2 |
| **WP4** | **시작 조건 정비** — 낙하·안착 종료 후 변형 개시 | — |

### 4.2 견인 (Traction)

| WP | 내용 | 선행 |
|---|---|---|
| **WP5** | **솔버 활성화 및 결함 정정** — 루프 연결, 이중 적용 제거, `WIP` 구간 정리 | — |
| **WP6** | **로버 제원 반영** — 질량·휠 반경·휠 폭·그라우저 높이를 자산 실측값으로 | — |
| **WP7** | **월면토 계수 확보** — Bekker–Wong 지지·전단 계수 | **토질 시험 자료** |

### 4.3 통합 및 검증

| WP | 내용 | 선행 |
|---|---|---|
| **WP8** | **침하 ↔ 견인 연결** — 계산된 침하량을 솔버 입력으로. **이 과제의 핵심** | WP2·WP5 |
| **WP9** | **연산 성능** — 현재 40 칸을 바꾸려 정점 배열 전체를 매 스텝 다시 씀 | — |
| **WP10** | **검증** — 슬립–견인력 곡선 및 바퀴자국(깊이·폭·형상)을 실측과 대조 | **토질 시험 자료** |

!!! danger "WP7·WP10 이 이 과제의 성패를 가릅니다"
    나머지가 모두 끝나도 **비교할 실측 자료가 없으면**, 「수치는 나오는데 근거가 없는」
    상태가 하나 더 생길 뿐입니다. 이번 분석에서 확인된 원인 ② 가 정확히 그 모양이었고,
    그것이 이 과제를 제안하는 이유이기도 합니다.

    **월면토 시뮬런트 시험 자료 확보를 과제 범위에 포함**해 주시기를 요청드립니다.
    필요한 항목은 아래와 같습니다.

| 구분 | 필요한 값 | 통상 시험 |
|---|---|---|
| 지지 특성 | `k_c`, `k_φ`, `n` (압력–침하) | Bevameter 관입 시험 |
| 전단 특성 | `c`(점착력), `φ`(내부마찰각), `K`(전단변형계수) | 직접전단 · Bevameter 전단 |
| 밀도 | `ρ` (다짐도별) | 상대밀도 시험 |
| 응력분포 계수 | `a_0`, `a_1` (최대응력각) | 위 시험자료에서 적합 |
| 조건 | 시뮬런트 종류(JSC-1A·KLS-1 등)·입도·하중 범위 | — |

**그라우저 휠 조건이 맞아야 합니다** — 저희 휠은 그라우저 24 개, 높이 19.1 mm 입니다.
평활 휠 시험 자료만으로는 전단 거동이 맞지 않습니다.

## 5. 기대 효과

- **주행 성능 예측의 근거 확보** — 슬립–견인력 곡선, 등판 한계, 주행 저항을 강체 지형이
  아닌 조건에서 산출
- **HILS 플랜트 충실도 향상** — 실기 제어기가 마주하는 부하 조건이 실제에 가까워집니다.
  루프 안에 실 제어기가 있다는 HILS 의 이점이 **플랜트 물리까지 확장**됩니다
- **크레이터 탈출 거동 연구의 전제** — 탈출은 토양이 무너지는 거동에 크게 좌우되므로,
  강체 지형에서 얻은 결과는 실기로 옮기기 어렵습니다
- **누적 주행 영향 평가** — 반복 통과로 다져진 자국이 이후 주행에 미치는 영향

## 6. 확인되지 않은 것

!!! note "이 절을 함께 읽어 주십시오"
    아래는 이 과제로도 **확인할 수 없는 범위**입니다. 과제 종료 시 무엇이 남는지를
    미리 밝혀 둡니다.

- **실제 월면 레골리스가 아닙니다.** 지상 시뮬런트 기준이며, 진공·정전기·입도 이력 등
  실제 레골리스의 조건은 재현하지 않습니다.
- **실물 로버 주행으로 검증하지 않습니다.** 검증은 시뮬레이터 내부에서, 문헌 및 토질
  시험 자료와의 대조로만 수행합니다.
- **토질 시험 자료가 확보되지 않으면 WP7·WP10 이 성립하지 않습니다.** 그 경우 결과물은
  「문헌 기반 정식화」까지이며, **검증된 모델이라고 부를 수 없습니다.**
- **연산 시간 여유가 크지 않습니다.** 현재 플랜트는 실시간의 약 절반 속도로 동작하며,
  침하·견인 계산은 부하를 더합니다. 실시간성 확보는 별도 사안이나, 이 과제의 설계
  제약으로 작용합니다.
- 시뮬레이터 상류(OmniLRS) 구조 변경이 포함되어 포크 유지 부담이 늘어납니다.

## 7. 준비된 것

과제 착수 시 바로 사용할 수 있는 상태로 정리되어 있습니다.

| 항목 | 상태 |
|---|---|
| 원인 분석 문서 | 8 개 절, 상류 소스 결함 포함 |
| 계측 도구 | 접지력·침하·좌표·지형 변화·로버 이동을 **한 기록에** 남김 |
| 실동작 검증 원자료 | 2 조건, 호출 단위 기록 |
| 성능 측정 자료 | 4 조건(침하 ON/OFF × 정지/주행), 구간 분포 포함 |
| 로버 자산 실측 | 그라우저 **24 개** · 높이 19.1 mm · 휠 반경 0.2133 m · 질량 450 kg |
| 기준선 | 강체 지형 슬립 ≈ 0 (2026-08-25 확인) |

!!! tip "부수적으로 확인된 것"
    설정의 그라우저 관련 계수가 **13 개에 해당하는 값**으로 들어가 있었습니다. 자산에서
    실측한 그라우저는 **24 개**입니다. 다만 접지 길이 자체에 근거가 없어, 값만 바꾸는
    것으로는 해결되지 않습니다(WP3).
