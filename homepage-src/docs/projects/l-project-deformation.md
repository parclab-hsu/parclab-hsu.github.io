# OmniLRS 지형 변형 엔진 정밀 분석

:material-circle:{ style="color:#2e9e44" } **기술 분석 노트** · 현대자동차 L-Project · 기준일 **2026-09-14** (최초 2026-09-10)

!!! abstract "요약"
    달 탐사 로버 HILS의 플랜트(NVIDIA Isaac Sim + OmniLRS)에는 휠 통과에 따른 자국을 생성하는
    **지형 변형(Deformation/Sinkage) 엔진**이 포함되어 있습니다. 이 문서는 L-Project 설정을
    적용한 오프라인 계산과 **시뮬레이터 실행 중 계측 결과**를 정리합니다. 실물 로버·토양 시험 결과는 아닙니다.

    **최종 확인 상태(2026-09-14): 휠 주변에 1.5 cm 격자의 타일을 생성하고, asset에서 추출한
    휠 단면과 회전각을 반영해 24개 그라우저의 연속적인 자국을 표현합니다.** 주요 개선 이력은 다음과 같습니다.

    - **초기 설정에서는 변형량이 0이었습니다**(2절). 접지면 폭만 실제 휠 폭으로 변경하자
      과도한 침하가 발생했습니다(3절). 정지 상태의 접촉력이 0으로 계측되는 문제를 보완하기 위해
      하중 입력을 서스펜션 조인트 토크 기반 추정값으로 전환했습니다(4절).
    - **2026-09-11에 변형 기능을 활성화했습니다.** 접지 길이·그라우저 주기·하중–침하 회귀·안식각을
      설계 침하량 0.020 m 기준으로 조정하고, 초기 낙하 충격을 제외하도록 시작 지연을 늘렸습니다(11절).
    - **주행 중 물리 스텝이 중단되는 문제를 해결했습니다.** 변형 정점을 collision mesh에 기록하면서
      256만 정점의 충돌 데이터가 반복 재생성(re-cooking)되었습니다. 렌더 전용 메시를 분리한 뒤
      주행 RTF는 **0.008 → 0.22**로 개선되었고, 시험 구간에서 중단이 관측되지 않았습니다(12절).
    - **접지면 폭 설정의 이산화 오차를 보정했습니다.** 휠 폭 0.159 m를 입력해도 경계 표본의 깊이가
      0이 되어 실제 자국 폭은 0.10 m에 그쳤습니다. 설정을 0.21 m로 조정한 뒤 Isaac Sim 계측에서
      **0.155~0.158 m(휠 폭의 97~100 %)**를 확인했습니다(13절).
    - **자국의 연속성을 개선했습니다.** 최초 통과 하중에 깊이가 고정되는 문제에 하중 low-pass filter와
      최대 깊이 유지 규칙을 적용했습니다. 주행 경로를 따른 깊이의 변동계수는
      **0.74~0.88 → 0.27~0.37**로 감소했습니다(14절).
    - **하중–침하 관계를 비선형으로 변경했습니다.** 강체 휠의 Bekker 식에 n = 1을 적용해
      침하량이 **하중의 2/3제곱**에 비례하도록 했습니다. 하중이 두 배이면 침하량은 약 1.59배입니다(15절).
    - **고해상도 타일과 Fabric 갱신 경로를 도입했습니다.** 기존 5 cm 격자의 표현 한계와 전체 메시
      갱신 비용을 줄이기 위해 휠 주변의 1 m 타일만 갱신합니다. 주행 RTF **0.48~0.50**,
      자국 깊이 **24~27 mm**, 그라우저 주기 **55.8~56.4 mm**(휠 기하 기준 55.9 mm),
      자국 폭 **0.164 m**를 확인했습니다(16절). RTF가 약 0.5이므로 실시간 실행을 달성한 것은 아닙니다.

    **검증 한계:** 깊이는 토양 시험 자료가 아닌 목표값(Bekker 계산값 21.6 mm·Lunokhod 참고 범위
    21~24 mm)에 맞췄습니다. 둔덕 비율과 벽 경사는 추정값이며, **변형은 렌더 전용으로
    collision geometry와 휠–토양 상호작용에 반영되지 않습니다**(9절).
    파라미터 조정은 **17절**, 문제 원인과 개선 이력은 **18절**을 참조하십시오.

!!! info "문서의 기준 시점과 용어"
    이 문서의 실험·설정 기준일은 **2026-09-14**, 문장·용어 정비일은 **2026-09-29**입니다.
    2~8절은 초기 분석, 11~16절은 개선 과정, 17절은 최종 확인 설정을 설명합니다.
    초기 설정의 문제를 현재 구현의 미해결 문제로 해석하지 않도록 각 절의 기준일을 함께 확인하십시오.

    **실측·계측**은 별도 표시가 없으면 USD asset 분석 또는 시뮬레이터 내부 측정을 의미합니다.
    **Footprint**는 접지면 또는 엔진의 접지면 표본 영역, **collision mesh**는 물리 충돌 판정용 메시,
    **re-cooking**은 변경된 메시로부터 충돌 데이터를 다시 생성하는 과정입니다.
    **RTF(real-time factor)**는 simulation time 증가량을 wall-clock time 경과량으로 나눈 값입니다.

## 1. 지형 변형 기능과 적용 범위

로버 휠이 통과한 영역의 **DEM(Digital Elevation Model, 높이맵)을 갱신합니다.** 변경된 높이는 **렌더 전용 메시**에만
반영됩니다. 물리 충돌 메시는 유지되므로 **변형된 자국이 휠 접촉에 영향을 주지는 않습니다**(12절).

!!! info "2026-09-14부터 고해상도 타일 경로 적용"
    아래 그림은 0.05 m 지형 격자를 갱신하는 **기존 경로**입니다. 최종 확인 설정에서는 휠 주변에 1.5 cm 타일을
    생성하고 휠 단면을 투영하는 경로(16절)가 자국을 생성합니다. 그림의 접지면·분포·회귀 계수는
    고해상도 경로를 비활성화할 때만 적용됩니다(17절). 두 경로 모두 **물리 충돌 메시는 갱신하지 않습니다.**

!!! note "정정 (2026-09-11 · 2026-09-14)"
    이 절에는 원래 "PhysX 콜라이더가 그 DEM에서 다시 생성되므로 파인 자국이 이후 주행에
    영향을 준다"고 기술했으나, 소스 분석과 실행 시험으로 해당 설명을 정정했습니다. 이후의
    "콜라이더는 그대로다"라는 설명도 불완전했습니다. 정점을 갱신하던 대상이 **충돌 속성이 적용된
    메시**였기 때문에, 반복적인 re-cooking으로 물리 스텝이 중단되었습니다(12절).
    이후 렌더 메시와 collision mesh를 분리해 변형 시 충돌 데이터를 갱신하지 않도록 수정했습니다.

``` mermaid
flowchart LR
    A["휠 링크 4개<br/>월드 포즈"] --> C["접지면 격자를<br/>월드 좌표로 투영"]
    B["하중<br/>(서스펜션 토크,<br/>0.3 s 저역통과)"] --> D["하중 → 침하 깊이<br/>회귀"]
    C --> E["DEM[y, x] =<br/>가장 깊은 값"]
    D --> E
    E --> F["렌더 전용 메시 갱신<br/>(바뀐 경우만)"]
    E -.->|"충돌 메시는 그대로"| G["PhysX 지형 충돌"]
```

참조점은 **휠 링크의 월드 원점(x, y)** 이고 방향은 **쿼터니언에서 추출한 yaw**입니다.
따라서 조향은 반영되지만 **z·roll·pitch는 계산에서 제외됩니다.** 경사면에서도 접지면이
지형의 기울기를 따르지 않고 수평 격자에 투영됩니다. 이 설명은 기존 0.05 m 경로를 기준으로 합니다.

## 2. 초기 설정의 변형 미발생 원인 (2026-08-25) { #2-0 }

초기 설정에서 `enable: True`로 변경해도 **지형 변형이 발생하지
않았으며 오류도 보고되지 않았습니다.**

!!! warning "시뮬레이터 실행 시험 결과 (2026-08-25)"
    변형 기능을 활성화한 상태에서 실행 시험을 수행했습니다. **새 지형에서 12.156 m를 주행했지만
    갱신된 격자 셀은 0개였습니다.** 접촉력 입력이 최대 **907 N**에 도달했음에도
    변형 깊이는 0이었습니다. 원인은 하중 입력이나 좌표 변환이 아닌 **경계 분포의 표본화**로 확인했습니다.

### 원인: 접지면 폭과 격자 해상도의 불일치

```
지형 해상도    0.05 m/px
접지면 폭      0.09 m   →  int(0.09/0.05)+1 = 2 점
접지면 길이    0.20 m   →  int(0.20/0.05)+1 = 5 점
```

경계 분포(안식각) 함수는 **가장자리에서 정확히 0**, 안쪽에서 −1입니다. 그런데 폭에
2점만 잡히면 그 둘이 **모두 가장자리**(`y = −1`, `+1`)가 되어 `boundary = [0, 0]` 이고,
최종 깊이가 `boundary × (…)` 이므로 **전부 0** 입니다.

| 접지면 폭 | 격자 표본 수 | 경계 분포 | 결과 |
|---|---|---|---|
| **0.090 m (초기 설정)** | 2 | `[0, 0]` | **변형 없음** |
| 0.100 m | 3 | `[0, −1, 0]` | 발생 |
| **0.159 m (실제 휠 폭)** | 4 | `[0, −1, −1, 0]` | 발생 |
| 0.200 m | 5 | `[0, −0.87, −1, −0.87, 0]` | 발생 |

이 표본화·경계 분포 방식에서는 폭이 `2 × 지형해상도`(= 0.10 m)보다 작을 때 변형량이 **0**이 됩니다.

대상 휠의 asset 측정 폭은 **0.159 m**이며, 초기 설정 0.09 m는 그 **57 %**입니다.
0.09 m의 선정 근거는 확인되지 않았으며, OmniLRS 예제값을 유지한 것으로 추정합니다.

!!! note "안식각 조정만으로는 변형 미발생을 해소할 수 없습니다"
    폭이 2점이면 두 표본점이 모두 가장자리이고 거기서 식이 정확히 0이므로,
    **안식각 값과 무관하게 0**입니다. 표본 수를 3개 이상 확보하도록 폭 또는 해상도를 조정하거나
    표본화 방식을 변경해야 합니다.

## 3. 접지면 폭 변경 후 과도한 침하 발생

초기 회귀 계수를 유지한 채 `width: 0.159`로 변경하면 변형이 발생하지만 침하량이 과도하게 계산됩니다.

| 하중 | 접촉력 | DEM 변화 | 휠 반경(0.2133 m) 대비 |
|---|---|---|---|
| 무하중 | 0 N | −0.0053 m | 2 % |
| **정상** | **182 N** (450 kg × 1.62 m/s² ÷ 4) | **−0.0946 m** | **44 %** |
| 2배 | 365 N | −0.1839 m | 86 % |

**기준 하중에서 침하량이 휠 반경의 44 %에 달합니다.** 동일한 명령·시간 조건의 실행 시험에서 이동 거리는
기존 설정 **12.156 m**, 폭 변경 설정 **0.054 m**였습니다. 과도한 지형 변형과 주행 정체가 관측되었습니다.

또한 회귀식의 절편이 0이 아니므로 **무하중에서도 5.3 mm의 침하가 계산됩니다.**

```
amplitude = 0.00006·F + 0.008     ← F = 0 에서 0.008
mean      = −0.00046·F − 0.0013   ← F = 0 에서 −0.0013
```

무하중에서 침하가 계산되는 결과는 **회귀식의 적용 범위를 벗어난 외삽에서 물리적으로 타당하지
않은 값이 발생할 수 있음**을 보여줍니다. 네 회귀 계수의 **토양·휠·중력 조건과 교정 자료**는
OmniLRS upstream 문서와 프로젝트 설정에서 확인하지 못했습니다.

## 4. 정지 접촉력의 계측 한계와 하중 입력 전환 { #4-0 }

실행 시험에서 **PhysX 접촉력 조회값이 정지·안착 상태에서
4륜 모두 0으로 읽힙니다**(1,680회 연속 확인). 움직이거나 충격이 있을 때만 수백 N이
나옵니다.

!!! danger "정적 하중 대신 과도 접촉력이 침하량을 결정하는 문제"
    정지 상태에서는 변형이 없고 충격이 발생할 때 침하량이 증가했습니다. **접지면 폭 보정만으로 해결되지 않는 문제**입니다.

### 서스펜션 조인트 토크 기반 수직 하중 추정 (2026-09-09)

서스펜션 조인트 토크는 **정지 상태에서도 계측되며 명령에 따라 변화합니다.** 조인트 축이
차량 종축(x)이므로, 수직력에 의한 해당 축 토크는 접지점까지의 **y 오프셋**으로 계산합니다.

```
F = (0, 0, −N),  r = 접지점 − 조인트 원점
(r × F)_x = −N · r_y      →      N = |τ| / |Δy|
```

레버 암은 하드코딩하지 않고 **URDF 체인에서 회전까지 합성해 계산**합니다. 중간에
0.1745 rad 회전이 있어 좌표를 단순히 더하면 5.7 mm 어긋나는데, 회전을 넣으면 휠 y가
**0.6433 m**로 계약 윤거의 절반인 **0.64335 m**와 일치합니다. 이를 좌표 변환의 교차 검증에 사용했습니다.
레버 암 **0.4908 m**.

| 확인 항목 | 접지력 (전) | 서스펜션 토크 (후) |
|---|---|---|
| 정지 상태 하중 | 0 N | **148.85 N** |
| 값이 있는 휠 수 | 0 / 4 | **4 / 4** |
| 폭 0.159에서 침하 | — | 0.0906 m |
| DEM 변화 격자 | 0 칸 | **40 칸** |
| 그때 로버 이동 거리 | — | **0.0 m** |

**정지 상태에서도 하중에 따른 변형이 발생함을 확인했습니다.** 이는 하중 입력 연결의 검증이며, 침하량의 물리적 정확성을 검증한 것은 아닙니다.

### 링크 구조에 따른 하중 추정 오차와 보정

지형 내 다섯 위치에서 측정한 네 휠의 추정 하중 합은 자중(729 N)의 **51.6 ~ 66.1 %**, 평균
**56.2 %** 입니다. 원인은 서스펜션이 **4절 평행링크**라는 데 있습니다 — 아래 팔이
**2력 부재(two-force member)**로 하중을 전달하지만 해당 축 토크는 거의 0입니다(계측값 0.004 N·m).
**Upper arm 토크만을 이용한 단순 환산으로는 전체 하중을 산정할 수 없습니다.**

이 구현에서는 미계측 하중 전달 경로의 영향을 **보정 계수 1.78**로 보완했습니다.
보정 후에도 **산포 ±18 %**가 남으므로, 평균 하중의 정합이 개별 자세의 정확성을 보장하지는 않습니다.

## 5. 접지면(Footprint) 형상과 이산화 오차 분석

휠 폭 0.159 m의 적용 타당성을 확인하기 위해 asset 메시를 분석했습니다. 그 결과
**유효 접지 폭과 길이는 침하량에 따라 달라집니다.** 아래 분석은 2026-09-10의 기존 0.05 m 경로를 기준으로 합니다.

접지 길이는 강체 휠 기하로 계산합니다 — 진입각 `θ_f = arccos(1 − z/R)` 의 현 길이이고,
이탈각을 진입각과 같다고 본 값입니다.

```
L = 2·√(2Rz − z²)          R = 0.2134 m (팁 반경 실측)
```

| 침하 z [m] | 걸리는 폭 [m] | 접지 길이 L [m] | 폭 격자점 | 길이 격자점 | `wave_frequency` |
|---|---|---|---|---|---|
| 0.0020 | **0.1297** | 0.0583 | 3 | 2 | 1.04 |
| 0.0050 | 0.1575 | 0.0918 | 4 | 2 | 1.64 |
| 0.0100 | 0.1589 | 0.1291 | 4 | 3 | 2.31 |
| 0.0200 | 0.1592 | 0.1804 | 4 | 4 | 3.23 |
| **0.0320** | 0.1592 | **0.2248** | 4 | 5 | 4.02 |
| **0.0500** | 0.1592 | **0.2745** | 4 | 6 | 4.91 |
| 0.0906 | 0.1592 | 0.3490 | 4 | 7 | 6.25 |

굵게 표시한 두 줄이 이 프로젝트의 실측 침하 범위입니다.

### 관측된 침하 범위에서의 휠 폭 근사 { #0159 }

**그라우저 tip 영역(반경 99~100 %)의 폭은 0.1297 m** 로 전체 폭보다 **18 % 좁습니다.**
그런데 침하가 **5 mm만 넘으면 0.1575 → 0.1592로 포화**합니다. 실제 침하 범위에서는
항상 전체 폭이 걸리므로 **휠 폭을 상수 0.159로 보는 것은 타당합니다** — Tip 영역의 폭이 좁은 영향은
첫 2 mm에서만 유효합니다.

!!! warning "정정 (2026-09-14): 휠 폭과 엔진 접지면 폭 설정의 구분"
    휠 폭 값 자체는 맞지만, 엔진은 접지면의 **양 끝 표본을 늘 깊이 0으로** 만듭니다.
    `footprint.width` 에 0.159를 넣으면 가운데 2칸 = **0.10 m(휠의 63 %)** 만 파입니다.
    기존 0.05 m 경로의 설정은 0.21 m로 조정해 유효 변형 폭 0.150 m를 확보했습니다(13절).

축방향 중심이 **−0.0031 m** 로 완전 대칭이 아닌 것도 확인했습니다. 접지면이 휠
중심선 기준으로 생성되므로 3 mm만큼 한쪽으로 치우칩니다 — 격자 0.05 m 대비 6 %라
기존 해상도에서는 영향이 작지만, 고해상도에서는 검토가 필요합니다.

### 침하에 따른 접지 길이 변화와 초기화 방식의 한계 { #_3 }

!!! danger "접지면은 초기화 때 한 번만 만들어집니다"
    접지면 생성 함수가 엔진 `__init__` 에서 한 번만 호출됩니다. **침하가 깊어져도
    접지면이 넓어지지 않습니다.** 접지 면적이 고정된 채 하중만 늘면
    **압력이 과대평가되는 방향**입니다.

초기 설정 0.200 m는 **침하 0.0249 m에 해당하는 길이**입니다. 실측 침하 범위
0.032~0.05 m에서는 0.225~0.275 m여야 하므로 **12~37 % 과소**입니다.

### 접지 길이와 그라우저 주기 설정의 불일치 { #_4 }

| 설정 항목 | 값 | 그 값이 가정하는 침하 | 그때의 접지 길이 |
|---|---|---|---|
| `footprint.height` | 0.200 | 0.0249 m | 0.200 m |
| `wave_frequency` | 4.14 | **0.0339 m** | **0.231 m** |

같은 접지면을 두 곳에서 다르게 가정하고 있습니다 — 길이 기준 **15.6 % 차이**입니다.
`wave_frequency` 를 3.58(길이 0.200 기준)로 맞추면 최소한 서로 모순이지는 않게 되지만,
이는 **파라미터 간 일관성을 확보하는 조치**입니다. 접지 길이의 물리적 타당성을 확보하려면 침하량을
반영해 길이를 갱신해야 합니다.

### 초기 접지면 면적비와 격자 표본화의 영향 { #4656 }

설정한 폭·길이와 함께 **DEM 셀에 매핑되는 면적**을 확인해야 합니다.
엔진은 접지면 표본점을 `int(좌표/해상도)` 로 격자 셀에 매핑하므로, 설정값이 아니라
**이산화 결과와 각 표본의 깊이**가 실제 변형 영역을 결정합니다.

접지면 생성이 `linspace(−w/2, w/2, int(w/res)+1)` 이라 **표본 간격이 지형 해상도와
다릅니다**(폭 0.159 → 4점, 간격 0.053). 그래서 셀이 겹치거나 건너뛰고,
**격자에 매핑된 면적이 설정값보다 커질 수 있습니다.**

| 설정 (폭 × 길이) | 표본점 | 매핑된 셀 | 덮는 폭 | 덮는 길이 | 매핑 면적 |
|---|---|---|---|---|---|
| **0.090 × 0.200 (초기 설정)** | 10 | 8.0 | **0.141** | 0.200 | 0.0200 m² |
| 0.159 × 0.200 | 20 | 16.0 | 0.210 | 0.200 | 0.0400 m² |
| 0.159 × 0.275 | 24 | 20.8 | 0.210 | 0.274 | 0.0519 m² |

셀 위상에 따라 달라지므로 무작위 위상 300~400회 평균입니다.
**초기 설정 폭 0.090 m의 표본이 매핑되는 셀의 폭은 평균 0.141 m로, 설정값의 1.57배입니다.**

실제 접지 면적은 침하 0.032 m에서 **0.0358 m²**, 0.050 m에서 **0.0437 m²** 입니다.

| 조건 | 기하 기준 대비 매핑 면적비 (z=0.032) | (z=0.050) |
|---|---|---|
| **초기 설정 0.090 × 0.200** | **56 %** | **46 %** |
| 폭·길이를 실제값으로, 해상도 0.05 | 114 % | 119 % |
| 폭·길이를 실제값으로, **해상도 0.025** | **99 %** | **101 %** |
| 〃 해상도 0.02 | 99 % | 96 % |

시험한 설정 중 해상도 0.025 m/px에서 면적비가 **99~101 %**로 계산되었습니다. 0.05 m/px에서는
폭·길이를 정확히 넣어도 이산화가 **14~19 % 과대**로 만듭니다 — 휠 폭 0.159가 격자
3.2칸이라 양자화 오차가 원리적으로 ±0.5칸(±15 %)이기 때문입니다.

!!! warning "정정 (2026-09-14) — 위 두 표는 깊이가 0인 표본까지 셌습니다"
    "매핑된 셀·덮는 폭"은 접지면 표본이 떨어지는 셀을 모두 센 값입니다. 그런데 엔진의 경계
    분포는 **양 끝 표본의 깊이를 늘 0으로** 만들어, 그 셀은 실제로는 파이지 않습니다.
    엔진으로 자국을 생성해 측정한 결과, 설정 폭 0.159 m의 실제 변형 폭은 **2칸 = 0.10 m**였습니다.
    따라서 비영(非零) 변형 영역은 휠 폭 대비 **37 % 작았습니다.** 유효 변형 셀 수는 「횡 표본 수 − 2」이며,
    접지면 폭 0.21에서 3칸 = 0.150 m가 됩니다(13절).

### 해상도 0.025 m에서 관측된 물리 스텝 중단 { #_5 }

변형이 비활성화된 시험에서는 해상도를 높여도 tick 29.959 Hz, RTF 0.4994로
기준 조건과 유사했습니다. 다만 기동 시간은 40 s에서 118 s로 증가했습니다.

| 조건 | tick | RTF |
|---|---|---|
| 0.05 · 변형 OFF | 29.96 Hz | 0.4994 |
| 0.05 · 변형 ON | 27.88 Hz | 0.4725 |
| 0.025 · 변형 OFF | 29.96 Hz | 0.4994 |
| **0.025 · 변형 ON** | **5.61 Hz** | **0.0000** |

!!! danger "물리 스텝 중단: simulation time이 3.8 s에서 정체"
    해당 구간에서도 관절 상태 토픽은 5.6 Hz로 계속 발행되었습니다(20초간 115건 수신, 스탬프는
    전부 3.8000). **메시지 수신 빈도만으로는 물리 시뮬레이션의 중단을 판별할 수 없습니다.**

물리 스텝 중단은 변형 함수가 **깊이가 0이든 아니든 매 스텝 정점 배열 전체를 다시 쓰는**
구조와 관련이 있습니다. 정점 수는 2.6 M에서 10.2 M으로 약 4배 증가했습니다. 이후 대조 시험에서 충돌 데이터의 반복 재생성이 물리 스텝 중단의 원인으로 확인되었습니다(12절).

따라서 당시 구현에서는 해상도 증가만으로 접지면 표현과 실행 성능을 함께 개선하기 어려웠습니다.
**렌더·충돌 경로를 분리하고 변경된 영역만 갱신하는 구조**가
필요했습니다.

|---|---|---|

휠 메시에서 실측했습니다 — 방위각 히스토그램의 이산 푸리에 변환으로 지배 주파수를

## 8. Traction solver 연결 및 실행 경로 검증 { #8 }

변형 엔진과 짝을 이루는 **Terramechanics 견인 솔버**도 같이 점검했습니다. 이 둘은
"지형의 모양을 바꾸는 쪽"과 "로버가 받는 힘을 바꾸는 쪽"으로 나뉘는데, 연결이
끊겨 있었습니다. (기준일 2026-09-10)

| | 결함 | 왜 드러나지 않았나 |
|---|---|---|
| ① | 호출부가 주석 처리 | 토양 반력이 누락되어도 시각적 이상이 뚜렷하지 않음 |
| ② | 기본 인자 **20 kg · 휠 반경 0.09 m** (실제 450 kg · 0.2133 m) | 실행 여부·대상 제원과의 대조가 누락됨 |
| ③ | 힘을 **2회 연속** 적용 | 연속된 중복 호출을 검출하지 못함 |
| ④ | 없는 API 호출(`get_velocities`) | 호출 경로가 비활성화되어 실행되지 않음 |
| ⑤ | 휠당 스칼라 자리에 (n,3) 월드 벡터 | 〃 |
| ⑥ | 수치적분 결과를 **튜플째** 연산 | 힘 계산 세 함수가 **한 번도 실행된 적 없음** |
| ⑦ | 중력 **9.81 하드코딩** | 달 시뮬레이터에서 σ_max가 **약 6배** 과대 계산됨 |

일곱 건을 고쳐 연결한 뒤 실측하면 침하 0.032~0.05 m, 슬립비 0.846 → −0.189,
견인력 −48 ~ +4 N 범위에서 **해당 시험 구간에서 NaN 없이** 실행되었습니다.

!!! warning "다만 수직 반력은 더하지 않습니다"
    PhysX의 접촉 계산이 이미 수직 지지력을 제공합니다. Solver의 수직 반력을 추가하면
    **동일 지지력을 이중 계상**할 수 있으며, 검증되지 않은 계수는 과도한 수직 가속을 유발할 수 있습니다
    (σ_max 약 44 kPa → 휠당 1.5 kN 수준, 로버 자중 729 N). 이 구성에서 solver의 적용 대상은
    **견인력과 저항 토크**로 제한합니다.

## 9. 검증 범위와 한계

앞 절의 결과는 구현의 동작과 시뮬레이션 내 계측값을 확인한 것입니다. 물리적 정확성과 실물 적용 가능성에는 다음 한계가 있습니다.

- **토양 계수의 출처가 없습니다.** 깊이는 시험 자료가 아니라 **목표값**에 맞췄습니다 — 정지
  하중 182 N에서 약 20 mm(Bekker 21.6 mm · Lunokhod 21~24 mm 범위), 그 밖에서는 하중^(2/3).
  Bekker/Wong 계수 9개도 출처가 없습니다. **월면토 시험 자료 없이는 계산값의 정량적 정확성을 보장할 수 없습니다** —
  확인한 것은 경향과 연결 여부입니다.
- **실제 월면토로 검증한 것이 아닙니다.** 전부 시뮬레이션 내부 계측이며,
  시뮬런트(모사토) 시험도 아직 없습니다.
- **하중 추정의 산포가 ±18 %** 입니다(교정 계수 1.78). 이것이 주행 경로를 따른 깊이 변동으로
  남습니다 — 변동계수 0.25~0.30(16절).
- **둔덕·벽 경사는 추정입니다.** 옆으로 밀려난 흙의 비율(10 %)과 벽 임계각(60°)에는 정량
  문헌이 없고, 그라우저 자국 진폭(9~10 mm)은 단륜 시험의 6.09 mm보다 큽니다. 0.3 s보다 짧은
  충격은 자국에 남지 않습니다.
- **자국 변형은 collision geometry에 반영되지 않습니다**(12·16절). 반복 통과에 따른 침하와 slip–sinkage
  coupling을 물리 거동으로 검증하려면 변형 지형과 휠 접촉을 연결해야 합니다.
- **휠과 자국 바닥 사이가 몇 mm 어긋날 수 있습니다.** 자국은 렌더 지형을 기준으로 생성하지만 휠은
  근사된 충돌 메시 위에 서 있어, 휠 팁과 지형 사이가 직진 중 평균 6 mm · p95 15 mm 차이 납니다(16절).
- **경사면 처리를 확인하지 않았습니다.** 자국은 휠의 수평 방향(진행·차축)만 써서 수직으로
  투영하므로 경사면에서 오차가 발생할 수 있으나, 크기를 정량화하지 않았습니다.
- **제자리 선회·고슬립 조건의 자국 형상은 검증하지 않았습니다.** 검증 범위는 직진과 완만한 선회 구간입니다.
- **장거리 주행 시 타일과 정점 수가 누적됩니다.** 185만 정점에서 RTF 0.481을 확인했으며, 1 km 주행(약 600만 정점)은
  측정하지 않았습니다.
- *(0.05 m 경로에만 해당)* 자국 중심이 휠보다 안쪽으로 약 1.5 cm 치우쳤던 것(13절)과 접지면 면적
  면적비 재계산(5절)은 미확인 항목입니다. 최종 확인 설정에서는 16절 경로가 자국을 생성합니다.

## 12. Collision mesh re-cooking에 따른 물리 스텝 중단 (2026-09-14) { #12-2026-09-14 }

**증상:** 주행 명령에도 로버가 이동하지 않았습니다. 관절 상태 토픽은 24 Hz로 계속 발행되었으나

### 변형 기능 활성화·비활성화 대조 시험 { #_7 }

보드를 EPOS backend로 전환해 시뮬레이션 명령 발행을 중지하고, 구동 4축에 2.0 rad/s 명령을 직접 입력했습니다. RTF는 5 s 측정 구간마다 simulation timestamp 증가량을 wall-clock time 경과량으로 나누어 계산했습니다.

|---|---|---|---|

## 15. 하중–침하 비선형 관계 적용: 하중의 2/3제곱 (2026-09-14)

**문제:** 하중-깊이 회귀가 원점을 지나는 직선이라 하중이 두 배면 깊이도 두 배였습니다. 14절의
「주행 중 깊이가 1.4~1.7배」 가운데 일부가 이 선형성입니다 — 주행 중 크게 읽히는 하중 피크가 그대로
깊이에 실렸습니다.

**적용 모델:** 강체 휠의 Bekker 침하식은

```
z = [ 3W / ((3 − n)·(k_c + b·k_φ)·√D) ]^(2/(2n+1))      →      z ∝ W^(2/(2n+1))
```

이며, 달 표토 참고값(Lunar Sourcebook, Soil B) n = 1이면 **W^(2/3)** 관계를 얻습니다. 대상 휠(폭 0.159 m·
지름 0.427 m)과 하중 182 N의 계산값은 **21.6 mm**로, 11절의 설계값 0.020 m와 유사합니다.

**수정 내용:** 회귀에 넣기 전에 하중을 `F_ref · (F / F_ref)^(2/3)` 로 바꿉니다(F_ref = 182.2 N = 자중 ÷ 4).
기준하중에서는 값이 그대로라 11절 교정이 유지됩니다 — 182.2 N에서 0.0201 m 그대로, 364 N에서 **1.587배**
(선형이면 2배).

## 16. 휠 단면 기반 고해상도 타일 자국 생성 (2026-09-14) { #16-15-cm-2026-09-14 }

**도입 배경:** 0.05 m 격자에서는 휠 폭이 3칸이라 자국 단면이 V자가 되고, 그라우저 무늬(주기 약 56 mm)는
충분히 표현되지 않습니다. 해상도를 0.025 m로 올리면 시뮬레이션이 멈췄고(5절), 기존 0.05 m 해상도에서도 256만 정점
지형을 매번 갱신하면서 주행 중 RTF가 0.22로 제한되었습니다(12절). 80 × 80 m 지형 전체를 1.5 cm 격자로 구성하면 약 2,844만 정점(1 cm에서는 6,400만 정점)이 필요하므로,
전체 메시 갱신 방식은 연산·전송 부담이 큽니다. 설계 목표는 **해상도 1.5 cm·기존 자국 유지·휠 형상 기반 표현**으로 정했습니다.

  림 194.2 mm · 팁 213.3 mm · **직선 그라우저 24개 · 높이 19.1 mm** · 가장자리 플랜지 200.4 mm.
- **그라우저 위치는 휠 회전각을 따릅니다.** 그래서 자국 간격이 슬립 s에 따라 `55.9 mm × (1 − s)` 로 줄고,
  Slip이 커질수록 무늬가 중첩됩니다. 이 효과는 휠 회전각과 이동량의 기하 관계에서 발생합니다.
- **그라우저 형상 반영률** — 되메움 효과를 시각적으로 근사하기 위해 그라우저 높이 차의 40 %를 반영합니다. 제거된 토양의 10 %를 측면
  둔덕으로 재분배하는 것으로 가정하고, 자국 측벽의 경사가 60°를 넘으면 경사를 완화합니다. 이 비율과 임계각은 추정값입니다.
- **표시 지면 = 기준 렌더 지형 + 27 mm.** 휠은 유지된 collision mesh와 접촉하고 표시 지면은 위로 이동하므로, 그라우저 팁이 지면에 잠긴 형태로
  표현됩니다. 렌더 지형과 collision mesh의 근사 오차로 실제 표시 깊이는 달라질 수 있습니다.
- **생성된 타일을 유지해 이전 주행 자국을 보존합니다.** 타일 아래의 기존 지형 메시를 낮춰 중복 표시를 방지합니다.

### 반복 주행 대조 시험으로 확인한 두 가지 결함 { #_12 }

해당 시험에서는 초기 상태·장면·카메라·명령을 동일하게 유지해 자국을 비교했습니다. 모든 환경에서 결정성이 보장된다는 의미는 아닙니다.

1. **타일 경계의 밝은 선:** 기존 지형의 비표시 처리가 반영되지 않았다는 가설을 검토했습니다. 그러나 갱신
   경로(Fabric·USD)를 바꿔도 **동일한 현상**이 발생했고, 기록값을 다시 조회한 결과도 일치해 해당 가설을 배제했습니다. 원인은 경계
   첫 행의 정점을 0.2 m 낮추면서 형성된 급경사가 **보간된 vertex normal의 방향을 변화시킨 것**이었습니다.
   첫 행의 하강량을 2 mm로 제한한 뒤 밝은 선이 사라졌습니다.
2. **주행 경로를 따른 자국 깊이 변동(10~35 mm):** 휠의 물리 높이를 기준으로 자국을 생성했으나, collision mesh가 렌더 지형의
   근사이므로 휠 팁과 지형 사이에 직진 중 평균 6 mm·p95 15 mm의 간격이 발생했습니다(암석 위·선회 중에는 수백 mm). 하중에 따른 침하 보정량도
   ±16 mm 범위에서 변동했습니다. **렌더 지형 기준으로 자국을 생성하고, 지형과의 간격이 4 cm를 넘는 휠은 제외하며, 하중 침하량을 ±10 mm로
   제한한 뒤** 깊이 변동계수가 0.35~0.38에서 **0.25~0.30**으로 감소했습니다.

!!! note "추가 검증이 필요한 항목"
    - 잔여 깊이 변동의 주요 원인은 하중 추정 잡음입니다(서스펜션 토크 하중 산포 ±18 %).
    - 그라우저 자국 진폭 9~10 mm는 단륜 시험(6.09 mm)보다 큽니다.
    - 둔덕 비율과 벽 임계각은 정량 문헌이 없는 추정입니다.
    - **렌더 전용입니다.** 변형된 자국이 휠 접촉을 바꾸지 않으므로 자국에 의한 slip·견인 변화는 반영되지 않습니다.
    - 타일이 계속 남으므로 아주 긴 주행에서는 정점이 쌓입니다(1 km에 약 600만 정점 추정).

## 17. 파라미터 조정 가이드 (기준일 2026-09-14)

설정은 lunaryard 환경 설정의 `terrain_manager.moon_yard.deformation_engine` 아래에 있습니다.
각 파라미터의 적용 경로와 조정 영향을 정리했습니다. 표의 값은 **2026-09-14에 확인한 설정**입니다.

### 경로별 파라미터 적용 범위 { #_13 }

| 구분 | 적용 조건 |
|---|---|
| A. 공통 (활성화·지연·하중 입력) | 전체 변형 경로 |
| B. 0.05 m 지형 경로 (`footprint` · 분포 · 회귀) | `track_tiles.enable: False` 일 때만 |
| C. `track_tiles` (1.5 cm 자국, 16절) | **최종 확인 설정의 활성 경로** |

!!! warning "`track_tiles` 활성 상태에서는 B 경로의 파라미터가 자국에 적용되지 않습니다"
    B로 되돌리려면 `track_tiles.enable: False` 로 둡니다 — 이때 주행 RTF는 0.22로 떨어집니다(12절).

### A — 공통

| 파라미터 | 현재 | 의미 | 조정 시 |
|---|---|---|---|
| `enable` | True | 변형 전체 스위치 | False면 자국 없음 |
| `delay` | 10.0 s (시뮬레이션 시간) | 시작 후 변형 시작까지 | 짧으면 스폰 낙하 충격이 구덩이로 남습니다(2 s일 때 21 cm) |
| `force_source` | suspension | 휠 하중 입력 경로 | `contact` 는 정지 시 0으로 읽혀 **정적 하중보다 충격에 따른 변형이 지배적입니다**(4절) |
| `suspension_joints` | FL · FR · RL · RR | 하중 토크를 읽을 조인트 | **휠 링크 목록과 순서가 같아야 합니다** — 순서 불일치가 수치만으로 드러나지 않을 수 있습니다 |
| `suspension_lever_arm` | 0.4908 m | 토크–힘 환산용 lever arm | 로버 asset을 바꾸면 다시 계산 |
| `suspension_gain` | 1.78 | 4절 링크 보정(실측 교정) | 네 휠 합이 자중과 맞도록. 산포 ±18 % |
| `force_filter_tau` | 0.3 s | 하중 저역통과 | 증가 시 고주파 변동 억제·응답 지연 증가, 감소 시 하중 변동 반영 증가 |
| 지형 크기·해상도 | 야드 설정 참조 | 자동 | 직접 고치지 않습니다 — 해상도 0.025에서 멈췄습니다(5절) |

### C — `track_tiles`: 최종 확인된 1.5 cm 자국 생성 경로

```
표시 지면       = 지형 + surface_offset
휠 투영면     = 지형 + R + [원 + κ·(asset에서 추출한 휠 단면 − 원)] − δ
하중 침하 δ     = surface_offset · ((F / reference_load)^load_exponent − 1)
                  → [−max_less_sinkage, +max_extra_sinkage] 로 제한
```

그라우저 팁 깊이 ≈ `surface_offset + δ`, 그라우저 사이 둔턱은 ≈ `κ × 19.1 mm` 만큼 얕습니다.

**자국 형상과 시각적 표현**

| 파라미터 | 현재 | 의미 · 효과 |
|---|---|---|
| `surface_offset` | 0.027 m | 자국 깊이의 기준. **+1 mm → 평균 깊이 약 +1 mm**(오프라인 0.024 → 18.0 mm, 0.027 → 20.9 mm). 크게 하면 휠·암석이 묻혀 보입니다 |
| `grouser_transfer` (κ) | 0.40 | 그라우저 형상 반영률. **그라우저 무늬 깊이 ≈ κ × 19.1 mm**(0.35 → 6.7 · 0.40 → 7.7 · 0.45 → 8.6 mm, Isaac 실측 9~10 mm). 0 = 매끈한 홈, 1 = 휠 모양 그대로 |
| `berm_fraction` | 0.10 | 제거된 토양 중 측면 둔덕에 재분배하는 비율 — **정량 문헌 없는 추정**. 0.25면 둔덕 약 11 mm로 과했습니다. 0 = 둔덕 없음 |
| `berm_width` | 0.03 m | 둔덕 폭 |
| `critical_angle_deg` | 60 | 휠 밖 벽 최대 경사. 낮추면 완만한 V, 높이면 날카로운 벽 |
| `relax_iterations` | 2 | 벽 경사 완화 연산의 반복 횟수. 늘리면 임계각에 더 가깝게 수렴 |
| `wheel_profile` | 휠 단면 표 | **로버 asset 변경 시 휠 메시에서 다시 추출합니다** |

**하중 반응**

| 파라미터 | 현재 | 의미 · 효과 |
|---|---|---|
| `reference_load` | 182.2 N | 이 하중(자중 ÷ 4)에서 δ = 0 |
| `load_exponent` | 0.6667 | 깊이 ∝ 하중^p (Bekker n = 1, 15절). 1이면 선형 — 하중 피크에서 과대 |
| `max_extra_sinkage` / `max_less_sinkage` | 0.010 / 0.010 m | δ의 한계. 넓히면 하중 차가 더 드러나지만 **하중 추정 잡음에 따른 깊이 변동도 증가합니다**(±16 mm로 풀었을 때 변동계수 0.35~0.38) |

**높이 기준 · 예외**

| 파라미터 | 현재 | 의미 · 효과 |
|---|---|---|
| `height_reference` | terrain | `terrain` = 렌더 지형 기준(권장). `wheel` = 물리 휠 높이 기준 — 충돌 메시 근사 오차(평균 6 mm · p95 15 mm)가 그대로 깊이 변동이 됩니다 |
| `lift_threshold` | 0.04 m | 지형과의 간격이 이 값을 넘는 휠은 자국 생성에서 제외합니다. 감소 시 요철에서 자국이 단절될 수 있고, 증가 시 비접촉 휠의 자국이 생성될 수 있습니다 |

| 파라미터 | 현재 | 의미 · 효과 |

### B — 0.05 m 지형 경로 (`track_tiles` 를 끌 때만)

| 파라미터 | 현재 | 의미 |
|---|---|---|
| `footprint.width` | 0.21 | 횡 표본 수 = int(폭 / 0.05) + 1. **양 끝 표본은 늘 0**이라 파이는 칸 = 표본 − 2 → 0.21은 3칸(0.15 m) (13절) |
| `footprint.height` | 0.1804 | 접지 길이 L = 2√(2Rz − z²), z = 0.020 m |
| `wave_frequency` | 3.229 | **접지 길이 안의 그라우저 수** = N·L / (2πR). 한 바퀴 개수가 아닙니다 (6절) |
| `angle_of_repose` | 0.7854 (45°) | 가장자리 경사. 깊이를 최대 2.6배 좌우 |
| 회귀 기울기 · 절편 | 2.466×10⁻⁵ / −1.111×10⁻⁴ · 0 | 깊이 = 경계 × (진폭/2 × 파형 − 평균). 182.2 N에서 −0.0201 m. **절편은 0이어야 합니다** |
| `load_exponent` / `reference_load` | 0.6667 / 182.2 | 15절 |
| `accumulation` | max_depth | 같은 칸은 가장 깊은 값. `decay_sum` 일 때만 감쇠 비율을 씁니다 (14절) |

!!! warning "폭 · 안식각 · 회귀 기울기 · 길이 · `wave_frequency` 는 한 세트입니다"
    모두 침하 0.020 m를 가정합니다. 하나만 바꾸면 서로 어긋나므로 오프라인 재현 계산으로 다시 맞춥니다.
    설정에 있지만 **읽히지 않는 값**도 있습니다 — `gravity`, `footprint.shape`, `num_links` (6절).

### 파라미터 변경 및 검증 절차 { #_15 }

1. **설정 파일을 고치지 않고 시험** — 실행 명령에 Hydra override를 추가합니다.
   ```
   ++environment.terrain_manager.moon_yard.deformation_engine.track_tiles.grouser_transfer=0.35
   ```
2. **확정** — 설정 파일을 고치고, **시뮬레이터가 실제로 읽는 OmniLRS 설치본의 설정도 같은 파일인지** 확인합니다.
   저장소만 변경하면 설치본의 이전 설정이 계속 적용될 수 있습니다.
3. **검증** — 오프라인 시험(수 초: 깊이 · 주기 · 폭 · 이음매)을 먼저 보고, Isaac에서 직진 주행 → 후방 카메라 →
   깊이·그라우저 형상·폭·RTF를 측정합니다. **초기 상태·장면·카메라·명령을 동일하게 유지한 대조 시험**으로 전후 영상을 비교할 수
   있습니다. RTF는 **simulation timestamp 증가량과 wall-clock time 경과량**으로 계산합니다. 수신 빈도만으로는 물리 스텝 중단을 판별할 수 없습니다(12절).

## 18. 문제 원인과 개선 이력

초기 설정은 반경 0.09 m의 소형 휠과 낮은 하중 범위를 전제로 작성되어,
450 kg 로버에 적용하려면 제원·하중·격자 해상도의 정합을 확인해야 했습니다.
회귀 계수의 원 교정 자료는 확인되지 않았습니다. 실행 오류가 보고되지 않아도
변형량·하중·물리 시간 진행이 부정확할 수 있으므로 각 경로를 분리해 계측했습니다.

| # | 증상 | 원인 | 조치 | 절 |
|---|---|---|---|---|
| 1 | 변형 미발생 | 폭 0.09 m의 횡방향 표본 2개가 모두 경계에 위치해 깊이 0. 12 m 주행 후에도 변경 셀 0개 | 접지면 폭 확대 | 2 |

주요 원인은 다음 세 범주로 정리됩니다.

1. **대상 로버와 파라미터의 불일치:** 접지면 폭·길이·회귀 계수·그라우저 주기 설정이 대상 로버의 제원과 하중에 맞지 않았습니다.
2. **실행 상태와 물리 유효성의 구분 부족:** 프로세스 실행이나 토픽 수신만으로는 변형 미발생, 하중 오차, 물리 스텝 중단을 검출할 수 없었습니다. DEM 데이터·타임스탬프·대조 시험을 함께 사용했습니다.
3. **렌더링과 충돌 처리의 결합:** 자국 표현을 위한 정점 갱신이 충돌 데이터 재생성을 유발했습니다. 두 경로를 분리해 실행 성능을 개선했으며, 변형 지형과 휠 접촉의 물리적 연계는 후속 과제로 남아 있습니다.
