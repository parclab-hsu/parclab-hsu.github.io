# OmniLRS 지형 변형 엔진 정밀 분석

:material-circle:{ style="color:#2e9e44" } **기술 분석 노트** · 현대자동차 L-Project · 기준일 **2026-09-10**

!!! abstract "요약"
    달 탐사 로버 HILS의 플랜트(NVIDIA Isaac Sim + OmniLRS)에는 바퀴자국을 만드는
    **지형 변형(Deformation/Sinkage) 엔진**이 들어 있습니다. 이 문서는 그 엔진을
    **우리 설정으로 재현해 계산하고, 실제로 켜서 측정한** 기록입니다.

    핵심 결과는 셋입니다.

    - **현행 설정으로 켜면 변형이 정확히 0 입니다.** 오류도 나지 않습니다 —
      즉 "변형을 켰다"고 믿는 상태가 됩니다. 12.156 m를 달려도 격자가 한 칸도
      바뀌지 않는 것을 실측으로 확인했습니다.
    - **발자국 폭만 실제 휠 폭으로 고치면 이번엔 로버가 파묻힙니다.** 같은 지령·같은
      시간에 **12.156 m 대 0.054 m** 입니다.
    - **깊이가 하중이 아니라 충격에 비례했습니다.** 물리 엔진의 접지력이 정지 시
      4륜 모두 0으로 읽히기 때문입니다. 2026-09-09에 하중 입력을 서스펜션
      조인트 토크로 바꿔 **정지 상태에서도 파이도록** 연결했습니다.

    실행 파라미터 13개 중 **출처가 분명한 값은 3개**뿐입니다. 그래서 현재도
    `enable: False` 입니다 — 이 문서는 그 판단의 근거입니다.

## 1. 무엇을 하는 기능인가

로버 휠이 지나간 자리의 **DEM(높이맵)을 직접 깎습니다.** PhysX 콜라이더가 그 DEM에서
다시 생성되므로, 파인 자국이 이후 주행에 영향을 줍니다.

``` mermaid
flowchart LR
    A["휠 링크 4개<br/>월드 포즈"] --> C["발자국 격자를<br/>월드 좌표로 투영"]
    B["하중<br/>(접지력 또는<br/>서스펜션 토크)"] --> D["하중 → 침하 깊이<br/>회귀"]
    C --> E["DEM[y, x] +=<br/>깊이 × 감쇠^통과횟수"]
    D --> E
    E --> F["PhysX 콜라이더<br/>재생성"]
    F -.->|"다음 스텝"| A
```

참조점은 **휠 링크의 월드 원점(x, y)** 이고 방향은 **쿼터니언 yaw 하나**입니다.
따라서 조향은 반영되지만 **z·roll·pitch는 버려집니다** — 경사면에서 발자국이
지형에 눕지 않고 수평 격자로 찍힌다는 뜻입니다.

## 2. 현행 설정으로는 변형이 정확히 0 이다

가장 중요한 결과입니다. 현행 설정으로 `enable: True` 로 바꾸면 **아무 일도 일어나지
않고, 오류도 나지 않습니다.**

!!! warning "실동작으로 확인 (기준일 2026-08-25)"
    오프라인 계산이 아니라 실제로 켜서 확인했습니다. **12.156 m를 새 지형 위로 달려도
    격자가 한 칸도 바뀌지 않았습니다.** 접지력은 최대 **907 N** 으로 충분히 들어오는데도
    깊이가 0입니다 — 막히는 곳이 접지력도 좌표도 아니고 **경계 분포**임이 확정됐습니다.

### 원인 — 발자국 폭이 격자 두 칸보다 좁다

```
지형 해상도    0.05 m/px
발자국 폭      0.09 m   →  int(0.09/0.05)+1 = 2 점
발자국 길이    0.20 m   →  int(0.20/0.05)+1 = 5 점
```

경계 분포(안식각) 함수는 **가장자리에서 정확히 0**, 안쪽에서 −1입니다. 그런데 폭에
2점만 잡히면 그 둘이 **모두 가장자리**(`y = −1`, `+1`)가 되어 `boundary = [0, 0]` 이고,
최종 깊이가 `boundary × (…)` 이므로 **전부 0** 입니다.

| 발자국 폭 | 격자 점수 | 경계 분포 | 결과 |
|---|---|---|---|
| **0.090 m (현행)** | 2 | `[0, 0]` | **변형 없음** |
| 0.100 m | 3 | `[0, −1, 0]` | 발생 |
| **0.159 m (실제 휠 폭)** | 4 | `[0, −1, −1, 0]` | 발생 |
| 0.200 m | 5 | `[0, −0.87, −1, −0.87, 0]` | 발생 |

폭이 `2 × 지형해상도`(= 0.10 m)보다 작으면 **무조건 0** 입니다.

우리 휠 폭은 자산 실측 **0.159 m** 이고, 설정의 0.09는 그 **57 %** 입니다.
OmniLRS 예제값으로 보이며 근거가 문서 어디에도 없습니다.

!!! note "안식각을 낮춰서 풀 수 있는 문제가 아닙니다"
    폭이 2점이면 두 표본점이 모두 가장자리이고 거기서 식이 정확히 0이므로,
    **안식각 값과 무관하게 항상 0** 입니다. 폭을 늘려 점수를 3 이상으로 만드는 것
    외에 방법이 없습니다.

## 3. 폭을 고치면 이번엔 로버가 파묻힌다

`width: 0.159` 로 바꾸면 변형은 발생합니다. 그런데 깊이가 문제입니다.

| 하중 | 접촉력 | DEM 변화 | 휠 반경(0.2133 m) 대비 |
|---|---|---|---|
| 무하중 | 0 N | −0.0053 m | 2 % |
| **정상** | **182 N** (450 kg ÷ 4, 달 중력) | **−0.0946 m** | **44 %** |
| 2배 | 365 N | −0.1839 m | 86 % |

**정상 주행에서 휠 반경의 44 % 가 파입니다.** 실측에서는 같은 지령·같은 시간에
**12.156 m 대 0.054 m** 였습니다 — 로버가 제자리에서 자기 구덩이를 파고 갇힙니다.

그리고 **무하중에서도 5.3 mm가 파입니다.** 회귀식의 절편이 0이 아니기 때문입니다.

```
amplitude = 0.00006·F + 0.008     ← F = 0 에서 0.008
mean      = −0.00046·F − 0.0013   ← F = 0 에서 −0.0013
```

접촉력이 없어도 깊이가 나온다는 것은, **회귀가 맞춰진 구간 밖에서 물리적으로 말이
안 되는 값을 낸다**는 신호입니다. 그리고 이 네 계수가 **어떤 흙·어떤 휠·어떤 중력에서
맞춰진 것인지** 상류 문서에도 우리 설정에도 없습니다.

---

## 4. 하중 입력을 바꿨다 — 접지력은 정지 시 0으로 읽힌다

실측 과정에서 더 근본적인 문제가 드러났습니다. **PhysX 접지력이 정지·안착 상태에서
4륜 모두 0으로 읽힙니다**(1,680회 연속 확인). 움직이거나 충격이 있을 때만 수백 N이
나옵니다.

!!! danger "진짜 바퀴자국은 무거울수록 깊어야 하는데, 이 모델은 충격이 클수록 깊었습니다"
    서 있으면 안 파이고 부딪히면 파입니다. **발자국 폭을 고쳐도 남는 문제**입니다.

### 서스펜션 조인트 토크로 하중을 만든다 (기준일 2026-09-09)

서스펜션 조인트 토크는 **정지 상태에서도 살아 있고 지령에 반응합니다.** 조인트 축이
차량 종축(x)이므로, 수직력이 만드는 토크는 접지점까지의 **y 오프셋**에만 걸립니다.

```
F = (0, 0, −N),  r = 접지점 − 조인트 원점
(r × F)_x = −N · r_y      →      N = |τ| / |Δy|
```

레버 암은 하드코딩하지 않고 **URDF 체인에서 회전까지 합성해 계산**합니다. 중간에
0.1745 rad 회전이 있어 좌표를 단순히 더하면 5.7 mm 어긋나는데, 회전을 넣으면 휠 y가
**0.6433 m** 로 계약 윤거의 절반 **0.64335 m** 와 맞습니다 — 이것이 자기 검산이 됩니다.
레버 암 **0.4908 m**.

| 확인 항목 | 접지력 (전) | 서스펜션 토크 (후) |
|---|---|---|
| 정지 상태 하중 | 0 N | **148.85 N** |
| 값이 있는 휠 수 | 0 / 4 | **4 / 4** |
| 폭 0.159에서 침하 | — | 0.0906 m |
| DEM 변화 격자 | 0 칸 | **40 칸** |
| 그때 로버 이동 거리 | — | **0.0 m** |

**로버가 서 있는데 파입니다.** 이것이 이 연결의 목표였습니다.

### 다만 자중의 절반만 읽힙니다 — 결함이 아니라 기구입니다

야드 다섯 자리에서 재면 네 휠 하중의 합이 자중(729 N)의 **51.6 ~ 66.1 %**, 평균
**56.2 %** 입니다. 원인은 서스펜션이 **4절 평행링크**라는 데 있습니다 — 아래 팔이
**2력 부재**라 큰 힘을 나르면서도 자기 축 토크는 0입니다(실측 0.004 N·m).
**위 팔 토크만으로는 원리적으로 전체 하중을 볼 수 없습니다.**

따라서 고칠 문제가 아니라 **계수로 보정할 문제**이고, 교정 계수는 **1.78**,
**산포 ±18 %** 입니다. 평균은 맞고 자세별 오차는 남습니다.

## 5. 실행 파라미터 전수 점검 — 근거 있는 값은 3개뿐

**값이 적혀 있다고 쓰이는 것은 아닙니다.** 설정에 자리가 있는데 코드가 한 번도 읽지
않는 항목이 있고, 설정과 대상이 연결되지 않은 항목도 있습니다. 둘 다 겉으로는 정상으로
보입니다. (기준일 2026-09-08, 13개 항목 전수)

| 항목 | 상태 | 영향 |
|---|---|---|
| **`gravity`** | 설정에 있으나 엔진 소스에서 **참조 0회** | 값을 고쳐도 아무 일이 없다 |
| **`footprint.shape`** | 분기 자체가 없음 | **접지면이 항상 직사각형**이다 |
| **`num_links`** | `target_links` 로부터 채워지지 않음 | 기본값 4로 돌고, 휠이 4개라 **우연히 맞다** |
| **`angle_of_repose`** | 현행 60°, 출처 없음 | 폭을 고친 뒤 **깊이를 2.6배까지 좌우** |
| **`wave_frequency`** | 현행 4.14 = 그라우저 13개분 | 실측은 **24개** |

### 그라우저는 24개다 (기준일 2026-08-26)

휠 메시에서 실측했습니다 — 방위각 히스토그램의 이산 푸리에 변환으로 지배 주파수를
보는 방식이며, 반경 문턱 98/95/92 %에서 모두 같은 답이 나왔습니다.

| 항목 | 실측 |
|---|---|
| **그라우저 수** | **24 개** |
| 휠 반경(팁) / 지름 | 0.2134 / 0.4268 m |
| **그라우저 높이** | 약 **19.1 mm** |

설정 주석은 `num_grouser/pi` 라고 적혀 있는데, **그 식은 접지 길이 L이 휠 지름과 같을
때만 성립합니다.** OmniLRS 기본값(반경 0.09, 길이 0.18)은 정확히 `L = 2R` 이라 맞았지만
우리는 아닙니다. 일반식 `L·N / (2πR)` 로 계산하면 현재 접지 길이 0.20 m에서 **3.58** 이고,
그 접지 길이 자체도 아직 근거가 없습니다.

## 6. 상류 소스 결함 3건

우리가 만든 것이 아니라 OmniLRS 원본의 문제입니다. 앞의 둘은 패치로 고쳐 두었습니다.

| | 내용 | 상태 |
|---|---|---|
| ① | `y_deform_offset` 이 **`x` 값을 받는다** | 패치 적용 |
| ② | `delay` 단위 변환이 반대 방향(곱셈) | 패치 적용 |
| ③ | 야드 경계 검사가 없어, 밖으로 나가면 **음수 인덱싱으로 반대쪽 끝을 판다** | 미조치 |

## 7. 함께 확인한 것 — 견인 솔버는 한 번도 돌아본 적이 없었다

변형 엔진과 짝을 이루는 **Terramechanics 견인 솔버**도 같이 점검했습니다. 이 둘은
"지형의 모양을 바꾸는 쪽"과 "로버가 받는 힘을 바꾸는 쪽"으로 나뉘는데, 연결이
끊겨 있었습니다. (기준일 2026-09-10)

| | 결함 | 왜 드러나지 않았나 |
|---|---|---|
| ① | 호출부가 주석 처리 | 로버가 토양 반력을 안 받아도 화면은 정상 |
| ② | 기본 인자 **20 kg · 휠 반경 0.09 m** (실제 450 kg · 0.2133 m) | 값이 그럴듯했다 |
| ③ | 힘을 **2회 연속** 적용 | 두 줄이 나란히 있어 눈에 띄지 않는다 |
| ④ | 없는 API 호출(`get_velocities`) | 유일한 호출자가 주석이라 |
| ⑤ | 휠당 스칼라 자리에 (n,3) 월드 벡터 | 〃 |
| ⑥ | 수치적분 결과를 **튜플째** 연산 | 힘 계산 세 함수가 **한 번도 실행된 적 없음** |
| ⑦ | 중력 **9.81 하드코딩** | 달 시뮬레이터에서 σ_max가 **6배** 부푼다 |

일곱 건을 고쳐 연결한 뒤 실측하면 침하 0.032~0.05 m, 슬립비 0.846 → −0.189,
견인력 −48 ~ +4 N 범위에서 **NaN 없이 안정적으로** 돕니다.

!!! warning "다만 수직 반력은 더하지 않습니다"
    PhysX가 접촉으로 이미 지지력을 줍니다. 거기에 솔버의 수직 반력을 얹으면
    **이중 계상**이고, 출처 없는 계수로는 그것만으로 로버가 날아갑니다
    (σ_max 약 44 kPa → 휠당 1.5 kN 급, 자중은 729 N). 이 솔버로 보려는 것은
    **견인력과 저항 토크**입니다.

## 8. 확인되지 않은 것

이 절을 줄이지 않습니다. 위의 수치가 어디까지를 말하는지가 여기에 있습니다.

- **토양 계수의 출처가 없습니다.** 침하 회귀 4개, Bekker/Wong 계수 9개가 전부
  상류 예제값이거나 출처 불명입니다. **월면토 시험 자료 없이는 크기를 믿을 수
  없습니다** — 지금 확인한 것은 경향과 연결 여부이지 값의 타당성이 아닙니다.
- **실제 월면토로 검증한 것이 아닙니다.** 전부 시뮬레이션 내부 계측이며,
  시뮬런트(모사토) 시험도 아직 없습니다.
- **하중 교정 계수 1.78은 산포 ±18 %** 입니다. 평균은 맞지만 자세별 오차가
  남고, 그 오차가 침하에 어떻게 전달되는지는 아직 정량화하지 않았습니다.
- **접지면 형상은 여전히 직사각형**입니다. 실제 휠 접지는 진입각~이탈각 사이의
  원호이고, 그 차이가 깊이에 미치는 영향은 측정하지 않았습니다.
- **경사면 처리를 확인하지 않았습니다.** 참조점이 yaw만 쓰므로 경사에서 발자국이
  지형에 눕지 않는데, 그 오차 크기를 재지 않았습니다.
- **성능 손실이 있습니다.** 켜고 주행하면 30 → **26.5 Hz**(−12 %)입니다. 깊이가
  0이든 아니든 엔진이 매 스텝 정점 배열 전체를 다시 쓰기 때문입니다.

## 9. 켠다면 이 순서로

앞에서부터 하지 않으면 뒤가 무의미하거나 해롭습니다.

1. **`delay` 확대** — 스폰 낙하 충격이 지형에 새겨집니다(주행 전에 이미 21 cm 구덩이).
2. **힘–깊이 모델 재수립** — 하중 입력 연결은 끝났고(4절), 남은 것은 **회귀 계수의 출처**입니다.
3. **발자국 폭을 0.159 m로** — 안 그러면 변형이 0인데 0인 줄 모릅니다. **단 1·2를 먼저
   하지 않으면 로버가 파묻힙니다.**
4. **발자국 길이·형상의 근거 확보** — 접지 길이는 침하량의 함수라 상수로 두는 것 자체가 근사입니다.
5. **`wave_frequency` 를 3.58로** — 접지 길이를 정한 뒤 일반식으로 재계산합니다.
6. **지형 해상도 재검토** — 0.05 m/px에서 휠 폭 0.159 m는 4칸이라 형상이 매우 거칩니다.
7. **경계 검사 추가** — 야드 밖으로 나가면 반대쪽 끝을 팝니다.
8. **안식각 출처 확보** — 현행 60°는 통상값 30~45°보다 높아 침하를 과대평가하는 방향입니다.

이 목록이 [차년도 과제 제안](l-project-terramechanics.md)의 출발점입니다.
